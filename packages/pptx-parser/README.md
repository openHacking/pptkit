# @pptkit/pptx-parser

The experimental [declared-slot font profile](../../docs/api/declared-slot-font-import.md) adds `textFontProfile: "script-families-v3"`: supplemental rules require their effective native bucket, with source-only missing-selection diagnostics. Earlier font profiles remain compatible; source font/style writes and native implicit-font inference remain unsupported.

Experimental package-inspection foundation. The public `inspectZipArchive(bytes, options?)` checks a bounded ZIP32 envelope and decoded CRC/size inventory in Node or browsers. `inspectXmlPart(bytes, options?)` separately checks XML 1.0 structure, namespaces and resource limits. `inspectOpcPackage(bytes, options?)` adds content types, a validated relationship graph and cumulative XML budgets. These APIs do **not** import a Core document, interpret all OOXML dialects or provide preservation saves.

Use the package root or `/browser` for runtime-neutral byte inspection/import/save. Use `/node` only for local file import and publication. Implementation modules are not public exports. See the [inspection contract](../../docs/api/archive-inspection.md), [Node file contract](../../docs/api/file-save.md), [ownership ADR](../../docs/architecture/decisions/0001-import-preservation-save.md) and [remaining import backlog](../../docs/planning/implementation-backlog.md).

See the [XML contract](../../docs/api/xml-inspection.md) for encoding limits and [third-party notices](THIRD_PARTY_NOTICES.txt) for bundled dependencies.

The [OPC profile](../../docs/api/opc-inspection.md) distinguishes verified graph structure from presentation-specific validity and lists remaining format restrictions.

`compareOpcPackages(before, after, options?)` independently validates both source packages and compares their exact part payloads and relationships. The explicit `opc-xml-v1` profile allows conservative XML representation differences while retaining unknown markup, namespace bindings, text whitespace and prolog/epilog. It does not import Core or establish edit-save/visual fidelity. See [comparison profiles, limits and evidence](../../docs/api/package-comparison.md).

`inspectOpcClosure(bytes, { roots })` analyzes source relationship dependencies from explicit ordinary part/package roots. It includes inactive MCE declarations and owned relationship parts, records outside incoming owners, and reports scoped incompleteness/identity findings under separate budgets. Unreached parts are not proven garbage, and this does not permit edit-save. See [the closure profile](../../docs/api/preservation-closure.md).

`inspectPresentationPackage(bytes, options?)` identifies the PresentationML entry point, dialect and main content type after OPC validation. See the [entry contract](../../docs/api/presentation-inspection.md); this is not full schema conformance or semantic import.

`inspectMarkupCompatibility(bytes, options)` processes XML using explicit consumer capabilities and returns effective inventory/decisions. OPC relationship inspection uses this processor for MCE markup; other XML bodies require explicit processing. See the [MCE profile](../../docs/api/markup-compatibility.md).

`inspectPptx(bytes, options?)` reads bounded PresentationML structure: page order, dimensions, hidden state, structural source references and package-linked core/extended/custom metadata. Metadata includes source identities, lexical scalar values and explicit uninterpreted complex values; date/calendar validation and preservation are not implied. See the [structural inspection contract](../../docs/api/pptx-inspection.md); session creation and bounded content projection use the separate APIs below.

Native section inspection in `inspectPptx` exposes source GUID/name/member identities, empty sections, order/coverage findings and uninterpreted presentation/section extension descriptors. Import projections map named native members to Core slide labels by source slide identity, with separate native-collection/label capability findings. Empty sections, collection identity and native editing/export remain source-only. See the [section profile](../../docs/api/pptx-inspection.md#native-sections-and-presentation-extensions) and [label projection](../../docs/api/import-session.md#native-section-member-labels).

`importPptx(bytes, { projection: "structure" })` creates an explicit Core structural projection and original-byte no-op session. Source content is retained for unchanged save, but drawing/notes/theme semantics are not imported into that document. Default edit and all rebuild requests return blocked reports. See [session contracts and budgets](../../docs/api/import-session.md).

`importPptxFile(path, options)` and `writePptxFile(session, plan, path, options)` are Node-only stable-file adapters. Create never clobbers an existing name; replace requires a process-local source snapshot and verifies path, inode/metadata and complete SHA256 before same-directory publication. Failed precommit work preserves the original and permits retry; postcommit sync/cleanup warnings remain visible on the committed result. Standard Node has no cross-process CAS between the final check and rename, so the adapter assumes cooperating writers and a trusted/stable parent. See [file semantics, cancellation and platform limits](../../docs/api/file-save.md) and [ADR 0011](../../docs/architecture/decisions/0011-node-file-publication.md).

Content import can explicitly enable `editSaveProfile: "text-runs-v1"` to save scalar character changes on existing bound imported text-box runs, including mapped groups. Full-candidate analysis blocks unsupported mixed edits, source guards reject known range references, and minimal XML/ZIP patches retain untouched source content. Independent package differences and actual-output reprojection validate each candidate. Styles, geometry, other text owners, assets, structural operations, nonempty loss consent and general rebuild remain outside this profile. See the [checked example, budgets and evidence](../../docs/api/text-edit-save.md). The separate explicit `text-runs-v2` profile additionally admits existing bound mapped shape-text and direct notes-body runs; its [owner contract](../../docs/api/text-owner-save.md) defines distinct notes provenance, source-part guard scoping and independent/native evidence. V1 scope and report shape remain compatible. Explicit `text-runs-v3` adds [table-anchor run characters](../../docs/api/table-text-save.md), with separate row/compact-cell/physical-column provenance and unchanged grids/merges. Earlier profiles do not gain table permission.

`projection: "content"` adds experimental slide-local text, seven preset shapes, nested groups, embedded PNG/JPEG/GIF pictures, same-scope straight connector attachments and safe direct click actions, with property findings. Image assets retain source-part identity, bounded header dimensions, supported crop/opacity and immutable bytes. External links are inventoried without loading or execution. Unsupported connector references keep free endpoint geometry and do not claim attachment. Missing inheritance, unknown objects/effects and edit-save limits remain explicit. See [content import](../../docs/api/content-import.md).

Content projection also maps one explicit direct body placeholder's rich text into speaker notes. Notes identity maps to the owning Core slide, while note-page geometry, other placeholders, masters and unresolved inheritance remain reported source semantics. Core `slide.setNotes()` edits/clears projected notes; preservation edits remain blocked. See [speaker notes](../../docs/api/notes-import.md).

Content projection also maps direct table grids, rectangular merge anchors, cell rich text/clicks and a bounded direct style subset. Authored frame/grid dimensions remain separate, nonempty continuation content prevents lossy import, and unknown table/edge/theme styles remain source-reported. Table rotation/flips survive fresh export. Explicit V3 admits fixed-topology bound anchor characters; default/earlier profiles, broader table edits and all rebuilds remain blocked. See [table import](../../docs/api/table-import.md).

Content projection also maps bounded 2D bar/line/pie/doughnut/area/scatter data, direct styles and approximate chart preview, with cache priority, explicit workbook conflict/missing-cache fallback, nested package/work budgets and no formula execution or external fetching. See [chart import](../../docs/api/chart-import.md). Explicit `chartEditSaveProfile: "existing-values-v1"` admits [existing numeric preservation writes](../../docs/api/chart-value-save.md) when cache and unshared XLSX cells bind exactly, with atomic two-layer staging, package comparison and actual-candidate rebinding. The opt-in `existing-values-v2` profile additionally supports existing nonblank scatter points in matching sparse caches without changing blank positions. Full format/label semantics, shared edits, structural changes and interactive Edit Data remain open.

Selected plain page Fade transitions with explicit p14 milliseconds now map in both projections. Unknown effects/sounds/extensions and speed-only MCE fallbacks remain source-only; source transition mutations remain blocked by preservation profiles. See [the transition contract](../../docs/api/slide-transitions.md).

The same bounded transition profile additionally maps Push/Wipe with explicit cardinal direction and exact duration. All eight variants retain the static/preservation restrictions documented in [the extension](../../docs/api/slide-transitions.md#push-and-wipe-extension).


Read-only native timing inspection is available through `inspectPptxTiming(bytes, options?)`; see the [contract](../../docs/api/native-timing-inventory.md). It adds no animation editing or playback authority.


The explicit `textTargetSaveProfile: "paragraph-stable-v1"` can preserve proven direct shape paragraph-index targets during fixed-topology scalar text saves. It requires an existing text-run profile; see [the source contract](../../docs/api/paragraph-target-save.md) for guards and native limitations.

[`inspectPptxNotes`](../../docs/api/notes-source-inventory.md) provides bounded read-only notes/master roles, source geometry, artwork identity and stored field caches in Node and browser builds. Geometry remains unresolved and fields are not evaluated.
