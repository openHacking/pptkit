## Implemented and partial capabilities

“Implemented” below means the stated bounded behavior exists and has tests. It does not imply every Office feature in that category is supported. “Partial” identifies a capability whose common shape exists but needs further semantics or fidelity work.

[Independent OPC source comparison](../api/package-comparison.md) now adds exact payload and explicit conservative XML profiles with source-local graph differences. It validates both packages, retains unknown/unselected source markup, compares binary bytes without CRC shortcuts, and bounds comparison work/report retention. Independent ZIP/SHA256, Chromium DOM, Node/browser and installed declarations provide scoped evidence. Effective-value fresh-output comparison, identity bijections, full corruption/native gates and preservation edits remain open under IMP-08/09.

[OPC source closure analysis](../api/preservation-closure.md) now follows all recognized source relationship declarations, including inactive MCE branches, and includes owned relationship sets. It reports shared/cyclic targets, outside incoming owners, unreached parts, selected-byte footprints and scoped findings for opaque/missing/ambiguous source information. Independent graph models, DOM, cross-package fixtures and installed consumers verify the bounded profile. It does not expose payloads, authorize cleanup or implement source edit-save; full IMP-07/09 remains open.

The private [XML character-edit foundation](../architecture/decisions/0007-xml-character-edit-boundaries.md) retains lexical regions outside explicitly identified character-only targets, including unknown siblings and inactive markup. UTF-8/BOM-marked UTF-16, guards, budgets and lifecycle are tested. It is not a public editing API or a package/session writer; Core run ownership, application-level range references and IMP-09 remain open.

**Experimental implemented profile (2026-10-25):** [`text-runs-v1`](../api/text-edit-save.md) wires existing text-box run characters into source bindings, whole-candidate analysis, raw guards and scoped-preservation plans. Minimal XML/ZIP changes retain untouched content, exact OPC differences and actual-output reprojection validate the candidate, and cancellation/disposal release reservations and caller signal listeners. The [Node file profile](../api/file-save.md) subsequently adds stable path capture, exclusive create, snapshot-guarded replacement, a synchronous final plan guard and committed warnings, with injected stage/race tests. Full build/typecheck/test, browser ESM/global and installed consumers pass. Cross-process CAS and broader filesystem/platform certification stay open. Native headless text survives, while producer resave loses unknown extension/orphan data. PowerPoint/interactive/full-reference gates remain open under IMP-09.2.1.1 and its parents. Default edit blocking and general rebuild restrictions remain; wider owners, topology, table/chart/property/action edits and structural preservation are separately planned under the [object-save TODOs](advanced-capability-todos.md#编辑保存的对象覆盖补齐).

**Additional explicit owner profile:** [`text-runs-v2`](../api/text-owner-save.md) now also admits bound mapped shape-text and direct notes-body run characters. Notes provenance has slide/source identity without a fabricated element ID. Whole-plan classification, per-part range guards and actual-output validation retain the existing boundaries. Independent ZIP/XML/DOM, three-round mixed-deck, browser/installed-consumer and native headless evidence is recorded in the [owner execution record](execution-record.md#shape-text-and-speaker-notes-preservation-saves-2026-10-25). V1 remains compatible; full IMP-09.2.1.2 inherited/native gates remain open.

**Additional table profile:** [`text-runs-v3`](../api/table-text-save.md) admits existing bound table-anchor run characters with explicit compact-cell/physical-column provenance. Complete grid/merge validation precedes binding; style/metric/topology mutations remain blocked. Independent partitions, three-round mixed decks, browser/installed consumers and native headless evidence are linked in the [table execution record](execution-record.md#table-anchor-character-preservation-saves-2026-10-25). Producer geometry/opaque-content losses are explicit; IMP-09.2.5's complete gates remain open.

## Audit conclusions

[Content-model research and native observations](../testing/smartart-native-editing.md) now distinguish ordered forests/assistants from presentation/cache data and layout-generated Cycle closure. Subsequent [PowerPoint cache-conflict evidence](../testing/smartart-stale-cache.md) covers standard process3/orgChart1/cycle2 open/save/reopen, three native layout-change/return cases and three controlled conflict-rebuild rounds per family. Earlier generated-output edit/identity observations are recorded separately in ADR0025/0026; full native operation/fidelity admission remains incomplete. These named-source results do not admit a public Core diagram model, native authoring/export or general native editing support.

[Explicit SmartArt mappings](../api/diagram-mapping.md) now retain property/connection evidence once per data part and recognized cache-shape references once per actual data/cache pair. Independent source checks cover 103 presentation mappings (including two differing-target points) and ten cache shapes, with shared-owner identity and budget tests. These source links do not establish complete semantic ownership, freshness, family layouts or native node editing.

The [SmartArt source graph profile](../api/diagram-data.md) now adds direct point/connection identities, typed reference statuses, stored paragraph/run/field text and raw cache shape model references. Cumulative format-owned graph limits apply to inspection/import/candidate reprojection. Independent DOM and seven Python-checked source cases advance ADV-02.1.2.1/.2.3; complete data-to-cache semantics, family layouts and actual native node editing remain open.

- Preserve the existing Core → Layout → format boundaries. Byte sources, parser preservation, font measurement and editor state require explicit owners before adding APIs.
- Existing tests prove numerous package and SVG behaviors; actual Office open/edit/save evidence is a separate release gate. See [application matrix](../testing/application-compatibility.md).
- Expand tests for failure behavior and concurrency, not just expected XML strings. The shared corpus already exposed concurrent chart numbering and unescaped hyperlink relationship targets, both now covered by regression tests.
- The current public surface is provisional. Release policy and installed consumers have explicit evidence; application support must not be inferred from the presence of a `0.1.x` version or a green unit suite.

Browser measurement evidence: [adapter contract](../api/browser-measurement.md), [12 pinned-font tests](../../packages/svg-renderer/test/measurement.spec.mjs), [font provenance](../../packages/layout/test/fixtures/README.md). Chromium is verified; Firefox/WebKit and native Office font parity are not.

Document metadata inspection now reads package-linked core/extended/custom records, source identities and lexical scalar values through [inspectPptx](../api/pptx-inspection.md#document-metadata-profile). Complex values are explicitly uninterpreted, dates are not calendar-validated, and no Core import/edit/save capability follows from this inspection surface.

Native section inspection now retains MS-PPTX GUIDs, names, empty sections and source slide references, with order/coverage findings and shallow unknown-extension descriptors. Both import projections map named members to Core slide labels by numeric source identity and separately report native-collection limitations. [Native evidence](../testing/native-sections-evidence.json) records Transitional LibreOfficeDev save/reopen, independent membership-to-label comparison and exact source no-op. Core native collection modeling, authoring/export and edit-save remain unimplemented; fresh output contains PPTKit label metadata only. See [the section profile](../api/pptx-inspection.md#native-sections-and-presentation-extensions) and [label projection](../api/import-session.md#native-section-member-labels).

[Import/no-op sessions](../api/import-session.md) create an explicitly incomplete Core projection, inventory every source part by operation, and return exact original bytes through owned plans with freshness/lifecycle/budget checks. [Content projection](../api/content-import.md) adds bounded drawing/notes/table/chart semantics and can select the separate text-run save profile. Broader image semantics, notes-page/master/theme semantics, complete inheritance, general edit-save closure and rebuild remain pending; neither projection is a complete source preview.

[Reference-aware copying](../api/copy-references.md) now remaps current Core connector targets inside copied slides/groups and self-slide actions across element/text/table/notes content. Shared assets/layouts and external references remain unchanged; cross-document and advanced-object preservation remain AUT-09/IMP-09 work.

Experimental [page Fade](../api/slide-transitions.md) now has immutable Core authoring, detached IR/Layout transport, exact p14 milliseconds in fresh output and bounded Strict/Transitional import. Three-round, static SVG, independent DOM and preservation tests cover the profile. Native interactive/playback, other transitions and preview playback remain open under ADV-05/08.

[Push/Wipe cardinal variants](../api/slide-transitions.md#push-and-wipe-extension) now extend the experimental page transition data profile with eight separately verified directions. Native XML and source semantics have automated evidence; dynamic preview, interruption and application playback remain open.

[Versioned source capability observations](../api/import-capabilities.md) now group exact source/Core subjects and retain explicit unreported/conflicting operation states. They attach task/artifact navigation hints and keep native/candidate-save validation not-performed; absence and static references are not support evidence.

**Existing chart numeric save slice:** explicit [`existing-values-v1`](../api/chart-value-save.md) binds fixed-topology values only when cache/local XLSX agree and are unshared/unaliased. Atomic two-layer staging, independent package differences, actual-output rebinding and full Core validation have both-dialect/family three-round tests plus browser/installed consumers. Names/categories/styles/topology, full reference policies and native Edit Data remain open under IMP-09.2.6; general mapped-chart findings do not grant blanket editability.

**Finite time arithmetic:** [Core compile/sample utilities](../api/finite-timeline.md) provide bounded immutable span/group schedules and random-access progress with explicit rejection of unsupported timing. They add no drawing targets, effects, event listeners, authoring/IR animation fields or native playback/export claims. ADV-06/07 and their native gates remain open.

**Foreground event arithmetic:** [Core compile/replay utilities](../api/event-timeline.md) add explicit ordered logs, visit isolation, current-inventory guards and immutable consumed/ignored/future observations. They add no listeners, wall clock, authored/IR effects, source timing edits or native playback claims.

**Slide-bound timing identity:** [Owned Core programs](../api/slide-event-timeline.md) now normalize to versioned IR/Layout metadata and follow whole-slide copy, with referenced delete/replace guards. Native timing import/export/playback remains unimplemented: PPTX defaults to typed rejection, explicit omit reports static loss, SVG warns, and timed page splitting is unapplied.


**Native timing inventory:** [inspectPptxTiming](../api/native-timing-inventory.md) records decoded timing/source identities, effective/raw-only membership and conservative part-local candidates. Node/browser/installed and independent Python XML evidence cover inspection; mapping/editing/playback remain unimplemented.


**Stable paragraph source targets:** [paragraph-stable-v1](../api/paragraph-target-save.md) explicitly allows existing scalar text edits only when raw drawing ownership, paragraph identity and transparent in-bounds paragraph ranges are proven. Defaults and character/opaque guards stay unchanged. Three source rounds pass independent checks; the named native producer rewrites the sample range even on the unedited control, so native range preservation is partial.


**Atomic table authoring:** [editTable](../api/table-editing.md) now performs bounded row/column insert/delete and merge/split with explicit content/frame policies, anchor promotion, rich-text append and complete original-anchor mappings. Core/browser/installed and independent physical-grid/native headless checks cover fresh outputs, including a fixed wide-merge continuation bug. Full style precedence, native UI editing and Parser structure preservation remain open.

**Regional table authoring:** [TableStyleInput](../api/table-style.md) now resolves whole/banded/first-last/corner/text rules, physical merged boundaries and implicit blanks into effective canonical cells. Local presets/content override regions; edits recompute, pagination preserves source-row styles. Independent source/browser checks and named native fill/text resaves pass in the documented scenes. Native region definitions are absent (`table-style-materialized`); source table-style/theme inheritance, broader geometry/content origins, text direction and source style writes remain open; [authoring cell-format origins](../api/table-format-origins.md) are now available.


**Source table styles:** [direct-region import](../api/table-style-import.md) adds verified definition/default/flag selection, per-slide theme evaluation, effective direct cell/text fields and selected bounded provenance. Conditional preview stays fallback. Independent source/browser checks and named native direct fills agree in current controls; the [matrix extension](../api/table-style-import.md#theme-format-matrix-extension) adds positional fill/line selection and placeholder color composition. Five native controls retain background/transform/line discrepancies and one application failure; text appearance, other matrix paints/effects, arbitrary merge/overlap order, PowerPoint/native interactions and source-style writes remain open.

**Table text appearance:** [reference color/uniform-font extension](../api/table-style-import.md#reference-text-color-and-explicit-script-fonts) applies fontRef default colors below region/local overrides and resolves explicit lt/ea/cs slots when families agree. Different/missing explicit alternatives block a misleading Latin projection. Four independent native controls retain a reference-only default-color discrepancy and font substitution; Core [mixed-family authoring/transport](../api/script-fonts.md) now exists, while the explicit [source profile](../api/script-font-import.md) maps independent fields; native/script-language selection, shaping, complete omitted defaults and PowerPoint interaction remain open.

Experimental [script font maps](../api/script-fonts.md#script-font-map-extension) support Core authoring/inheritance, language-aware Han selection, Layout concrete provider fragments and both SVG paths. Fresh PPTX materializes current fonts with `script-font-map-materialized`; map rules/theme linkage and run topology do not round-trip. Source supplemental projection and native shaping/theme editing remain unverified.

Experimental [supplemental source fonts v2](../api/supplemental-font-import.md): admitted theme/table rules now reach Core maps after per-field inheritance, with actual source provenance and scalar-save reprojection. Generic empty slots stay unsupported; unknown scripts stay source-only. Default/v1 stay compatible. Independent source evidence does not certify native font selection, coverage, notes inheritance or font writing.

Experimental [notes text profile](../api/notes-style-import.md): supported notesStyle/body-list/paragraph/run inheritance and independent notes themes/colors/fonts now project through an explicit option, with bounded actual source provenance and scalar candidate revalidation. Direct default/v1/v2 without that option stay unchanged. Full notes-page layout/artwork/native editing/style writers remain unsupported or unverified.
