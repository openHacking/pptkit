# Directional SVG import: implementation gates

ECO-03 remains open. SVG is an input format, not a new Core element type. A dedicated importer may depend on Core's public contracts; Core and the SVG renderer must not depend on it. Its result must say whether the whole source was converted, is unsupported, or failed to parse. A partial editable result must never be presented as a faithful whole-image conversion. Import does not execute scripts, resolve URLs or fetch resources. A caller-supplied raster fallback is a separate explicit outcome, not proof that conversion preserved editability or appearance.

| ID | Scope and acceptance |
| --- | --- |
| ECO-03.1 | Establish bounded XML parsing and diagnostics with no DTD/entity expansion, network, script execution or implicit fetch. Limit input, elements, nesting and attributes; test malformed XML, namespace confusion, external resources, deeply nested and oversized inputs in Node and browsers. No unsupported feature may disappear without a diagnostic. |
| ECO-03.2 | Convert a named conservative viewport/geometry/paint subset to editable Core objects. State coordinate units, viewport/clipping, default paints, ordering and unsupported cases. Test exact authored geometry and paint independently, rendered comparisons, PPTX output, and native editing/reopening. Reject or report shapes crossing unsupported clipping boundaries. |
| ECO-03.3 | Add paths, transforms and inherited style only after their coordinate and stroke semantics have explicit coverage. Exercise nested transforms, fill rules, stroke scaling, path closure and unsupported combinations; do not silently approximate. |
| ECO-03.4 | Define text/font measurement, styling, shaping and accessibility behavior. Test mapped editable text against named font/environment samples and report unsupported shaping or layout rather than claiming general text equivalence. |
| ECO-03.5 | Provide explicit fallback and capability reports with caller-owned trusted raster bytes and source identity. Test fidelity tradeoffs, resource failures, no accidental external requests and both editable/fallback outputs. |
| ECO-03.6 | Integrate package boundaries, portable bundles, installed consumers, examples, release policy and API documentation. Recheck all child gates and REL-02 native evidence before closing ECO-03. |

The first geometry profile uses an explicit root viewport in CSS pixels, converts at 96 px/in to Core points, and admits rectangle/ellipse/circle shapes with bounded, non-clipped geometry and literal solid fills. A missing SVG fill means black, while a missing stroke means none. Circle and ellipse elements accept literal solid strokes, including inherited root/group colors and widths, with uniform combined scaling and reject stroke bounds crossing the viewBox or viewport; visible rectangle strokes and dash patterns remain unsupported. Bounded unfilled linear paths, polylines and polygons with round joins and, when open, round caps map to connectors with explicit closure and report loss of source element/commands; filled paths and curves remain unsupported. The experiment accepts numeric `viewBox` with nonuniform `none` or any alignment with `meet` or `slice`; shape and nested-group `translate` and `scale` lists are composed with the rightmost transform acting on the geometry first, then baked into boxes, including reflections. Root/group literal fill inherits; group structure is flattened with an explicit warning. It rejects shapes crossing the viewBox or mapped viewport. CSS cascade, rotation/skew, clipping, group opacity, text, general paths, image references and unsupported attributes remain explicit findings until their own gates are implemented. A shape's presence, its visual effect and native editability are separate assertions; no generated raster or native application result is implied by a structural conversion test.

The private [workspace experiment](../../packages/svg-parser/README.md) implements this initial all-or-nothing subset with SAX parsing and fixed limits. Literal paint also supports 148 named sRGB colors, bounded integer `rgb()` / `rgba()`, color alpha and inherited paint opacity, compared with Chromium. It also provides caller-owned raster fallback with copied bytes, caller source identity and an explicit non-editability warning, separately or through an opt-in outcome that retains unsupported/parse failure reasons; the caller is responsible for validating the raster and its correspondence to the source. [Core integration and adversarial tests](../../packages/svg-parser/test/smoke.test.mjs) cover accepted geometry, viewBox mapping, nested transform and fill inheritance, unsupported markup and limits; a [cross-runtime experiment](../../scripts/svg-import-experiment.test.mjs) checks Node/Chromium results, no network requests for a rejected external image or fallback creation, editable PPTX shape XML, three projection/export rounds of round linear paths, fallback image bytes embedded in PPTX, invalid raster export warnings, selected interior pixels, 36 native SVG geometry comparisons across all alignments and both viewport orientations, five translated/scaled/reflected geometry cases, and one nested-group/fill sample. Limited PowerPoint observations sample [outlined shapes](../testing/svg-stroke-powerpoint-evidence.json) and [transparent fills/stroke](../testing/svg-opacity-powerpoint-evidence.json), each with one native move/save/reopen. These are not full pixel parity, installed-package, verified raster fidelity or general SVG acceptance. No child gate is closed by this preliminary evidence.

The cross-runtime XML matrix compares 16 specific valid, malformed, DTD/entity, namespace, external-resource, script and limit inputs in Node and Chromium, including element, attribute, depth and character limits. The browser run observes no requests and no execution of the test script. This is a bounded sample, not a complete security audit or proof for every browser or XML input; ECO-03.1 remains open.
