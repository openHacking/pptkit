# ADR 0017: SmartArt cache and direct resource associations

Status: accepted for experimental source inspection, 2026-10-25. Progress on ADV-01.1.1.3; preview, full closure and native editing acceptance remain open.

The source object inventory needs to distinguish explicit cache ownership from nearby cache candidates. Multiple diagrams can share data, layout, style, colors or pictures. Matching filenames, selecting the only cache on a page, or resolving every relationship at the XML part that spells its ID would give incorrect ownership.

Parser recognizes the raw data-model extension path documented by [Microsoft's dataModelExt definition](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/052211cd-4f97-4860-aeb1-3fee41317937) and [CT_DataModelExtBlock](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/66cc6c59-45c6-438e-82ba-7d67de771f68). The unqualified reference resolves in the owning slide's relationship scope. This scope is corroborated by the [LibreOffice exporter implementation at revision 65f19039](https://cgit.freedesktop.org/libreoffice/core/tree/oox/source/export/drawingml.cxx?id=65f1903921c448da61733ca0d47c2ffc862b201d): the exporter adds the drawing relationship alongside slide-side diagram components and writes that ID into the data XML. The [Microsoft cache part contract](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/ec96c9e0-757a-4f24-9725-c52d3c34e310) and [DSP schema](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/e1b56dd5-305b-4b3b-a983-28df1d4ffc3f) define the relationship/content type and raw drawing root.

Only a unique recognized direct block can establish an association. Multiple blocks/lists are ambiguous. Data-part MCE remains source-only rather than globally claiming to understand DSP or extension branches. Unknown extension URIs/wrappers are not searched for a guessed owner. Cache presence and root matching never prove freshness, schema validity or semantic equivalence; `freshness` is always unknown. The reference's raw source index and minimum-version URI remain visible.

The package-level source inventory separates slide cache candidates, deduplicated component/cache/image parts, recognized owner tuples, effective OPC incoming edges and direct raw image-reference evidence. An unassigned candidate is not garbage. Image branches are explicitly raw, including opaque/inactive content, and no decoding or external loading occurs. Outside incoming users remain visible. Full raw-relationship closure and non-relationship references stay under IMP-07; no edit/cleanup permission is derived from this graph.

Shared data blocks and resource XML are scanned once. Owners stay as direct edges and images as source-part edges, avoiding a Cartesian expansion of diagrams and pictures. Traversal uses existing cancellation checkpoints and package budgets. Core/IR/Layout/Renderer/Exporter stay unchanged; no new package or dependency is needed. The public contract is [SmartArt inventory](../../api/smartart-inventory.md).

Validation includes both dialects, a same-ID trap in the data part, different slide targets for shared data, multi-page/shared resources, outside users, unassigned/absent/ambiguous/MCE cases, invalid cache/image targets, large shared-reference counts, browser/installed consumers and independent DOM checks. Three unrelated text-save rounds verify exact cache/image/unselected payloads for the synthetic fixtures. Native producer samples, actual cache preview, data/cache consistency and native node editing require separate evidence; these experiments do not close those gates.

Four pinned [external source cases](../../testing/smartart-inventory-evidence.json) additionally pass source inspection and exact no-op with independent Python ZIP/XML checks. They cover process3, orgChart1, cycle2 without a recognized cache, and PictureStrips with three images. These local corpus inputs are separate from portable CI and remain pending redistribution/fixture licensing admission. Their existing source layout IDs do not establish family creation, native editing or actual preview.
