# ADR 0019: Independent cached diagram text rectangles

Status: accepted for an experimental source-projection subset, 2026-10-25. Extends ADR0018/ADV-01.1.2; native fidelity, flipped/upright text and full geometry remain open.

A cached shape can place its text in a different rectangle, with a rotation that compensates the shape. Treating it as shape text loses those dimensions; wrapping a separately positioned text frame inside the shape transform applies rotation twice. Unknown visual presets must not hide independently located text.

The private DrawingML reader now accepts a qualified transform-child name, keeping its existing default behavior. Parser reads complete nonzero `dsp:txXfrm` rectangles and creates a parent-space identity wrapper containing visual and text siblings. Text uses the explicit rectangle rebased by the parent group's child origin. Its local angle is `(shape rotation + txXfrm rotation + bodyPr rotation) mod 360`; enclosing group transforms then apply once. The wrapper itself adds no shape rotation. Image and unsupported-preset visuals use the same split; a placeholder visual does not add a competing text label when an independent text frame is available.

The [Microsoft Open Specifications support explanation](https://learn.microsoft.com/en-us/answers/questions/912190/is-rot-attribute-in-txfrm-autogenerated-in-a-smart) describes compensating the shape angle. The [LibreOffice transform reader](https://github.com/LibreOffice/core/blob/0ea8f79d15a62dfb5a0325640ed5771fc8b75ef2/oox/source/drawingml/transform2dcontext.cxx) and [shape text mapping](https://github.com/LibreOffice/core/blob/0ea8f79d15a62dfb5a0325640ed5771fc8b75ef2/oox/source/drawingml/shape.cxx) corroborate explicit text rectangles, relative rotation and body-property rotation. This implementation expresses the source projection through ordinary Core geometry; it does not copy those readers or establish native application equivalence.

Flip combinations and `upright=true` lack a verified complete contract in this profile. They retain the visual and an unavailable text marker with a located finding. Their text bodies remain uninterpreted, avoiding scalar validation of a body the projection cannot display. Missing/zero rectangles also remain unavailable; malformed mapped transform scalars/duplicate transform nodes reject with cache-part provenance. Other unknown fields continue through the existing audit. Text without an explicit transform keeps prior behavior.

No source edit bindings or SmartArt node identities are introduced. Existing snapshot-bound saves reproject the derived group consistently; independent cached text mutations remain blocked. Repeated cache work and image/snapshot budgets retain existing ownership.

Validation uses both dialects, negative/fractional/full-turn angles, body rotation, rebased nested child spaces, independent image text, hidden/unknown visuals, invalid/unavailable transforms, preserved unrelated edits and public installed consumers. Browser tests separately verify native SVG baselines/scale matrices and rich-text frame bounds against hand-specified source geometry. Seven independent text frames from three pinned public source files are checked by Python ZIP/ElementTree for source index, text, rectangle and angle in [source evidence](../../testing/smartart-text-transform-evidence.json). Their unsupported paints/fonts/presets remain partial; no Office rendering/editing result is inferred.
