# ADR 0016: Source SmartArt component association inventory

Status: accepted for an experimental bounded inspection profile, 2026-10-25. Progress on ADV-01.1.1.1/.1.2; complete ADV-01.1.1 and inherited acceptance remain open.

SmartArt editing first needs reliable source identity and component ownership. Inferring diagrams from ZIP filenames loses multiple objects, custom paths and shared components. Treating cached shapes as semantic nodes would introduce a false editable contract.

Parser therefore extends existing slide inspection with optional readonly diagram records. Discovery walks only the effective slide shape tree, preserves raw source element/group identities using the existing MCE origin map, and resolves four role attributes through the existing OPC relationship index. Component results distinguish missing attributes/relations, wrong role, external/fragment targets, wrong content type/root and located associations. The check intentionally uses raw component roots and makes no semantic MCE projection or layout interpretation inside component payloads. Duplicate structural children reject rather than picking a relationship arbitrarily.

Core, IR, Layout, Exporter and Renderer gain no SmartArt model or dependency. Raw XML trees remain private. The existing options, checkpoints and source-index cache bound work; component lookup is indexed once per structure inspection. Output is proportional to visited effective objects and their bounded group paths, plus four records per diagram. Shared target parts are repeated as references, not copied payloads.

Native component roles/roots follow [Microsoft's DrawingML part summary](https://download.microsoft.com/download/e/1/4/e14fb96f-83b8-4a2a-84db-7fa8acbe061a/Office%20Open%20XML%20Part%201%20-%20Fundamentals.pdf) and the [diagram relationship attribute example](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/a76a4974-881b-4ca5-98fe-a758cda15e82). The [Microsoft drawing-cache part](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/ec96c9e0-757a-4f24-9725-c52d3c34e310) represents the last successful layout and can be related from slide-side parts. Its presence cannot establish freshness or identify an owner by proximity. Cache association and resource closure are deliberately separate follow-up work under ADV-01.1.1.3; no inferred cache is exposed here.

Rejected alternatives: filename discovery, treating ordinary groups as SmartArt, exposing XML in Core, and attempting to classify supported families from `uniqueId` before native layout admission. They either lose identity/ownership or promise semantics the inspection does not verify.

Validation uses both dialects, nested/multiple/shared objects, raw identity aliases, selected MCE branches, every role/status failure, independent Chromium DOM source indices and references, byte-identical no-op, three unrelated text-save rounds and installed consumers. Synthetic fixtures prove the bounded source contract; native producer/editing evidence remains required for future broader claims. API and remaining limits are in [SmartArt inventory](../../api/smartart-inventory.md).
