# 0061: Opt-in native placeholder run inheritance

Core owns the explicit reset intent. Its authoring element records selected text properties even when no named preset exists; the normalized IR remains a pure effective-value snapshot. The exporter captures that intent alongside the resolved Layout and only omits a run declaration when the selected property has no later local override and its effective value matches the target placeholder. It writes only the selected eligible level-one defaults in the target layout; other run and paragraph defaults remain untouched. No Layout-to-Core dependency or hidden global registry is introduced.

`nativePlaceholderText: "inherit"` supports Western font family, color, bold, italic, underline, strike, font size and language, plus paragraph alignment, indent, hanging indent, line spacing, space before/after and bullet. A script-font map, a font-slot null barrier, explicit color opacity, color on a non-opaque element, a mismatching value, or an unsupported property is materialized with a diagnostic. A subsequent run declaration remains explicit. Default `"materialize"` keeps historical PPTX bytes and warns that reset intent was not preserved as live native inheritance.

Adding layout defaults changed text metrics of other shapes sharing that layout in the observed PowerPoint control. Until that behavior is resolved, the opt-in reports a warning per affected layout and requires visual review. Script-specific fonts and opacity, arbitrary script-map entries, interactive native editing and more host/version combinations remain open; this profile is not evidence of complete template rebinding.

PowerPoint controls isolated the observed shared-layout position shift to adding a font default: adding only color or bold defaults did not shift the named controls. The production color/bold-only combination has been checked against materialized output and across three save/reopen rounds. This is not a proof for every font, shape or host, so the metrics warning remains. Trying to stabilize the paragraph mark with the document theme font failed when the document theme itself was Courier New.

Paragraph selection is captured per paragraph alongside per-run selection. A local declaration remains local even if equal to the target. Indent and hanging are conservatively materialized when a local or unmasked preset bullet may synthesize list indentation. Native Office may remove an empty local `a:pPr`; absence remains valid inheritance.

Frame wrap, vertical alignment and individual insets can now be omitted from an eligible slide bodyPr so they resolve from its already serialized layout bodyPr. Local declarations continue to win. A manually patched three-page PowerPoint 16.104 probe matches explicit baseline rendering and changes only the selected page after a layout-only edit. A production control also survived three native save/reopen rounds with first/final three-page rendering equal to the materialized baseline; a package-level layout edit changed only the selected page. Six individual-property controls also passed three PowerPoint save/reopen rounds and initial-open package-only layout-edit comparisons; a production autofit control also passed three save/reopen rounds for none, shrink and resize. A semantically equivalent manually patched file demonstrates dynamic resize after actual text edits; interactive layout editing and other hosts remain unverified.

Eligible autofit resets inherit as a whole in the opt-in mode. A production six-page control passed three PowerPoint save/reopen rounds; a semantically equivalent manual probe showed dynamic resizing after text edits. Interactive native layout editing and other hosts remain unverified.
