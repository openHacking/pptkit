# ADR0049: Source supplemental-font projection after native slot inheritance

Status: accepted for experimental `script-families-v2` source projection and existing scalar-save profiles, 2026-10-26. Native font-selection/shaping and complete notes inheritance remain open.

## Problem and decision

[ADR0048](0048-script-font-maps-and-language-selection.md) makes per-script families transportable without splitting author runs. [ADR0047](0047-source-script-font-profile.md) intentionally leaves supplemental collections source-only. Resolving a font only for characters present during import would couple later scalar character edits to font/style changes, breaking source-save reprojection even when no font XML changed.

Add a separately captured `textFontProfile: "script-families-v2"`. Default and v1 semantics remain unchanged. Parser retains private supplemental metadata on each source native-slot declaration until the existing independent font-field cascade has selected its final declaration. Finalization chooses the map associated with each admitted script's effective native bucket, falling back to the selected Latin declaration only when that native bucket is absent. An explicit unsupported bucket blocks that fallback. A local literal native slot replaces that bucket's older map; another theme collection replaces it with its own map. This selection never reads current characters or language.

Only finalized, admitted map key/value strings enter Core. `run.scriptFontFamilies.<code>` provenance retains actual source font/script locations, selection declaration, generic slot dependencies and target identity. Private maps do not leak into reports or Core. Existing text/notes and table property/dependency/work budgets charge the expanded effective records. Traversal is asynchronous/checkpointed over source children; the supported destination set is fixed to Core's public key contract. No package/dependency/font registry or native API is added.

## Explicit projection rules

[API](../../api/supplemental-font-import.md) specifies bucket membership, aliases and the cross-slot rule. Matching `+mj/+mn-lt/ea/cs` references carry their chosen collection's supplemental map; a deliberate cross-slot token projects the named concrete slot, without enabling script substitution on that destination. If an EA/CS declaration is absent, a Latin theme reference can supply its collection map for that otherwise-default bucket. A present but empty/unsupported declaration does not uncover an older map. Empty theme slots remain unsupported generic-family properties even when admitted individual supplemental rules are usable.

Table fontRef resolves all three effective native fields. Direct table collections parse their own supplemental dictionary and attach it as the collection's map, replacing referenced supplemental metadata when nonempty; the explicit collection choice still blocks omitted required generic slots. Higher conditional collections replace lower choices; local run/list native slots remain later in the cascade. Text language remains its existing independently inherited source value; Core's deterministic selector evaluates the retained map for current characters.

Known invalid typefaces block their own key. An entry without a script identity blocks the collection's entire admitted map because its target cannot be determined. Duplicate selected script identities reject, including duplicates outside the admitted set. Unknown scripts remain located source-only findings and do not become arbitrary Core keys. Unknown attributes/children are audited. Effective MCE branches precede interpretation. A nearer fontScheme replaces the font component, so missing maps/slots never borrow an older scheme. Theme and shared-definition caches remain scoped; source diagnostic state cannot cross target scopes.

## Evidence and limits

Eleven Parser groups cover both dialects, profile compatibility, omitted/empty buckets, literal/unsupported/major-minor overrides, malformed/unknown/duplicate rules, MCE/audit, conditional tables/fontRef, multi-master/theme scopes, exact budgets, option capture, cancellation and three scalar saves. Three cross-package groups add Node/ESM/global no-network parity, independent actual DOM paths and mutation controls, mixed text/shape/table/notes saves, warned fresh materialization and browser failure/retry. Packed runtime/types exercise v2 and its map provenance property union.

The [independent Python evidence](../../testing/supplemental-font-import.md) reads actual source ZIP/XML in four packages: 29 map properties, six scalar leaves, unchanged non-character bytes and deliberate wrong-map rejection. This proves the named source fixture, not arbitrary native font behavior. No-op and scalar saves retain source theme/collection XML; font/map/lang/style edits remain atomically blocked, with full captured-profile candidate equality rather than masked font comparisons.

The public Microsoft [MinorFont](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.minorfont?view=openxml-3.0.1) and [SupplementalFont](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.supplementalfont?view=openxml-3.0.1) descriptions establish collection/entry structure. They do not certify every producer's fallback/precedence behavior. The declared v2 rules remain an experimental projection profile pending named native comparison, real installed-font coverage, full shaping/bidi and PowerPoint edit/theme checks. Complete source font semantics and parent TODOs remain open; source font-write admission is separate.

Later [20 baseline and 32 paired native controls](../../testing/real-fonts.md) support matching explicit EA/CS supplemental references but contradict native parity for the absent-EA/CS Latin-collection heuristic. Covered cross-slot references follow the named concrete slot. `ko`/`ko-KR` and bare `zh` also expose environment-specific selection differences despite verified glyph coverage. V2 compatibility remains unchanged; [ADR0051](0051-declared-slot-supplemental-projection.md) separately admits conservative v3 selection across drawings, tables, notes and captured candidates, with missing-bucket rules reported unsupported. Full native .6.1/editing gates remain open. Do not treat the v2 heuristic as proven native source semantics or bake application font substitutions into Core/source language values.
