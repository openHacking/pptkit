# ADR0062: Source text topology edits need explicit provenance

Status: proposed research boundary, 2026-10-29. No new edit or save operation is enabled by this document. The parent task [IMP-09.2.1.3](../../planning/advanced-capability-todos.md#编辑保存的对象覆盖补齐) remains open.

## Problem

The existing `text-runs-v1`/`v2`/`v3` profiles bind character changes to existing source atoms. Their positional paragraph/run paths are useful within one immutable baseline, but the public Core text model has no persistent paragraph or run identity. After insertion, deletion, splitting or merging, equal strings, equal styles and repeated empty runs do not prove which source node survived. A general diff must not infer source ownership from text or normalized array positions.

DrawingML paragraphs can contain runs, line breaks, fields and end-paragraph properties. A line break can itself carry run properties; it is not automatically interchangeable with a newline character. Run properties can also contain hyperlinks and effects. See the Microsoft Open XML definitions of [paragraph](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.paragraph?view=openxml-3.0.1), [line break](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.break?view=openxml-3.0.1) and [run properties](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.runproperties?view=openxml-3.0.1). These definitions establish structural possibilities, not how an Office version edits or rewrites a particular file.

## Candidate contract to prove

Use an explicit operation against a session baseline and a source-bound owner/paragraph/run identity, rather than inferring a split from the final text array. The identity must be private to the format session and tied to raw owner ancestry, source part, effective/raw branch and baseline freshness. It must not expose XML inside Core. Reject an ambiguous/shared owner, inactive-branch conflict, stale session or conflicting operation; do not turn a rejected operation into an implicit fresh export.

First research one ordinary existing run split within one paragraph. The caller must choose the split point and the intended handling of direct formatting and actions. Preserve all unrelated XML lexically, including paragraph properties, adjacent unknown children, break/field nodes and end-paragraph properties. A source run with unknown child structure, unproven shared references, unsupported markup or incompatible edits remains blocked until a proof exists. If a hyperlink relationship is reused, prove the relationship still resolves and is not removed; never duplicate or delete a relationship merely from visible text.

The split coordinate system is not yet accepted: UTF-16 indices, Unicode scalar positions and grapheme boundaries can differ. Do not silently split a surrogate pair, combining sequence or emoji join sequence, and do not conflate the caller's selected text boundary with native animation range semantics. Character-range and opaque subtargets stay blocked; [ADR0039](0039-stable-paragraph-target-preservation.md) only permits a specifically proven stable paragraph range for fixed paragraph topology, not generic topology edits. Paragraph insertion/deletion/reordering requires separate range and identity proofs.

The current private [`xml-text-source`](../../../packages/pptx-parser/src/preservation/xml-text-source.ts) binds inner character spans to a validated parser tree and deliberately rejects a candidate whose element structure changes. Its raw element inventory includes a frozen parent index and complete outer lexical ranges, including inactive branches. Ranges are half-open UTF-16 offsets into decoded XML without the BOM, not byte offsets. This establishes tree ancestry and lexical location only, not effective-branch selection or permission to edit. A caller cannot implement a run split by passing markup as replacement text: markup is escaped, and the writer rechecks unchanged element count. A topology writer needs a separately reviewed lexical operation with effective/raw identity and post-write structural validation. It must retain the existing scalar writer's encoding, XML budget, abort and disposal guarantees; loosening its element-count check would also weaken unrelated scalar edits.

The private capture can read one complete element from its immutable source snapshot by raw index and expanded name, with a UTF-16 character limit and abort/disposal checks. This keeps a future writer from reading a caller-mutated input buffer or relying on a lexical text search. Reading the slice neither validates owner semantics nor creates a writable candidate; no public Parser entry exposes this operation.

Private text bindings now retain raw run and paragraph indices when the source text atom has direct DrawingML `r` then `p` ancestry. They are omitted when that exact raw ancestry is absent; for example, an effective MCE fallback run still has a raw fallback wrapper between the run and paragraph. These indices are deliberately removed from the public report and do not alter scalar-save eligibility. [Identity tests](../../../packages/pptx-parser/test/source-identity-concurrency.test.mjs) check both dialects, concurrent raw lookups and the wrapped fallback case. The next step must still prove the owning text body, unique references and complete candidate closure before allowing a topology edit.

When direct ancestry evidence exists, scalar candidate preparation now cross-checks the indices, expanded names and direct parent edges against the separately captured raw lexical tree. A mismatch fails candidate preparation; absent optional evidence does not authorize any additional operation. The check honors the existing cooperative checkpoint and is covered by wrong-run, wrong-paragraph, wrong-namespace, cancellation and MCE-wrapper controls. It is a consistency check, not a topology writer.

An experimental private preflight now validates a captured text atom's exact baseline, direct raw `p/r/t` ancestry and an interior UTF-16 offset at a runtime grapheme boundary; it returns detached text halves and source indices without constructing or writing XML. Fields, mixed text and raw MCE wrappers do not pass that direct-ancestry check. Character/grapheme work budgets, unavailable `Intl.Segmenter`, cancellation and disposal fail closed. Unicode segmentation follows the host runtime, so cross-runtime Unicode-version differences remain unverified. The preflight does **not** inspect all formatting, hyperlinks, unknown siblings or reference closure and must not be treated as permission to split a source run.

An experimental private XML-only primitive can now split one direct `p/r/t` run at a preflighted boundary. It accepts no run properties or a direct `rPr` with only unqualified `b`, `i`, `sz` and `lang` attributes and no non-whitespace children; it duplicates those declarations lexically. It does not validate their OOXML schema values or prove that a producer will interpret the duplicates identically. It rejects run attributes, hyperlinks, other run properties, opaque children and text attributes other than `xml:space`. It retains surrounding lexical content and encoding, revalidates the candidate XML and enforces output/work limits. [Private tests](../../../packages/pptx-parser/test/xml-plain-run-split.test.mjs) cover UTF-8 with/without BOM, both UTF-16 byte orders, escaping, selected scalar formatting, rejection, cancellation/disposal, budgets and three successive recaptures. This primitive has no OPC/package writer, ownership/reference closure proof, loss policy, public session API or native acceptance. Other formatting and all broader topology work remain open; the primitive is not authority to edit an imported presentation.

A separate test manually feeds this XML primitive into the existing private ZIP replacement utility for a controlled text-box fixture. Both dialects survive three split/repackage/reimport rounds with the expected run text and scalar formatting, exact non-target parts, and byte-exact no-op saves. The test itself chooses raw indices and does not exercise a session split API or prove source-reference closure. A duplicate-text control also shows that a raw index can intentionally select either identical run; equality of text and index alone is not proof of the caller's intended owner.

The [private browser control](../../../scripts/split-preflight-browser.test.mjs) bundles the internal source reader separately and compares a plain-run XML candidate, selected combining/emoji boundaries and failures in Node and Chromium without network access. It covers that named corpus and runtime pair only; it does not expose a browser API or establish equivalence across Unicode versions.

The [private XML tests](../../../packages/pptx-parser/test/xml-text-source.test.mjs) check parent identities for repeated text in separate and inactive branches, self-closing siblings, and 80 nested elements in UTF-8, UTF-16LE and UTF-16BE before and after a scalar replacement. Complete ranges are checked against exact source slices with BOMs, quoted angle brackets, comments and CDATA in all three encodings. Parent indices come from the existing bounded lexical scan stack rather than a second tree traversal. A small concurrent timing sample was noisy and does not establish a speed improvement or performance bound. These are raw-tree identity checks, not a source-to-Core topology mapping or a native save claim.

## Required evidence before implementation admission

Preliminary reader control: [text-save tests](../../../packages/pptx-parser/test/text-save.test.mjs) start with an already split, identically formatted pair containing a combining sequence and an emoji. In both dialects, the two source atoms retain distinct bindings; three rounds of ordinary scalar edits preserve the exact remaining XML and all other package parts. This is not evidence that PPTKit can split a source run or that Office preserved one.

- Positive and negative source fixtures for both dialects and encodings, repeated identical runs, empty text, XML escaping and adjacent unknown markup; independently check exact unchanged parts and lexical siblings.
- Formatting, hyperlink, field, break and end-paragraph controls; show which inputs are preserved, rejected or explicitly transformed. Include mixed supported/unsupported operations and stale plan, cancellation, retry, budget and session-disposal behavior.
- Independent parser/package comparison and candidate re-projection over three import/edit/save/reopen rounds; prove source identity mapping and absence of resource/relationship drift. Reopening alone does not prove native editability or animation playback.
- Actual named PowerPoint and LibreOffice observations for chosen operations, including Unicode boundaries, links and formatting. Record repairs, rewrites and non-equivalence rather than accepting a headless conversion as native interaction. Environments without evidence remain untested.
- Extend to merges, paragraph changes, breaks and fields only through their own contracts and tests; a run-split proof must not authorize these operations or close the parent task.

## Open decisions

Operation transport and identity lifetime, exact split-coordinate policy, namespace/encoding-safe lexical insertion, independent source closure and range mapping remain unresolved. No current public API promises them. Preserve existing no-op and scalar-edit compatibility while this research proceeds.
