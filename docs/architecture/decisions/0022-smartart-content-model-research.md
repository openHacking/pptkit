# ADR 0022: SmartArt content-forest research and native source editing

Status: experimental research decision, 2026-10-25. Advances ADV-02.1.2.4 and part of ADV-02.2.1. No public Core diagram API, native authoring/export or family admission is granted.

## Evidence before model selection

The three pinned layouts do not share a simple chain/tree/cycle authoring interpretation. process3 has nested content points that contribute to composite cards. orgChart1 has a virtual document root with two visible roots and a distinct assistant. cycle2 stores five ordered children of a document point: its visual closure is generated by layout, not a cyclic `parOf` content graph. Treating every point as visible, requiring one visible hierarchy root, or requiring a closing content edge would misrepresent these samples.

The [Connection reference](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.diagrams.connection?view=openxml-3.0.1) identifies source/destination/order fields. Source/native comparisons in [the evidence record](../../testing/smartart-content-model-evidence.json) independently check their actual role in the three exact layouts. The following is a bounded research policy for those inputs, not a rule for all DiagramML.

| Exact layout suffix | Candidate structure | Observed native operation / outstanding gate |
| --- | --- | --- |
| `process3` | Ordered rooted content forest with nested descendants retained. Composite text ownership remains separate. | PowerPoint recognized Accent Process; text edit, add, reorder, automatic re-layout, save and visible reopen were observed. Fresh minimal output, deletion, theme change, full typography and repeated native editing remain open. |
| `orgChart1` | Ordered forest, multiple visible roots, explicit assistant roles and paragraph boundaries. | PowerPoint recognized Organization Chart; text edit, child addition, reorder, automatic re-layout and save were observed with assistant retained. Reopen was interrupted by the Mac lock; other native gates remain open. |
| `cycle2` | Flat ordered children with `closure: "layout-generated"`. | Source topology verified. Native UI was not reached before the Mac lock; playback/edit/layout/empty/single-node behavior remains untested. |

All three use the full `urn:microsoft.com/office/officeart/2005/8/layout/` prefix. Matching is exact; the prototype does not guess families from arbitrary URNs or titles. Source layout XML includes multiple algorithms/constraints: process3 uses lin/composite/tx/sp/conn, orgChart1 uses hierRoot/hierChild/composite/tx/sp/conn, and cycle2 uses cycle/tx/conn. Their native geometry is not reproduced by the content model.

## Executable candidate

The pure [research module](../../../scripts/research/diagram-content-model.mjs) consumes the inspected source graph. One virtual document root organizes visible node/assistant records through unique resolved `parOf` edges, ordered by explicit numeric `srcOrd`. Noncontiguous orders are allowed; ties reject rather than use XML storage order. Every content point must be reachable with one parent. Orphans, disconnected cycles, multiple parents/repeated edges, unknown topology and references to presentation/transition points reject without repair. Presentation and transition records stay outside the candidate with explicit source coverage counts.

The detached candidate has `family`, ordered root IDs, nodes with roles/plain paragraphs/ordered child IDs, and a Cycle closure policy. Source part/index bindings and layout URN remain outside it. Candidate IDs are **local traversal IDs** only: they are invariant under shuffled source arrays with unchanged explicit ordering, but are not stable authoring identities across edits. A public contract must allocate persistent managed IDs and retain Parser-owned bindings separately. No code in a package imports this research module.

Text coverage is direct plain paragraphs, preserving empty paragraphs and soft breaks. It does not preserve formatting/theme/list levels as semantic authoring values. Stored fields and nonempty/opaque document-root text reject rather than disappear. The model is not a save projection and cannot authorize any diagram write. Full rich text, field semantics, source extensions, parameters, layouts and visual ownership remain source evidence for later adapters.

Default bounds are 10,000 content points including the virtual root, 20,000 parent edges, depth 256 and 200,000 work checkpoints; overrides must be known positive safe integers. Iterative traversal avoids call-stack recursion. These limits cover trusted inspection records, not hostile JavaScript accessors or a security sandbox. Source XML/text/byte budgets remain Parser's responsibility. Layout, renderer and native authoring support are not established by this projection.

## Validation and next decisions

`pnpm test:diagram-research` runs seven groups: explicit order/storage independence, hierarchy roots/assistant/paragraphs, Cycle closure and empty/single-node projection, presentation/transition separation, malformed/unknown/field/identity/topology rejection, limits/retry and 1,500-level traversal, and 100 seeded forests checked against an independently built parent map. The suite is part of `pnpm test`.

The optional [source/native verifier](../../../scripts/inspect-smartart-content-model.mjs) uses Python ZIP/ElementTree independently of Parser to check content identities, parent/child order, roles, paragraphs and cache model references. It covers the three original sources and two PowerPoint-saved outputs, including exact no-op results for all five. Screenshots/AX hashes record the actual UI observations; the verifier does not launch/replay or certify those actions. [Native editing notes](../../testing/smartart-native-editing.md) retain version, operations, observed results and untested gates.

Decision: retain the ordered-forest candidate and explicit assistant/closure distinctions as a research foundation. Defer all three public native family admissions until minimum generated outputs, complete rich-text/style/parameter policy, deterministic geometry/cache consistency, native deletion/theme/reopen/multi-round operations and supported application evidence pass their own gates. Existing source preservation and cache preview remain available within their contracts. This ADR does not close ADV-02/03 or the overall implementation objective.


The subsequent [ADR0027 source-binding adapter](0027-smartart-source-binding-research.md) remaps the unchanged traversal projection into a distinct managed domain. It consumes explicit scope/root/part/layout state and cumulative work; projectDiagramContent itself retains its original projection-local identity contract.
