# ADR 0063 — Explicit chart blanks

Status: accepted for fresh bar, standard line and pie authoring, and bounded content projection. AUT-06.2 and its native editing and formatting gates remain open.

A missing point is not numeric zero. Core represents a blank only as an explicit `null` in a dense, category-aligned values array; array holes and non-finite values remain validation errors. This widens the public normalized value type, so typed consumers must handle null. Positive and negative zero remain numbers. The optional `blankDisplay` selects `gap` or `zero` for bar, line, pie and doughnut, and `span` for line. The default is `gap` when any value is blank and `zero` otherwise, including for legacy normalized inputs without this property. Gap lines split at blanks; zero lines render zero-valued points and markers; span lines connect present points without extrapolating beyond them. Gap bars omit blanks; zero bars expose zero-height geometry marked `blank`. Pie and doughnut blanks produce no visible slice. `ChartLineLayout.segments`, when present, expresses the line paths and must be used for drawing.

Fresh export emits an empty numeric workbook cell and omits the point from a numeric cache whose declared count still includes every category. Export writes the selected display policy without replacing the underlying blank data. [Microsoft's Office format notes](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/b5c5c694-21d9-437c-9a4a-21e0e843eed8) describe gap support for these chart families. A three-round PowerPoint save/reopen observation is recorded in [chart-blank evidence](../../testing/chart-blank-powerpoint-evidence.json), not as proof of interactive data editing.

Import admits an existing sparse numeric cache only when a supported blank policy is explicit, the cache declares its point count, and that count matches the already parsed dense categories. Allocation and iteration are bounded by the category count and data-point budget, not the untrusted declaration. If the numeric cache is absent, a supported explicit policy also admits a local one-dimensional workbook range of exactly the verified category count: absent cells and plain numeric cells without value/formula children map to null; an empty `<v/>` is not admitted. Error, boolean, text, unresolved formula, unknown cell metadata or content are never inferred as blanks. Unspecified or incompatible blank policies, missing counts, errors and malformed values remain source-only. Cache snapshot precedence and conflict reporting remain as in [ADR 0002](0002-chart-data-projection.md). Workbook fallback is a data projection, not proof of the source's native display: [one PowerPoint observation](../../testing/chart-workbook-only-powerpoint-evidence.json) showed blank plots when numeric caches were absent. The existing-value preservation profile cannot edit charts with sparse caches; no source atom or workbook cell is fabricated. No-op preserves the original bytes; an unrelated admitted text edit can retain the chart cache and workbook byte-for-byte.

The [cross-package suite](../../../scripts/chart-blank-parity.test.mjs) covers blank/zero distinction, all-blank series, line breaks, stacked bars, cache/workbook synchronization, three fresh rounds, both chart and workbook dialects, cache/workbook conflicts, absent and explicit workbook blanks, Node/browser ESM/global parity, source-only unsupported policies and blocked preservation edits. [Additional PowerPoint evidence](../../testing/chart-blank-modes-powerpoint-evidence.json) checks line gap/zero/span and bar/pie zero on first open and one save/reopen, including vector geometry and retained empty workbook cells. It does not establish date/error/formula semantics, labels, all chart families or native Edit Data behavior.

[Doughnut charts](../../api/chart-doughnut.md) use the same null/cache/workbook model and bounded explicit policies; their native observation is separate from the bar/line/pie samples above.
