# ADR 0020: SmartArt source data graph inspection

Status: accepted for an experimental read-only format profile, 2026-10-25. Advances ADV-02.1.2.1/.2.3; semantic graph editing, cache consistency and native family admission remain open.

Component locations and cached shapes cannot explain content/display nodes, auxiliary transitions or graph references. A generic Core tree would discard those distinctions before the layout/model contract is known. Parser therefore owns a detached source graph per located data part. It reads direct point/connection lists, typed identity references, source order, direct stored text and unvalued property attributes; no raw XML or OOXML identity enters Core/Layout.

The [Open XML SDK source schema](https://github.com/dotnet/Open-XML-SDK/blob/main/data/schemas/schemas_openxmlformats_org_drawingml_2006_diagram.json) describes model identifiers as an int32/GUID union and explicit uint32 connection orders. The [Point](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.diagrams.point?view=openxml-3.0.1) and [Connection](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.diagrams.connection?view=openxml-3.0.1) references identify the corresponding elements and fields. The [OOXML primer](https://download.microsoft.com/download/e/1/4/e14fb96f-83b8-4a2a-84db-7fa8acbe061a/Office%20Open%20XML%20Part%203%20-%20Primer.pdf) describes transition-only `cxnId` use. The implemented profile retains lexical source values and distinguishes unknown/missing/duplicate IDs rather than rejecting every unsupported graph spelling or inferring a repaired tree.

Point and connection identities share a table, with broad-kind reference validation. Numeric aliases compare by value; recognized uppercase braced GUIDs compare literally after XML edge trim. Cache shapes expose raw model references separately: several shapes referencing one model do not create duplicate data identities. Full content/display/visual mapping is a later slice. Presence of source text or a unique link never grants source-edit permission, native validity or freshness.

MCE data parts and ambiguous list topology remain source-only. Limited `inspected` status names coverage rather than full schema validation; unsupported typography, layouts, effects, extensions and graph constraints remain outside it. Unknown source stays in original bytes. Cyclic graphs retain source edges; no validity/layout repair happens.

Format-owned `diagramLimits` extend presentation inspection options, without adding diagram settings to OPC. Distinct-part graph checkpoints and findings share per-inspection limits and fail explicitly before returning a truncated success. ZIP/XML limits still bound raw payloads/trees. Options are captured before awaits and carried through byte/file imports and text-save candidate reprojection; Core, filesystem adapters and the generic OPC layer do not implement graph semantics.

Validation combines both dialects, malformed and shared synthetic data, independent browser DOM, public installed consumers, custom-budget file/candidate tests, three source-preserving text-save rounds and seven pinned public source files checked with Python ZIP/ElementTree. It does not substitute for actual native node insertion/removal, re-layout, cache freshness or visual comparisons. The [API contract](../../api/diagram-data.md) and execution record distinguish those remaining gates.
