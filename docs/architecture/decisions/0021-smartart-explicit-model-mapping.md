# ADR 0021: Explicit SmartArt source model mappings

Status: accepted for an experimental source profile, 2026-10-25. Advances ADV-02.1.2.2; family semantics, ownership/layout decisions, cache freshness and native editing remain open.

A cache shape and content node need not have a one-to-one relationship. Cache `modelId` references a model point; presentation points carry property/connection associations to other points. Guessing by text/order or choosing one relationship discards evidence. Expanding every owner × data node × cache shape would multiply shared data. Parser therefore stores presentation evidence once per data part and recognized cache references once per explicitly used pair, reusing model indices and cache scans. Existing owners retain slide/object provenance. No new package/dependency or Core/Layout coupling is introduced.

The [DSP shape specification](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/060cdb7c-1d52-4a9f-9319-bf1849c1f830) defines `modelId` as a data-model reference. [PropertySet](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.diagrams.propertyset?view=openxml-3.0.1) describes `presAssocID` and presentation indexing; [ConnectionValues](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.diagrams.connectionvalues?view=openxml-3.0.1) distinguishes `presOf` from parent connections. Independent source checks corroborate connection direction. Two process3 points have differing property/connection targets, so agreement is descriptive, without a validity assertion or repair rule. Layout expressions and semantic text ownership remain uninterpreted.

Only unique broad-kind points resolve. Unresolved/nonpresentation destinations remain in the source graph; duplicate visual references are valid raw evidence. Recognized cache traversal excludes extension descendants; raw inventory still retains them. MCE, missing/ambiguous trees or source-only graphs produce source-only maps. Empty explicit trees do not imply usable preview content. Graph work/findings budgets cover mappings too, with existing capture/cancellation/candidate validation. No diagram edit bindings, native validity or cache freshness follow.

Validation combines both dialects, one-to-many/differing-target evidence, alias/cross-kind collisions, tree boundaries, source-only cases, shared owners and distinct identity spaces, budget failures, no-op, independent DOM/browser/installed consumers and three unrelated text saves. Python independently checks 103 presentation maps and ten cache shapes in seven pinned source files. Fixture licensing and actual native editing/layout remain open; the [API contract](../../api/diagram-mapping.md) defines index scopes and limits.
