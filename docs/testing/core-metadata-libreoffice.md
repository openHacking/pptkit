# Core metadata: LibreOfficeDev headless observation

This experiment uses LibreOfficeDev 26.8.0.0.alpha0 (2c87e51eeaa2b413ff4ae097b2705eea1995d8e5) on macOS arm64. It compares one PPTKit source-preserving edit with an unchanged control. Each file is independently opened and resaved three times using the headless Impress Office Open XML filter. This is one fixture, not a general interoperability guarantee; it does not verify interactive application behavior, repair dialogs, metadata UI, or PowerPoint.

The edit changes title, subject, description and language. Before the application conversions, an independent ZIP comparison found only `docProps/core.xml` changed between the source control and edited packages. Both start with the same author, revision, keywords, last-modified-by and creation/modification timestamp sentinels. An independent Python ZIP/XML reader inventories each retained output, including slide text.

Across all three headless resaves, the four edited values and the control values survived. Author, revision, last-modified-by, both timestamp strings, and the slide text also survived in both paths. The first resave changed the keywords string in both files from `alpha, beta` to `alpha beta`; it stayed in that form for the next two rounds. Thus the application conversion itself was not a byte- or metadata-preserving round trip, even for the unchanged control. Other metadata, producer versions, documents and user interactions were not assessed.

The [recorded manifest](core-metadata-libreoffice-evidence.json) contains application version, exact XML inventories, artifact hashes and conversion logs. Generated files are retained locally under `.tmp/core-metadata-libreoffice/`; that directory is not a portable committed fixture. On the machine retaining those files, run `python3 scripts/research/verify-core-metadata-libreoffice.py` to verify their hashes, independent inventories, paired round order and source package difference. Reproduce the experiment with `node scripts/research/core-metadata-libreoffice.mjs`; a new run writes a new manifest and may differ across environments.
