# Shared master image replacement: named native observation

A PPTKit-authored deck uses a shared master on three pages and another master on a fourth. Its image replacement plan changes the shared master's contained 2×3 PNG into a 4×2 transparent PNG, using the previously resolved 160×240 frame. A blue rectangle lies behind the image; a separate master contains a green rectangle. The third page suppresses inherited artwork.

PowerPoint 16.104 on macOS 26.5 opened the generated PPTX and showed a slideshow. In the manual observation, pages 1 and 2 showed red and the blue background visible through the transparent half; page 3 showed neither; page 4 showed the independent green rectangle. This is first-open display of generated output, not a native image replacement, edit, save/reopen, or proof of color and alpha fidelity across formats and applications.

The [independent oracle](../../scripts/research/oracles/master-image-replacement-native.py) follows each page's slide → layout → master relationship, verifies the selected master picture's frame and transparent PNG bytes, checks page text and visibility attributes in the package, samples two colors per screenshot and verifies distinct screenshot title crops. It rejects three substituted controls. The screenshot title crops are not OCR and do not independently prove their page labels; the UI sequence and page identity are manual observations. [Evidence](master-image-replacement-native-evidence.json) binds files, scripts and screenshots. The PPTX, producer report and four SVGs reproduced byte-for-byte in a second directory. Local screenshots remain in `.tmp`.


## Native crop edit and one reopen

On a separate copy, PowerPoint 16.104's shared master view exposed the picture. Its left crop handle was dragged inward, then the file was saved, closed and reopened. The two shared pages showed the same new blue/red/blue sampled pattern; the hidden page remained white and the independent master remained green. This is a manual observation of one crop-handle edit and one save/reopen, not a native replacement of the image resource or a general editability claim.

The [edit oracle](../../scripts/research/oracles/master-image-native-edit.py) follows all four page-to-master relationships, checks the native crop value and changed picture frame, confirms exact transparent PNG bytes, checks page text and visibility, samples the screenshots and rejects three substituted controls. Screenshot title crops are compared with the first-open captures but do not independently witness UI provenance. [Evidence](master-image-native-edit-evidence.json) binds the native output, screenshots and parser report. PowerPoint renamed the media part and removed an unused old asset in this sample; this is not evidence that arbitrary unknown resource references can be deleted safely.

PPTKit's default content projection did not reconstruct source master artwork for this file (`projectedMasterCount: 0`). Its no-op save returned the native file byte-for-byte, which proves preservation for this file without proving semantic master-image import or edit-save. The [parser check](../../scripts/inspect-master-image-native-edit.mjs) reproduces that boundary. The later explicit `artwork-v1` projection maps the named shapes and image; [its separate SVG sampling](master-artwork-projection-evidence.json) is not a source-preserving edit.

PowerPoint 16.104 subsequently opened a [fresh export](../../scripts/prepare-master-artwork-projection-native.mjs) of that partial projection. Four-page slideshow screenshots were captured, the file was saved under a new name, closed, reopened, and the same four pages were captured again. The [independent oracle](../../scripts/research/oracles/master-artwork-projection-native.py) checks the slide text, slide-to-layout-to-master graph, blue shape before the cropped picture, green bystander, crop/frame, exact PNG bytes, screenshot sample colors and distinct title crops, and rejects three substituted controls. [Evidence](master-artwork-projection-native-evidence.json) binds the input, export, PowerPoint-saved file, screenshots and oracle. This is one Save As/reopen, with no native editing of this projection; screenshot pixels alone do not establish UI provenance. Other omitted source semantics and source-preserving edits remain unproven.
