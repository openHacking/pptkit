# Exact decimal source-save: LibreOfficeDev comparison

The [source fixture](../../tests/fixtures/custom-exact-decimal-source.pptx) was generated directly by PPTKit with three `vt:decimal` custom properties: `0.1`, `9007199254740993.0001`, and `-0.0001`, plus an unrelated string. It is not a native-application-authored file. PPTKit's explicit exact-decimal source-save profile changed the first value to `0.2` and the second to `9007199254740994.0001`. Independent ZIP and XML comparison confirms that only those two text values in `docProps/custom.xml` changed. The [automated test](../../packages/pptx-parser/test/custom-property-exact-decimal-save.test.mjs) reconstructs both the fresh source and the edited output and checks their SHA-256 hashes against the record.

LibreOfficeDev 26.8.0.0.alpha0 resaved the unchanged and PPTKit-edited files separately three times using isolated headless profiles. The first resave removed all three named decimal properties in both branches; the unrelated string remained. Subsequent resaves did not restore the decimal properties. An XML scan across every XML and relationship part found no `vt:decimal` elements in those outputs. This is an observation for one generated fixture and one version, not evidence about native authoring, interactive editing, PowerPoint or other decimal values.

The [record](exact-decimal-save-libreoffice-evidence.json) contains the producer version, package hashes, process logs and inventories. The eight observed PPTX files are retained under `.tmp/exact-decimal-save-libreoffice` locally, not distributed with the repository. Run `python3 scripts/research/verify-exact-decimal-save.py` where those artifacts exist to independently re-read each ZIP and XML payload, validate hashes and check the two exact source changes. The verifier rejected modified hashes, inventories and process statuses during this run. The record alone is not independent proof that the external producer ran.

To reproduce, run `pnpm run build:browser`, then `python3 scripts/research/probe-exact-decimal-save.py > evidence.json` with the recorded LibreOfficeDev build available as `soffice`. Pass the resulting file to the verifier. Output ZIP metadata and hashes can vary across environments.
