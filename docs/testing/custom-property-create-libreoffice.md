# Created custom properties: LibreOfficeDev headless observation

This experiment uses the SHA-256-verified PPTKit-produced input recorded in `core-metadata-libreoffice-evidence.json`, which has no custom-properties relationship. It compares an unchanged control with a `create-and-append-v5` save containing five typed properties. For that initial save, an independent ZIP comparison found exactly one new part (`pptkit-custom-properties-1.xml`), changes to the root relationships and content-types declarations, and no other changed payloads.

LibreOfficeDev **26.8.0.0.alpha0**, on macOS 26.5 arm64, headlessly resaved each branch three times. Independent XML inventories found all five edited values in every edited output. LibreOffice reordered and reassigned property IDs, serialized the boolean as `1`, normalized the date, and changed the integer from `i4` to `r8`. It also added `PresentationFormat` and `Slides` to both branches. Thus this observation supports value retention in this sample, not preservation of property types or IDs by LibreOffice.

The [record](custom-property-create-libreoffice-evidence.json) contains input/output SHA-256 hashes, exact inventories, subprocess logs and runner identity. Recheck retained artifacts with `python3 scripts/research/verify-custom-property-create-libreoffice.py`; reproduce with `python3 scripts/research/custom-property-create-libreoffice.py` in the recorded environment. Artifacts live under `.tmp` and are not a portable fixture corpus. This does not establish PowerPoint behavior, visual fidelity, native editing, or interactive save/reopen behavior.
