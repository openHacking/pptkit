### Retained corpus text audit

The separate [retained-artifact audit](corpus-retained-text-audit.json) rechecked the recorded byte lengths and SHA-256 of all seven source PPTX files, seven saved PPTX files and seven reopened PDFs before inspection. Its [independent Python tool](../../scripts/research/corpus-retained-text-audit.py) reads presentation relationships and ordinary slide XML paragraphs, checks corresponding source/saved paragraph sequences and hidden flags, then searches the saved visible-slide paragraphs in extracted PDF text with whitespace removed. Run `python3 scripts/research/corpus-retained-text-audit.py .tmp/corpus-retained-text-audit.json`; the optional retained local files and PyMuPDF are required. [Negative tests](../../scripts/research/test_corpus_retained_text_audit.py) reject tampered artifacts and reveal changed text, hidden-state mismatch and unresolved page mapping.

The seven retained pairs have matching slide counts, ordinary paragraph sequences and hidden flags. Each reopened PDF has one page, matching the count of non-hidden saved slides, and all 17 ordinary paragraphs on those pages occur in the corresponding extracted PDF text after whitespace removal. The text and theme/layout fixtures each have a second hidden slide; its absence from the PDF is not evidence of its rendering. The chart and missing-asset fixtures have no ordinary slide paragraphs and therefore provide no chart-text or asset visibility evidence in this audit. The page pairing assumes the saved presentation's visible slide order; extraction does not establish that text was visible, correctly positioned, legible or unmodified during an interactive edit. The earlier record shows the chart sample's three workbooks became zero on the headless resave. These results do not establish layout fidelity, editability, a repair-dialog outcome, PowerPoint behavior or stable LibreOffice compatibility.

### Fresh headless source/saved render comparison

The [render audit](corpus-headless-render-audit.json) independently rechecks the input and saved PPTX hashes, then uses fresh isolated LibreOfficeDev profiles to export each directly to PDF. PyMuPDF rasterizes corresponding pages at its default 1× scale; the script compares page rectangles and RGB pixels without a tolerance. Each pair yielded one 961 × 540 raster. Changed pixels out of 518,940 were: text 455, theme/layout 0, geometry 937, images 292, table 0, charts 2,433 and missing-asset 0. Bounds and maximum channel differences are recorded, not interpreted as severity or causes. A second fresh run produced identical page comparison metrics, although the generated PDF hashes differed; its local record is `.tmp/corpus-headless-render-audit-repeat.json`. The generated PDF files and logs remain in the directories named by each local record.

Reproduce with `python3 scripts/research/corpus-headless-render-audit.py soffice .tmp/corpus-headless-render-audit.json`; [unit tests](../../scripts/research/test_corpus_headless_render_audit.py) verify matching pixels, a visible change and page-size mismatch. The audit includes only pages exported by the headless application, not hidden slides. Zero pixel differences do not prove that content is editable, that chart workbooks survived, or that missing assets were displayed; for example, the retained chart save has no embedded workbooks. This is comparison within the same development application and environment, not a comparison with PPTKit SVG, other applications, interactive operations or human-reviewed visual fidelity.

The separate [PDF structure comparison](corpus-pdf-structure-audit.json) verifies the generated PDFs against the render record's hashes and compares PyMuPDF text spans, path records and image inventories by ordinal position. All paired text spans have equal extracted text, font names and sizes. Their largest bounding-box coordinate deltas are approximately 0.029 pt for text, 0.099 pt for geometry, 0.028 pt for images and 0.057 pt for charts; theme/layout and table text span bounds match. Path records also differ in the four raster-different fixtures; theme/layout has a path coordinate difference despite identical pixels at this scale. The images and charts fixtures each contain one extracted base image with the same decoded sample hash across the pair, but their placement rectangles differ. This check does not compare soft masks or prove that these coordinate changes caused all raster differences, and ordinal correspondence is an assumption rather than independently established object identity. Run `python3 scripts/research/corpus-pdf-structure-audit.py .tmp/corpus-pdf-structure-audit.json` against the retained render directory; [tests](../../scripts/research/test_corpus_pdf_structure_audit.py) exercise changed positions and unequal object counts.

## Stable LibreOffice on macOS

The [stable release evidence](libreoffice-stable-macos-evidence.json) records LibreOffice **26.8.2.2** on macOS **26.5 (25F71), arm64**, run from a read-only official disk image with a matching SHA-256 and verified app signature. All seven pinned inputs saved and reopened to PDF with independent ZIP CRC, XML parsing and visible-page counts. Slide order, hidden flags and ordinary paragraph sequences matched. The chart sample retained all three numeric caches (2, 4, 3 each) but lost all three embedded XLSX parts and their external-data declarations. Thus the intact cache is not evidence of workbook preservation.

At the recorded raster scale, four source/resave PDF pairs differed: text (455 pixels), geometry (937), images (292) and charts (2,433); the other three matched exactly. These compare rendering before and after the stable application's save, not rendering against PowerPoint or PPTKit. Headless runs cannot observe repair prompts.
