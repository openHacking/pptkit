# Combined extended-property creation: LibreOfficeDev observation

A control was derived from a hash-checked PPTKit presentation by removing its core and extended properties and their declarations. It had no custom-properties part. PPTKit then created core, extended and custom properties in one edit: title `Created 中文`, company `Company & 中文`, and integer custom property `Count` = 42. Independent ZIP comparison found exactly those three added parts and changes to the root relationship and content-type declarations.

LibreOfficeDev 26.8.0.0.alpha0 headlessly resaved the control and edited sample three times. The edited sample retained the title, company and numeric value in each round; the application changed the custom value type from `i4` to `r8`. The control acquired an empty core title, and an empty custom-properties part appeared by the second round. These are observations for one synthetic Transitional sample, not a general fidelity guarantee.

The [evidence record](extended-create-libreoffice-evidence.json) contains file hashes, inventories and conversion logs. `python3 scripts/research/verify-extended-create-libreoffice.py` independently checks the eight retained files, metadata relationship modes, content types and XML roots, the control's derivation, source isolation and observed values. `python3 scripts/research/test_extended_create_evidence.py` checks five corrupted evidence records and three corrupted packages whose hashes were recomputed. Local artifacts are under `.tmp/extended-create-libreoffice`; run `python3 scripts/research/extended-create-libreoffice.py` to repeat in the recorded environment. This does not establish interactive editability, repair prompts, PowerPoint behavior or Strict dialect compatibility in LibreOffice.
