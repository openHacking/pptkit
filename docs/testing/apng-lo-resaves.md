# APNG bytes through LibreOfficeDev headless resaves

On 2026-10-27, `scripts/prepare-apng-probe.mjs` generated a one-slide PPTX with the [Pillow-created APNG](../../tests/fixtures/two-frame-apng.png). LibreOfficeDev `26.8.0.0.alpha0 2c87e51eeaa2b413ff4ae097b2705eea1995d8e5` opened and converted the PPTX to PPTX three times using an isolated headless profile and separate output directories. The [independent inspector](../../scripts/research/oracles/apng-lo-resaves.py) follows the slide image relationship, checks the image bytes and APNG chunk CRCs, and records geometry and hashes in [evidence](apng-lo-resaves-evidence.json). Media-byte and missing-relationship negative controls were rejected. The [third resave](../../tests/fixtures/apng-libreoffice-resave.pptx) is retained for import and no-op regression testing.

All four packages refer to byte-identical two-frame APNG data. LibreOffice renamed the media part. The contained picture's source extent was 6,858,000 × 4,572,000 EMU; the third resave had 6,856,920 × 4,570,920 EMU, a reduction of 1,080 EMU (about 0.085 pt) per dimension. The test does not assert geometry is preserved, and the observation is limited to this fixture and build.

This is **file-preservation evidence**, not animation-playback, interactive-edit, visual-fidelity, or PowerPoint evidence. Headless conversion does not establish that the animation played. The complete source, all three resaves, and preview used during observation are under `.tmp/apng-lo-probe-01`; the evidence hashes do not guarantee those temporary files remain available. To reproduce, create separate empty source and round directories, run the producer, perform three sequential `soffice --headless --convert-to pptx` conversions with an isolated user profile, then invoke the inspector on the parent directory. Outputs vary with application and runtime version.
