# Chart label source-binding research

This record began as source-structure research and now also describes a scoped label edit-save implementation. The generated [two-series fixture](../../tests/fixtures/chart-label-source.pptx) has SHA-256 `c0de433468b8ff711af750964b83821bfe19b9aa0d2198a7967dd7d6b4410fa4`. It is reproduced by `node scripts/research/generate-chart-label-source.mjs`; the retained generator SHA-256 is `8af505a2caa4204e9d8ee2ff2f3603fb2e12e10f898a00cb2ac50edf578cd42d`.

An independent Python ZIP/XML reader checks each of the two series' category caches and series-name caches against the nested workbook. The category formula is `Sheet1!$A$2:$A$4` in both series: an edit to one logical category therefore requires coordinated updates to two separate cache points and one workbook cell. Series names reference distinct `B1` and `C1` cells. The fixture also checks leading/trailing whitespace, XML ampersands, Unicode and a literal `_x0041_` sequence encoded as `_x005F_x0041_`; decoding must be one pass. The inspector SHA-256 is `59997f8f4f8a940b5ab708afb2575aa5e2589523f50da287d392cbce8cdda556`.

Run `python3 scripts/research/verify-chart-label-source.py tests/fixtures/chart-label-source.pptx` and `python3 scripts/research/test_chart_label_source.py`. The latter creates four corrupted variants: one diverging cache, one range change, one incorrect escape and one diverging workbook cell. All are rejected by this fixture-specific oracle. The Parser test also confirms the exact projected strings, that the current numeric-only source-save profile blocks a category edit, and that undo restores byte-exact no-op eligibility.

A future write profile needs explicit ownership and alias closure across every affected cache, cell and chart; bounded agreement and conflict checks; a shared-string policy; whitespace and ST_Xstring encoding; exact preservation of unrelated XML and ZIP payloads; atomic mixed edits and stale-plan checks; candidate reimport; and independent multi-round, browser and native-application evidence. This sample covers only generated inline strings and one shared range. Rich/shared strings, formulas, external or shared workbooks, other producers and interactive editing remain unverified. The later opt-in v4 profile described below enables a bounded source-label write.

The internal chart reader now keeps the XML-decoded **source lexical string** separate from the one-pass decoded projection, and the workbook reader captures a source location for a single direct inline string only when its cell, container and text have the recognized simple structure. Rich runs, shared strings and unknown text attributes do not receive that candidate source location. These are internal inspection facts, not proof of write eligibility: the future binder must still establish raw ancestry, alias closure and all candidate-save guards. Focused tests cover both OOXML dialects, out-of-order cache points, escape sequences, XML entities, simple/complex inline cells and disabled capture.

An internal [closure candidate](../../packages/pptx-parser/src/import/chart-label-closure.ts) groups resolved physical cache observations by expected logical label and workbook cell. The caller must supply a complete formula-use count, including non-label references, and attest that its scan is complete; the closure itself does not perform that scan or validate raw ancestry. A private, opt-in path in the chart importer now collects categorical cache points and simple inline workbook sources from its actual resolved references and passes its formula-use counts to this check. It rejects missing expected labels, unaccounted references, conflicting logical owners, duplicate cache locations, inconsistent physical cell identities and decoded-value disagreement, under a bounded work counter and checkpoint. [Tests](../../packages/pptx-parser/test/chart-label-closure.test.mjs) exercise that path in both OOXML dialects and check unknown formulas, aliased name/category cells, rich strings and cache/workbook conflicts. The path does not appear in public import reports or save authorization, and `bound` in this private intermediate result is not a public write guarantee. Full raw ancestry and candidate revalidation remain required.

The private collector additionally checks the raw direct `cat → strRef → strCache → pt → v` chain, point identity, scalar lexical agreement and a restricted set of known attributes and children. Unknown cache/reference extensions or metadata block the affected candidate; cache and reference scans are memoized and charged to the existing binding-work budget. It also verifies that each category's original parent chain is the projected series, family, plot area, chart and chart-space root. Tests insert unknown attributes and extensions, and simulate a broken source-parent link at each level. These checks do not authorize a write or validate a changed package.

The private chart staging function can now prepare cache points and their shared inline worksheet cell together with numeric edits. It protects literal Xstring escapes and XML-forbidden code units, rejects competing cells and inconsistent source observations, and inserts or updates `xml:space="preserve"` when the replacement has boundary whitespace. A focused test applies the staged ZIP replacements and reimports the generated two-series fixture. The public profile described below uses this staging path; independent coverage beyond the generated fixture and native application verification remain outstanding.

An opt-in internal projection now associates those closures with the projected slide, chart and category identities. Private snapshot analysis accepts a changed category only when the binding is unique, its original value matches the baseline and its closure is bound; other changes still require their own bindings. Tests exercise real projection identity, stale and unmapped bindings, duplicate identities and unrelated edits. The v4 import option described below enables this path.

The private candidate pipeline now includes label source parts in package-closure inspection, stages label and numeric edits together, and reprojects the candidate. It checks the full Core snapshot and compares the rebound label's cache and worksheet physical identities and decoded values with the proposed edit. A focused end-to-end private test also rejects a changed source index. Independent coverage beyond the generated fixture and native evidence remain outstanding.

The explicit content option `chartEditSaveProfile: "existing-values-and-labels-v4"` enables this bounded category write alongside v3 numeric capabilities. It requires every category cache to resolve to one unshared internal workbook cell with a direct simple inline string and complete reference closure; unsupported sources remain blocked. Boundary whitespace causes the worksheet text’s `xml:space` to be inserted or updated to `preserve` when necessary. The save report includes `chartLabel` with the before/after value and category index. Tests exercise mixed numeric/label edits over three reopens, both namespace dialects, and rejection of an unaccounted formula. An independent Python ZIP/XML oracle checks three label-only rounds, both series caches, the shared worksheet cell, and every other XML structure and package payload; corrupted cache and unrelated-text variants must fail. Run `pnpm test:chart-save-evidence` after building the Parser. These generated-source tests do not establish PowerPoint or Excel interactive behavior.

The [cross-runtime test](../../scripts/chart-value-save-parity.test.mjs) compares Node, browser ESM and browser global bytes and reports over three combined label/numeric saves, with XML metacharacters, escape-like strings, boundary whitespace and Unicode. A shared-string workbook must block a combined edit without a partial plan in both browser entries. A file-adapter test verifies invocation-time capture of the v4 option. These tests run as part of `pnpm test:import`.

For an inline text cell with missing `xml:space` or explicit `default`, three saved/reopened rounds verify insertion or replacement with `preserve`. Attribute changes and text edits are staged in the same nested workbook candidate; the updated attribute is checked during candidate rebinding. The independent Python oracle checks both cases and rejects an unrelated cell attribute mutation; Node, browser ESM and global outputs match. Cancellation, stale plans and combined change limits have focused v4 tests. Native application evidence for this case is not yet available.

The chart reader also has a private, opt-in inspection for categorical, scatter and bubble series names. It checks direct `tx → strRef → strCache → pt → v` ownership and its series-to-chart ancestry, then applies the same complete formula-use counts to the name's workbook cell. Tests cover both namespace dialects for categorical charts, aliased series names, unknown source attributes and broken parent identity. The generated scatter and bubble fixtures are reproduced by `node scripts/research/generate-chart-coordinate-names.mjs`; their SHA-256 values are respectively `6b2c8b48c0e533c7e76a4088d023b71150b04c38ece6a3aa86d0af8fec8331d8` and `c3de2c328ba013cd4c7401a75355521ffe3aa23bfb2bbef49b0f764a0ee31841`. The explicit Parser option `existing-values-and-series-names-v5` now exposes these sources and permits scoped name saves alongside category and numeric edits. Generated tests cover three category-chart rounds, scatter/bubble name saves and alias rejection. An independent Python ZIP/XML oracle checks three name-only saves and rejects unrelated series changes and incorrect workbook cells; Node and browser ESM/global also match over three mixed name/category/value rounds. A [PowerPoint accessibility-tree observation](chart-series-name-powerpoint-reopen.md) covers three category-chart reopens; One subsequent PowerPoint resave retained name sources; Excel editing and other native cases remain unverified.
