# Native PowerPoint caption observations

PowerPoint for Mac 16.104 inserted `English.en-US.vtt` and `French.fr-FR.vtt` on the first video of `pptkit-video-trim.pptx`, whose first video has 150 ms removed at the start and 50 ms at the end. The two source files each contained two cues at 0.100–0.900 and 1.000–1.800 seconds. The editor recognized the filename language tags; the French label was set to `French test`. The [single-track](../../tests/fixtures/powerpoint-caption-single.pptx) and [two-track](../../tests/fixtures/powerpoint-caption-multi.pptx) samples retain PowerPoint's saved parts, apart from anonymizing the last-modifier metadata. Reopening the two-track file showed both tracks and the custom label in the editor. The second video instance shares the MP4 and has no tracks.

The slide's Office 2017 `tracksInfo` extension lists each language, label, generated track ID and relationship. Separate slide relationships target two VTT parts, with `text/vtt` in content types. The two stored cue timecodes match the inputs despite the trim. There is no default flag in this observed structure. This does not prove which track plays by default, whether the first cue is clipped, or how cue time maps to a trimmed playback clock; playback was not observed.

Run the research-only inspector with `python3 scripts/research/inspect-native-captions.py tests/fixtures/powerpoint-caption-multi.pptx`. It lists observed track links and checks only UTF-8 and a `WEBVTT` header, not complete cue validity. Tests cover no tracks, one track, multiple tracks, invalid bytes/header, absent or wrong relationships, MIME mismatch and an external target without fetching it. Current Parser reports source track parts as unsupported and preserves unchanged packages byte-for-byte; fresh export does not preserve captions. The [decision](../architecture/decisions/0065-caption-track-research.md) records remaining work.

The separate [bounded Parser source inventory](../api/caption-source-inventory.md) reports the observed raw extension chain and its relationship/byte status without importing caption semantics. It retains inactive MCE branches as raw-only, so it does not claim that every reported track is active.

Microsoft documents [WebVTT and SRT insertion for current PowerPoint versions](https://support.microsoft.com/en-us/powerpoint/add-closed-captions-or-subtitles-to-media-in-powerpoint). That product documentation is not evidence of how this particular sample plays or of support in other versions.

## SRT conversion and playback attempt

A copy of the two-track file received [a UTF-8 SRT file](../../tests/fixtures/caption-spanish-source.srt) on the second video. PowerPoint 16.104 showed Spanish (Spain) before and after save/reopen. The [saved sample](../../tests/fixtures/powerpoint-caption-srt.pptx) has three `text/vtt` parts and no SRT part: its new WebVTT track contains the Spanish text and corresponding 100–900 ms and 1000–1800 ms cue times. The first video's IDs, labels, languages and track contents remain unchanged. This is one plain SRT example, not proof that all SRT markup or encodings survive conversion. Node and Chromium produce the same unsupported-track findings and byte-identical no-op save without network requests.

For a playback attempt, a 12-second blue H.264/AAC MP4 with a 440 Hz tone was generated locally, embedded in the [playback sample](../../tests/fixtures/powerpoint-caption-playback.pptx), trimmed by 2 seconds at each end, and given [six source-relative cues](../../tests/fixtures/caption-playback-source.vtt). PowerPoint's slide show displayed blue video and an advancing media bar after setting the start to automatic. No subtitles were visible in the observed frames; attempts to select the caption track in the slideshow did not succeed. These observations do not establish the default selection or caption timing, and no sound was independently captured. The imported VTT still stores the original cue times and `st="2000" end="2000"` after save. Screenshots were inspected during the experiment but not retained as independent timing evidence.

## Unrelated text preservation

The [text-save regression](../../scripts/text-save-parity.test.mjs) constructs a mixed package by inserting a PPTKit-generated text object into the retained PowerPoint SRT-conversion sample; this combined package is synthetic. Three `text-runs-v1` saves change only that object's text. Every other part remains byte-identical, the slide differs only in the selected text, and the OPC relationship graph is unchanged. The independent research inspector finds the same three track IDs, labels, languages, relationships, VTT bytes and trim values after each round; invalid-header and missing-track injections verify that it detects those two faults. This is evidence for unrelated text preservation, not caption semantic import, editing, playback, or a native PowerPoint reopen of the mixed package.

To reproduce the input MP4, run `ffmpeg -f lavfi -i 'color=c=blue:s=640x360:r=15:d=12' -f lavfi -i 'sine=frequency=440:sample_rate=44100:duration=12' -c:v libx264 -pix_fmt yuv420p -c:a aac -shortest -movflags +faststart playback.mp4`, then build and run `node scripts/research/generate-caption-playback.mjs playback.mp4 base.pptx`. The retained sample additionally includes the PowerPoint-inserted track; regenerating it requires that manual step. In the later observation below, PowerPoint displayed the retained sample's start setting as “On Click”; the original experimental working copy displayed “Automatically”. Encoder versions may change MP4 bytes.

## Caption selection and trimmed playback observation

In a later PowerPoint for Mac 16.104 session, a copy of the retained playback sample initially showed **Off** selected in the media preview's CC menu. Selecting English (United States) displayed captions. At preview elapsed times 0.43, 2.40 and 4.47 seconds, the displayed cues were `TWO TO FOUR`, `FOUR TO SIX` and `SIX TO EIGHT`, respectively. These positions agree with adding the 2-second source trim to the displayed elapsed time. Selecting Off hid the displayed caption. After saving, closing and reopening the copy **in the same application session**, English remained selected. This does not determine whether the selection was saved in the document or retained as application state, nor establish the default on a fresh application session.

After setting the research copy's start option to Automatically, a slide show displayed `TWO TO FOUR`, then `FOUR TO SIX` and later `EIGHT TO TEN`. The [observation record](native-caption-preview-evidence.json) identifies the source and saved local copy and lists the measured preview positions. The [automated check](../../packages/pptx-parser/test/native-captions-research.test.mjs) verifies the source hash, stored trim, VTT contents and arithmetic consistency of the recorded positions; it does **not** reproduce or independently authenticate the UI observation. Screenshots were inspected but not retained. One sample does not establish cue-boundary precision, slideshow language switching, looping, a different producer, audible output or assistive-technology behavior; subtitle semantic import and playback remain unadmitted.

## Language switching on shared video instances

In the same PowerPoint 16.104 application session, a copy of the SRT-conversion sample presented English and `French test - French (France)` for the first video, and Spanish (Spain) for the second video. The first menu initially had English selected; the second initially showed Off. The prior experiment had selected English in the same application session, so neither initial state establishes a fresh-session default. In the first video's editing preview, selecting French showed `Première légende` at the reported elapsed time 0.45 seconds; switching to English and seeking showed `First caption` at 0.48 seconds. In the second video's preview, selecting Spanish showed `Primera frase` at 0.41 seconds. On returning to the first video, its menu showed Off; the observation does not identify whether selection is per-instance, player lifecycle or application state. The two objects share one MP4 but have separate track relationships.

The [observation record](native-caption-multitrack-evidence.json) binds these manual observations to the retained source hash. The automated research test checks the source track lists, trim values, cue text and time arithmetic, and the single packaged MP4; it does not reproduce the UI interaction. Screenshots were viewed but not retained. Slideshow language switching, precise cue boundaries, fresh-process defaults and selection persistence remain unverified.

## Loop and slideshow interruption observation

For a further PowerPoint 16.104 experiment, the longer trimmed-video copy received a second, [French WebVTT input](../../tests/fixtures/caption-loop-fr-FR.vtt), and its loop option was enabled. The retained [PowerPoint-saved fixture](../../tests/fixtures/powerpoint-caption-loop-multitrack.pptx) differs from that saved copy only in anonymized creator and last-modifier metadata. It contains both English and French tracks, 2-second start/end trims and an indefinite repeat setting.

In editing preview, after choosing French, `FR HUIT DIX` appeared at a reported 6.33 seconds; a later observation showed 3.20 seconds and `FR QUATRE SIX` without a seek. This is consistent with a rollover of the eight-second trimmed interval and continued French selection. A subsequent automatic slide show displayed `FR DEUX QUATRE`. While that slide show was active, PowerPoint unexpectedly exited and displayed its recovery/error-reporting dialog. The cause and reproducibility are unknown; the dialog was left for the user, and no report was submitted. This observation does not establish that captions, looping or an interaction caused the exit.

The [evidence record](native-caption-loop-evidence.json) captures the manual observations and fixture hash. The [automated check](../../packages/pptx-parser/test/native-captions-research.test.mjs) verifies the saved tracks, trim, repeat marker, recorded cue arithmetic and byte-identical no-op; it cannot authenticate or reproduce the UI observation or exit. Screenshots were viewed but not retained. Slideshow language switching, repeated loops, exact boundaries, recovery behavior and other environments remain unverified.

## LibreOfficeDev resave comparison

LibreOfficeDev 26.8.0.0.alpha0 headless PPTX conversion of the PowerPoint loop fixture removed the original video, both WebVTT tracks, their relationships, the repeat marker and the timing element from the resulting package. The slide's shape tree is empty. Three successive conversions with separate temporary application profiles showed the same structural result; the loss occurred on the first conversion. The [record](libreoffice-caption-roundtrip-evidence.json) identifies the source and the [separately retained first conversion](../../tests/fixtures/libreoffice-caption-roundtrip.pptx); its creator metadata already contained the anonymized research identity. The retained file came from a separate initial conversion using the default headless profile, while the recorded three-round run used isolated profiles.

Run `python3 scripts/research/probe-libreoffice-captions.py` with this LibreOfficeDev build installed to repeat the isolated conversion and package inventory. Output bytes and metadata timestamps may vary. The automated test checks the source and retained output hashes, structural markers, and PPTKit byte-identical no-op on that output; it does not rerun LibreOffice. These observations cover one development build and one source file; they do not establish subtitle playback, editing, behavior in other LibreOffice releases, or a native LibreOffice-authored caption format. PPTKit preserving the already stripped output cannot recover its missing content.
