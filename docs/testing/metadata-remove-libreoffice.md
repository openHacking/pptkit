# Metadata removal: LibreOfficeDev observation

A PPTKit-authored control contains title `Removal control`, subject `Subject 中文`, description `Description & control`, company `Company 中文` and revision 7. PPTKit's `metadata-remove-v13` removed subject, description and company in an edited copy. Independent ZIP/XML checks confirm that only the two metadata parts changed, and that their non-target bytes are identical.

LibreOfficeDev 26.8.0.0.alpha0 headlessly resaved both branches three times. The control retained the three values. In the edited branch, company remained absent; LibreOffice added empty subject and description elements on its first save and kept them through the third. Both branches retained title and revision, and LibreOffice replaced the application identifier. An empty property and a missing property are distinct; this sample therefore does not establish exact preservation of the deletions across applications.

The [evidence record](metadata-remove-libreoffice-evidence.json) binds eight actual files, inventories, application version and conversion logs. Run `python3 scripts/research/verify-metadata-remove-libreoffice.py` for independent ZIP/XML, relationship, content-type, hash and exact source-span checks; `python3 scripts/research/test_metadata_remove_evidence.py` verifies five corrupted evidence records and two rehashed corrupted packages are rejected. Local artifacts are under `.tmp/metadata-remove-libreoffice`; the experiment can be repeated with `python3 scripts/research/metadata-remove-libreoffice.py`.
