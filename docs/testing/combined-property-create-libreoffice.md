# Combined core and custom creation: LibreOfficeDev observation

A synthetic control was made from a hash-checked PPTKit presentation by removing the core-properties part and its root declarations; it also had no custom-properties part. PPTKit created both parts in one save, inserting title `Created 中文`, creator `Fixture Author`, a UTC creation date with `.123` seconds, and two custom properties (`Text` and integer `Count`). Independent ZIP comparison found only the two new parts and changes to root relationships and content types.

LibreOfficeDev 26.8.0.0.alpha0 headlessly resaved the control and edited file three times. The edited branch retained the title, creator and both named custom values, but removed the creation date's fractional seconds, converted `Count` from `i4` to `r8`, reassigned and reordered custom property IDs, and added `PresentationFormat` and `Slides`. The control gained an empty core properties part and those two application-generated custom properties. Results were stable in the inventoried fields through rounds two and three. This is a single synthetic sample and does not prove full fidelity.

An additional control rewrote only the two OPC declaration XML files with ElementTree, changing namespace-prefix and XML serialization while retaining the same expanded element and attribute structure. LibreOfficeDev reported it could not load either the control or edited prefix-reserialized file. The unmodified-prefix inputs above did load. A [follow-up isolation](opc-prefix-libreoffice.md) found that prefixing either declaration file alone caused this application to reject both sample branches, while removing the standalone declaration did not. This does not imply that prefixed XML is invalid.
