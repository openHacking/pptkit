# Layout rebind verification

This implements the bounded [review/atomic apply contract](../api/layout-rebind.md), not complete template/source reset support.

Ten focused [Core test groups](../../packages/core/test/layout-rebind.test.mjs) cover logical key/unique-role matching, deterministic ambiguity candidates, explicit role changes/detach, multi-page review cancellation, old geometry retention, all current foreground kinds through nested table/chart/image/shape/connector controls, old palette/font/script/background materialization, explicit false/zero and text actions, adopt/reset inheritance, long-text/shrink findings, inherited root reference maps, same-handle commits, ownership release/collision checks, allocator preservation, stale/invalid source drafts, input accessor rejection, forged reports, implicit/authored default no-ops and retained timing/notes/transitions. Plans also work on detached method-free authoring values.

The [public fixture](../../tests/fixtures/layout-rebind.mjs) has red/blue master domains and source/target/ambiguous/empty layouts. [Two public tests](../../scripts/layout-rebind-parity.test.mjs) compare complete plans/reports/IR/origins/Layout/SVG/warnings/PPTX across Node/ESM/global for review/adopt/preserve/reset with blocked network. Independent Chromium XML reads target layout/master, text and image placeholder indices, hidden/display flags, body frame geometry, effective native theme-font references, table fill and chart color. The reset case resumes target bold despite the old explicit false and preserves native theme slots. Source-only no-op stays byte-exact; adding/rebinding a new template remains source-edit unsupported and stales the old save plan.

Installed Node/strict NodeNext consumers exercise the new function, managed apply result and read-only value types without requiring methods on legacy documents. A [typed example](../examples/layout-rebind.ts) and [ADR0058](../architecture/decisions/0058-reviewed-layout-rebinding.md) document the ownership and failure model.

## Adversarial review

The checks target five failures: guessed ambiguous matches, partial multi-page/ID commits, stale or forged plans, old theme references leaking into the target theme under preserve mode, and accidental Parser write authority. Additional review found and fixed default-layout explicit-ID churn, guessed after-value previews for unresolved plans, stale invalid drafts being normalized before the freshness check, and a large spread operation after the identity commit. Slide-level inherited group-descendant references now block instead of reaching Layout's unresolved-reference fallback.

### Selective text reset (bounded coverage)

Core tests exercise selected Western font family and color reset on text and shape text, target theme references and origins, preservation of other preset and local values (including false, zero opacity and actions), multi-slide application and an untouched slide, repeated reset, and invalid/duplicate/sparse selectors. The public parity test compares Node, browser ESM and browser global authoring data, inheritance, layout, SVG and generated PPTX bytes. A changed named preset is checked through a fresh authoring snapshot to ensure unrelated properties remain live. The subsequent native control covers a bounded combination of these selectors; other fields and table cells remain outside this coverage.

### Run, paragraph and frame reset expansion

Focused tests individually exercise every supported run, paragraph and frame declaration, null font-slot and whole-script-map barriers, target origins, other local and preset properties, actions, zero/false values, stale multi-slide plans and shape text. Node/ESM/global parity covers combined run, paragraph and frame selectors through generated PPTX.

[Native evidence](style-reset-native-evidence.json) is limited to one three-page PowerPoint control: the selected page resets Western font, color, bold, paragraph alignment and frame wrap; the hidden control page retains local styles and the untouched page remains on its original layout. All three saved and reopened PPTX files passed independent XML checks, and the final reopened file was printed to a three-page PDF with the hidden page included. PDF extraction checks the target Courier bold/blue text against Arial/red controls; seven altered PPTX files were rejected. Only the final round was printed; no three-round visual equivalence or acceptance of other selectors is claimed. Script-map entries and margin sides are independently resettable in Core; script maps remain materialized and warned.

The exported control writes direct run, paragraph and frame declarations on the slide shape. It retains theme tokens for the selected font and color, but this evidence does not establish that subsequent native edits to the placeholder layout propagate the selected properties. The Core authoring inheritance contract must not be conflated with live PowerPoint layout inheritance; the latter remains open.

A separate native omission probe removed the selected page's explicit font slots, fill, bold, paragraph alignment and frame wrap from a copy of the fresh PPTX. PowerPoint printed that page as black Arial rather than the target blue Courier bold; the probe PPTX and PDF hashes are bound in the evidence. Simply dropping those declarations is therefore insufficient with the current layout serialization.

A second manually constructed probe added the target layout's run/paragraph defaults to `a:lstStyle/a:lvl1pPr`, while leaving the selected slide's five declarations omitted. PowerPoint printed blue Courier bold. Changing only those layout defaults to green Georgia regular changed the selected page to green Georgia while both local-style controls remained red Arial; the slide XML was byte-identical between the two probe packages. The printed text's vertical position differed from the fully materialized control, so this demonstrates a path for run-style inheritance rather than complete frame/paragraph or pixel equivalence. These probes do not modify the exporter.

### Opt-in native run inheritance

The exporter now supports an explicit `nativePlaceholderText: "inherit"` option for eligible Western font family, color and bold resets. [Native evidence](native-placeholder-text-evidence.json) binds a freshly generated input, three actual PowerPoint save/close/reopen rounds, first and final three-page PDFs and five corrupt ZIP controls. First/final page pixels and extracted text agree. A fresh generation reproduced the input PPTX byte-for-byte; warnings intentionally differ from the initially captured input because the shared-metrics warning was added after measuring the regression.

Compared with the previous materialized control, the opt-in shifted text vertically on both pages sharing the changed layout by approximately 0.96 points; the third page retained its position. Two paragraph-mark probes failed to remove this shift. For that reason the option emits a shared-metrics warning and the default remains materialized. This evidence covers a single combination and does not prove native UI layout edits or all fonts, paragraphs, frames or script maps. Earlier handmade-probe evidence describes the prior exporter and is historical after source changes.

A copy of the production-generated PPTX was independently edited only in the target layout's level-one defaults: green Georgia regular replaced blue Courier bold. All three slide XML parts stayed byte-identical. PowerPoint printed the selected page green Georgia and both controls red Arial. This is a package-level layout edit, not an interactive PowerPoint layout edit.

### Minimal native layout defaults

The exporter now emits only the properties needed by selected eligible runs, rather than all layout text defaults. In the named [color/bold control](native-minimal-color-bold-evidence.json), PowerPoint's materialized, first-open inherited and third-reopen output matched across all three pages in pixels, glyph traces, drawing commands and image records. A layout-only XML edit changed the selected page's color and bold while leaving the other two pages' slide XML and appearance intact. Five corrupted PPTX files were rejected. This is a bounded host/fixture result; the shared-metrics warning remains.

Independent probes show the position shift arises when a layout font default is added; adding only bold or color did not move the named local-style control. Setting an explicit Arial paragraph-mark font recovered its old position, but using the document theme font did not work when that theme was Courier New. The general font-metric fix therefore remains unimplemented. Previously recorded full-default native evidence is historical after this export change.

The current minimal-default font/color/bold production output has a separate [three-round native control](native-minimal-font-evidence.json).
