# PowerPoint text-runs-v1 interactive control

This named macOS PowerPoint 16.104 control advances IMP-09.2.1.1. It does not certify arbitrary source references, other owners, applications, versions or source structure edits. The original V1 source and PPTKit-edited candidate were copied from the [existing experiment](text-edit-save-evidence.json) only after their hashes matched that manifest; original research artifacts were not modified.

PowerPoint opened the candidate and displayed the selected and control text boxes. In the actual UI, text ` POWERPOINT UI 789` was appended to the selected box and saved. Three distinct Save As, close and exact-reopen rounds followed. In all four PowerPoint-saved packages the selected and control text, their IDs and geometry, notes text and named opaque extension were checked independently. The application's resave removed the orphan part that PPTKit's candidate had preserved. This is an observed application rewrite, not a PPTKit source-save loss.

The interactive-save and third-reopen PDFs have equal raster pixels, drawing and image records. Their raw text traces are **not** equal: segmentation changes and corresponding glyph origins differ by up to about 0.059 PDF points. Glyph identity, font, size and color match in the named sample. The untouched control's Unicode glyph positions and style remain equal in all captured PDFs. The requested font was Liberation Sans; PowerPoint's captured PDF uses ArialMT, so the result is not evidence of font-family fidelity.

The third reopened PowerPoint file was then imported using `text-runs-v1`; PPTKit changed the first existing run while leaving the UI-appended runs intact. Independent ZIP/XML comparison finds the same part set and only one changed slide payload, with exactly the selected text atom changed. This new PPTKit candidate opened in PowerPoint and underwent three further distinct Save As, close and exact-reopen rounds. Its first and final PDFs have identical pixels, complete text traces, drawing and image records. The prior orphan loss was already present in its input and was not restored.

The [independent oracle](../../scripts/research/oracles/native-v1-interactive.py) verifies source/candidate hashes, both isolated text changes, object identity/geometry, notes and control content, both PDF comparisons and six deliberately corrupted cases. Run it against the retained local directory recorded in [the evidence](native-v1-interactive-evidence.json). The [post-native PPTKit producer](../../scripts/prepare-native-v1-post-edit.mjs) reproduces the second candidate and report byte-for-byte from the retained third-round input; neither command simulates or repeats the PowerPoint UI actions. The [Parser consumer evidence](native-v1-interactive-parser-evidence.json) covers all ten source, candidate and native-saved files in Node, browser ESM and global, including thirty exact no-op saves; it does not certify broader source-reference safety.
