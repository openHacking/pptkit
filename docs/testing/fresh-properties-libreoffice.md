# Fresh custom properties: public authoring and LibreOfficeDev resaves

This experiment uses the public Core and PPTX Exporter APIs to create a one-slide presentation, then changes the same document and exports again. The first file contains an empty string, false, the int32 minimum, `1.25`, a UTC date, the exact decimal `9007199254740993.0001`, and a control string. The modified file removes the empty property and changes the other values, including the decimal to `9007199254740994.0001`. Separate fresh outputs distinguish `customProperties: []` (an empty custom part and relationship) from an omitted field (neither part nor relationship).

An independent Python ZIP/XML verifier checks fresh variant types, canonical values, sequential PIDs, format GUIDs, package relationship and content type. The [automated public-consumer test](../../scripts/custom-properties-roundtrip.test.mjs) reconstructs all four initial files and checks their hashes against the [record](fresh-properties-libreoffice-evidence.json).

LibreOfficeDev 26.8.0.0.alpha0 headlessly resaved the original and modified files separately three times. On the first resave, this sample's decimal property disappeared in both branches; integers became `r8`, booleans became `0`/`1`, date lexical text lost `.000`, IDs and order changed, and `PresentationFormat` and `Slides` were added. The original empty string remained, while its explicitly removed counterpart stayed absent. Subsequent resaves retained the first resave's property inventories without accumulating duplicate names. These observations apply only to this fixture and version; they do not establish PowerPoint or interactive authoring behavior.

The record includes process logs and hashes. Ten PPTX artifacts remain locally under `.tmp/fresh-properties-libreoffice`, not in the repository. `python3 scripts/research/verify-fresh-properties.py` independently checks them where retained; altered hashes, inventories, process statuses and duplicate records were rejected during this run. The record alone is not independent proof that the application ran.

To reproduce, run `pnpm run build:browser`, then `python3 scripts/research/probe-fresh-properties.py > evidence.json` with the recorded LibreOfficeDev build available as `soffice`, and pass the output file to the verifier. Different environments may produce different ZIP hashes or application behavior.
