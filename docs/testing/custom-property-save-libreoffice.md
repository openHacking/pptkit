# Source-preserved custom values: LibreOfficeDev headless observation

One PPTKit-authored presentation was used as the unchanged control. The opt-in source-preserving profile changed five existing custom values: Unicode text, boolean, int32 integer, real and UTC date. Independent ZIP comparison found that only `docProps/custom.xml` changed before application conversion. LibreOfficeDev 26.8.0.0.alpha0 then headlessly resaved the control and edited files separately for three rounds each; Python ZIP/XML inventories are recorded in the [evidence manifest](custom-property-save-libreoffice-evidence.json).

In this sample, all five edited values and the corresponding control values remained semantically recognizable through three resaves. On the first resave both paths reordered and renumbered properties, converted `i4` integers to `r8`, changed boolean spellings to `0`/`1`, removed `.000` from the dates, and added `PresentationFormat` and `Slides`. The next two resaves retained the same observed property list. These are application-induced changes, not preservation guarantees. The experiment does not inspect native UI, PowerPoint behavior, repair prompts, visual fidelity, arbitrary precision or other files and versions.

On the machine retaining `.tmp` artifacts, `python3 scripts/research/verify-custom-property-save-libreoffice.py` verifies runner and reader hashes, eight PPTX hashes, independent inventories, paired round order and the initial source-part difference. The runner `python3 scripts/research/custom-property-save-libreoffice.py` creates a new manifest using currently built packages and an earlier retained authored sample; the manifest does not pin every build dependency. Separately, [portable producer fixtures and tests](../../packages/pptx-parser/test/custom-properties-producer.test.mjs) confirm that actual LibreOfficeDev-resaved files can be rebound and edited while retaining other parts.
