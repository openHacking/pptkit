# PowerPoint audio volume observations

PowerPoint for Mac 16.104 changed the existing generated single-audio object-click file from its high setting to low, then medium, then mute, saving each to a separate file. The retained [low](../../tests/fixtures/powerpoint-audio-volume-low.pptx), [medium](../../tests/fixtures/powerpoint-audio-volume-medium.pptx), and [mute](../../tests/fixtures/powerpoint-audio-volume-mute.pptx) copies anonymize the last-modifier field. The audio file was not altered. Low produced `vol="20000"`, medium omitted both `vol` and `mute`, and mute produced `mute="1"` with no `vol`. The pre-existing high sample used `vol="80000"`. The [OOXML common media node documentation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.commonmedianode?view=openxml-3.0.1) describes volume and mute as separate attributes.

The [generated four-object sample](../../tests/fixtures/pptkit-audio-volume.pptx), reproducible with `node scripts/research/generate-audio-volume.mjs <output.pptx>`, shares one audio asset across four objects with low, medium, high and mute settings. It opened without a visible repair prompt in the same PowerPoint version; the Playback > Volume menu showed the corresponding setting on each object. This is a menu observation, not a measurement of acoustic output or proof of slideshow playback, repeat behavior, other PowerPoint versions, or other applications.

The independent [XML verifier](../../scripts/research/verify-audio-volume.py) checks each audio node's target and volume/mute attributes. Exporter tests compare the native samples, mixed video, both audio start modes, shared assets, invalid inputs and default byte compatibility. Source import does not map volume settings.
