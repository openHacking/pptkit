# Native table cell property repair

Advanced master verification exposed two existing exporter errors: border nodes followed the cell fill, so PowerPoint dropped them and rendered default white table-style lines; cell insets/vertical anchor were written into text body properties, so PowerPoint used its own cell defaults. `tableCellXml` now writes borders before fill and places `marL`, `marR`, `marT`, `marB` and `anchor` on `a:tcPr`, with an empty `a:bodyPr`. The [Microsoft cell property reference](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.tablecellproperties?view=openxml-3.0.1) identifies cell margins/anchor; its linked ISO schema and [Microsoft OOXML Primer](https://download.microsoft.com/download/e/1/4/e14fb96f-83b8-4a2a-84db-7fa8acbe061a/Office%20Open%20XML%20Part%203%20-%20Primer.pdf) specify border-before-fill ordering.

No Core/IR/Layout/Parser contract or new option is introduced. Fresh native table bytes and appearance intentionally change. Parser already reads cell properties with priority and retains its older body-property fallback. Source no-op remains byte-exact. Text/shape frames continue to use their own body properties.

[Focused exporter coverage](../../packages/pptx-exporter/test/table-cell-properties.test.mjs) exercises 27 combinations of slide/layout/master ownership, three alignments and none/direct/theme-alpha fills, including nested groups, merged anchors/continuations, zero/asymmetric margins and visible borders. [Public table origins](../../scripts/table-origins-parity.test.mjs) reads actual `tcPr` attributes in Chromium and compares Node/ESM/global complete IR/origins/Layout/SVG/PPTX. The existing [table style DOM check](../../scripts/table-style-parity.test.mjs) now selects a direct fill child, preventing a nested border paint from being misidentified as the cell fill.
