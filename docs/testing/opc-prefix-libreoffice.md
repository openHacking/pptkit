# OPC declaration prefixes: LibreOfficeDev headless isolation

Using the two hash-checked inputs from the [combined property-creation experiment](combined-property-create-libreoffice.md), this experiment varies only OPC declaration serialization. It compares the original declarations with four variants: prefixes on the relationship root and children, prefixes on the content-types root and children, both sets of prefixes, and removal of the XML declaration's `standalone="yes"` attribute. Expanded element names, attributes, text and child structure were independently compared. All other ZIP entry payloads were unchanged.

LibreOfficeDev 26.8.0.0.alpha0 headlessly loaded and resaved both baseline inputs and both standalone-attribute variants. It reported that the source could not be loaded for each of the three prefix variants in both branches. This isolates a reproducible application limitation in these synthetic files; it does not establish that prefix use is invalid OPC or that all LibreOffice versions behave this way. PPTKit's preservation save retains the source declaration encoding and prefixes. [Parser tests](../../packages/pptx-parser/test/core-property-create.test.mjs) confirm that combined creation retains pre-existing prefixes and reimports the candidate; LibreOfficeDev has not been tested on that saved candidate.

The [record](opc-prefix-libreoffice-evidence.json) contains hashes, conversion logs and outputs. `python3 scripts/research/verify-opc-prefix-libreoffice.py` independently checks exact input transformations and retained outputs; `python3 scripts/research/opc-prefix-libreoffice.py` reproduces the experiment with the recorded local dependencies. Local artifacts are under `.tmp`. PowerPoint and interactive behavior remain unverified.
