# Scatter chart native research

This is an independent research fixture for scatter-chart work; it is not itself a PPTKit-authored sample. The source was produced by `scripts/prepare-native-scatter-research.py` using python-pptx, with only each chart's explicit blank-display scalar set afterwards. It contains four slides with fixed -10 to 10 numeric X and Y axes, two series whose X coordinates differ, and one missing Y value. PowerPoint 16.104 opened the source, printed it to PDF, saved it under a new name, and reopened that saved file once.

| Sample | Missing red Y | Red line segments | Red markers |
| --- | --- | ---: | ---: |
| markers, gap | omitted | 0 | 3 |
| line, gap | omitted and line split | 1 | 3 |
| line, zero | plotted at zero | 3 | 4 |
| line, span | omitted and surrounding points connected | 2 | 3 |

The other series contains four points and three line segments in each line sample. The verifier checks numeric caches and workbook cells in source and saved packages, fits an affine transform from the specified input pairs to first-print marker centers, and checks both the residual and the line endpoint-to-marker distances. The recorded maximum marker residual is approximately 0.088 PDF points; the maximum endpoint difference is approximately 0.169 PDF points. This fit is self-calibrated from native markers: it checks linear placement and correspondence, not independently measured native plot-box bounds. The [evidence record](chart-scatter-research-powerpoint-evidence.json) binds the retained artifacts, verifier and captures by hashes.

`packages/core/src/chart/scatter-data.ts` and `packages/layout/src/chart/scatter-geometry.ts` are internal data and geometry building blocks; tests compare its points and segments with these observations. Internal scatter workbook and series-XML builders generate one X/Y column pair per series, independent formulas, and paired caches; they are now used by fresh public export. A [hybrid native observation](chart-scatter-hybrid-powerpoint-evidence.json) substitutes these builders into the independent chart shell: PowerPoint opened, printed, saved and reopened four samples, and the first-print marker boxes and line endpoints matched the native control exactly. The cache/formula/workbook values were checked in the source and saved files. This does not validate PPTKit-generated scatter chart shells or interactive editing. Public authoring now supports independent X/Y data, two numeric axes and fresh XLSX export. [PPTKit-authored native samples](chart-scatter-authored-powerpoint-evidence.json) have one save/reopen and bounded first-print comparison. Bounded scatter content projection and three fresh import/export rounds are tested; dense X/Y preservation bindings have three programmatic save/reopen rounds and [one native PowerPoint save/reopen](chart-scatter-coordinate-save-powerpoint-evidence.json); native interactive workbook editing remains unfinished. A [second native observation](chart-scatter-missing-x-powerpoint-evidence.json) tested one missing X and an unsorted second series. For this sample, gap omits and splits the missing point, zero plots X=0, and span omits it while connecting adjacent points; the unsorted series connects in original series order. Both-coordinates-blank, other missing-X positions, repeated X, automatic axes, other producers, interactive edits and reopened PDF remain unverified. The independently generated native fixtures with signed axis IDs, and PPTKit-authored fixtures before and after a PowerPoint save, project their X/Y coordinates. Signed and unsigned axis IDs are matched by their numeric value without two-complement reinterpretation; broader producer compatibility remains unverified. No-op save retains original bytes.

Local verification, when the retained `.tmp/native-scatter-research/powerpoint-grywvvg1` artifacts and PyMuPDF are present:

```sh
python3 scripts/research/verify-scatter-powerpoint.py
node --test scripts/chart-scatter-research-evidence.test.mjs

```

The public implementation uses an explicit per-series X/Y contract and two value axes; category strings and a single shared category array cannot faithfully represent these samples. The internal data contract supports different point counts by series, including empty paired arrays; a given series retains X/Y correspondence and point order. Empty native series have not yet been verified. Markers and line segments must be modeled separately because the native `scatterStyle` alone does not determine whether a series' line is visible: this source uses `lineMarker` even for its marker-only sample, whose series line has no fill. Fresh workbook formulas and caches identify each series' own X and Y data ranges. Future source numeric editing must bind each axis value to its own cache point and workbook cell under the existing conflict and transaction guards. Source variants whose X/Y blank semantics or styles lack a truthful Core representation should remain source-only. The internal geometry treats both coordinates blank under the same policy, but native behavior for that combination is not yet established.
