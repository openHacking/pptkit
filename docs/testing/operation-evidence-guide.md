# Operation evidence catalog

[The version 1 catalog](operation-evidence.json) records specific object, owner, family, variant, operation, producer, application/version, profile and fixture combinations. [The generated table](operation-evidence.md) is a view of those records, not a second task checklist or a blanket compatibility claim. The records cover the named V1/V2/V3 text-save candidates, PowerPoint interactive/edit-after-native controls, an interleaved LibreOffice table control, local Node no-op file publication, LibreOfficeDev Fade/Push/Wipe resaves, a timing inventory and partial manual PowerPoint observations of the four original and edited timing specimens. Those observations have no retained video and are not effect admission. Native application changes are recorded separately from PPTKit candidate behavior. Version `unrecorded` means the original evidence did not identify the version; it is not a wildcard.

`capability` describes the observed operation (`editable`, `preserved`, `fallback`, `unsupported` or `unknown`); `status` independently describes the evidence (`planned`, `untested`, `pass`, `fail` or `partial`). An absent combination is untested. Records are not inherited across applications, versions, profiles, fixtures or operations. A passing source inspection does not imply native playback or interactive editing.

Each executed record names a procedure, result, limitations and at least one repository-local JSON evidence manifest. The validator checks the manifest's SHA-256, explicitly selected scalar assertions, and the fixture SHA-256 stored in that manifest. Many earlier fixtures are retained local research artifacts rather than distributed repository files: **the default catalog check verifies the recorded digest against the manifest, not the fixture bytes themselves**. Evidence hashes detect later changes to the manifests; rerunning a producer or an experiment is separate work. Pending records use a known fixture digest but do not claim that their pending operation was run.

Three [connector interaction records](native-connector-interactions-evidence.json) additionally reference retained repository fixtures for the named straight move, elbow reroute and rotated target. Their dedicated independent ZIP/XML verifiers check both source and output fixture hashes and geometry. The catalog still checks only the recorded manifest assertions by default; it does not itself run those verifiers or authenticate the manual interaction.

Run `node scripts/operation-evidence-cli.mjs --verify-local-fixtures` when the retained artifacts are available to recompute every distinct source hash; missing, changed or outside-repository files fail that opt-in check. The retained `.tmp` paths are environment-specific and not part of the distributed repository. Run `node scripts/operation-evidence-cli.mjs --write` after intentionally updating the catalog or linked evidence. Run `node scripts/operation-evidence-cli.mjs` to validate and detect a stale generated table; `pnpm lint` includes this check. `node --test scripts/operation-evidence.test.mjs` covers unknown schema/enums, duplicate keys, fabricated pending evidence, missing files, path and symlink escapes, changed digests, missing or false claims, fixture-hash mismatches and deterministic rendering. `pnpm test` includes these tests. These checks validate the catalog's structure and selected manifest fields; they cannot prove that the historical experiment happened, make unavailable fixture bytes portable, or certify a result beyond the manifest's scope.

The [mixed text-save regression](../../scripts/text-save-parity.test.mjs) is linked to a [distributed synthetic fixture and evidence manifest](mixed-text-attribution-evidence.json). It executes three actual source saves/reopens, independently checks every unchanged ZIP payload and the exact permitted slide edit, and compares OPC changes. An unsupported chart edit blocks the mixed plan; restoring it permits retry. Separate post-save mutations damage an image resource, an image relationship and a slide link target, each detected at its source location. These injections test the verifier; they are not attributed to a native application. The catalog test checks the fixture hash and CI registration, while `test:import` runs the actual regression. This advances IMP-10.1.1.3 and the mixed-sample work in IMP-10.4.1/.4.2; the sample does not include the full required object matrix.

The retained [PowerPoint notes before/after pair](corpus-notes-edit-powerpoint-evidence.json) and [subsequent PPTKit attribution](native-notes-attribution-evidence.json) have separate matrix rows and source hashes. The [registered regression](../../scripts/text-owner-save-parity.test.mjs) runs the independent Python native-package verifier, compares all native input/output payloads, and records four changed parts: app/core properties, the edited notes part, and view properties. It then starts from the native output and performs three PPTKit notes edits/reopens; each changes only the intended notes part. Unsupported formatting blocks and can be restored before retry. The native UI result remains the historical manual observation, not a new application run; differences in other native saves are not inferred from this pair.

The [extended mixed fixture](mixed-smartart-timing-evidence.json) adds synthetic SmartArt data/layout/colors/style/cache and a whole-object timing target to the earlier mixed text/chart/table/notes/shared-image package. Its registered regression checks component location, source graph, timing inventory, byte-level payloads and OPC relationship closure through three text saves. A separate character-range timing variant blocks the referenced text edit, and restoring it permits a same-slide unrelated edit. The fixture is generated reproducibly from the retained base and its digest is checked. Synthetic components do not establish native SmartArt editability, playback, comments or media coverage.

The [media and comments mixed fixture](mixed-media-comments-evidence.json) adds an embedded synthetic PCM WAV, poster relationship, and legacy slide-comment/author parts to the SmartArt/timing deck. The [independent Python verifier](../../scripts/research/verify-mixed-media-comments.py) checks the WAV header/samples, poster, content types, source relationships and comment/author pairing, with seven corrupt controls. Three unrelated PPTKit text saves preserve all non-slide payloads, relationship closure and the unchanged slide XML outside the chosen text; a concurrent geometry edit to the projected audio picture is blocked under the text-only profile. The source patterns follow Microsoft's [audio-file](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.audiofromfile) and [legacy comment](https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-comments) descriptions. This is a preservation control, not schema certification, media playback, comment editing or a native application observation.

A separate [picture replacement observation](mixed-advanced-picture-evidence.json) uses that same retained mixed source under `replace-v1`. Three successive GIF/PNG/GIF retargets add one media part and relationship each, while preserving every other existing payload and the original shared picture used by the audio poster and another slide. SmartArt and timing inventories, relationship closure, and the independent WAV/comment verifier remain consistent; the first round also matches Node, browser ESM and global output. A simultaneous text change is blocked and the picture edit can be retried after restoration. This is a synthetic source-save result; it does not establish native picture interaction, media playback or comment editing.
