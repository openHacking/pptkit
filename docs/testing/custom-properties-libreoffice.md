# Custom properties: LibreOfficeDev headless observation

One independently constructed PPTX custom-properties part contains five named properties: Unicode text, false boolean, signed 32-bit minimum integer, finite double and UTC file time. The source is based on a hash-checked PPTKit-generated seed; only the package relationship, content-type declaration and new custom part are added. Python ZIP/XML inventory records names, format IDs, numeric IDs, variant types and XML-decoded values before and after each conversion. LibreOfficeDev 26.8.0.0.alpha0 independently resaved the file three times with the headless Impress Office Open XML filter. The [evidence manifest](custom-properties-libreoffice-evidence.json) records the exact version, hashes, inventories and logs.

After the first conversion, the text, false value, numeric values and UTC timestamp in this fixture remained semantically recognizable, but several source details changed: `false` became `0`, the `i4` integer became `r8`, property order and numeric IDs changed, and two additional named properties (`PresentationFormat` and `Slides`) appeared. The subsequent two resaves retained that observed property list without accumulating further entries. This means a model must not assume that an application's resave preserves property IDs, original variant type or lexical spelling. The sample does not prove general numeric precision, timezone behavior, other variants or other producer versions.

The earlier trial that rewrote package relationship and content-type XML with namespace prefixes failed to load in this LibreOfficeDev instance; its retained file is not part of the successful evidence. The successful fixture preserves those source XML encodings except for the added elements. The failure does not establish which serialization detail caused rejection.

Run `python3 scripts/research/verify-custom-properties-libreoffice.py` on the machine retaining the `.tmp` artifacts to check runner and artifact hashes and recompute the recorded inventories. `python3 scripts/research/custom-properties-libreoffice.py` runs a new experiment using the retained seed and replaces the manifest. The artifacts under `.tmp` are local, not portable fixtures. This headless observation is not PowerPoint, a native metadata UI test, or evidence that PPTKit can create or edit custom properties.

The source and three resaved PPTX files are also retained as [portable parser fixtures](../../packages/pptx-parser/test/fixtures/custom-properties-libreoffice/provenance.json). The [producer test](../../packages/pptx-parser/test/custom-properties-producer.test.mjs) verifies each fixture hash, independently expected type/value/ID inventory, both structure and content import findings, and byte-identical no-op saving.
