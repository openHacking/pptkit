# PowerPoint audio start timing observation

PowerPoint for Mac 16.104 opened the [mixed-media baseline](../../tests/fixtures/powerpoint-mixed-av.pptx), containing two videos and two one-second PCM audio objects. The second audio object (shape ID 5) originally used “In Click Sequence.” Its Playback menu was changed to “Automatically” and saved as the [automatic sample](../../tests/fixtures/powerpoint-audio-start-auto.pptx); that sample was then changed to “When Clicked On” and saved as the [object-click sample](../../tests/fixtures/powerpoint-audio-start-object-click.pptx). Each resulting file was closed and reopened in the same PowerPoint version; the selected audio object's Playback menu still showed the chosen setting. The retained copies replace the last-modifier field with `PPTKit fixture`; they are not byte-identical to the original saves.

The [independent ZIP/XML verifier](../../scripts/research/verify-media-start.py) checks media hashes and direct relationships, timing ID uniqueness, all four play targets, the two video pause targets, and the structure of the changed audio effect. The [negative controls](../../scripts/research/test_media_start.py) alter the effect type, delay, click target, timing ID and media bytes. These checks run in `pnpm test:timing-research`.

In the baseline, shape 5 is a `clickEffect` in a separate main-sequence group. In the automatic sample, it becomes an `afterEffect` in the same main-sequence group as shape 4, with an enclosing 1000 ms delay. Shape 4's command duration is also 1000 ms. This supports the inference that the observed automatic setting is sequenced relative to the previous effect; it does not prove that all automatic media starts at slide entry. In the object-click sample, shape 5's play command moves to an `interactiveSeq` triggered by `onClick` on shape 5. The other three play targets remain in the main sequence, and the two videos retain separate pause commands.

The [generated mixed sample](../../tests/fixtures/pptkit-audio-start-object-click.pptx), reproducible with `node scripts/research/generate-object-click-media.mjs <output.pptx>`, is checked against the same independent object-click structural observations. PowerPoint for Mac 16.104 opened it without a visible repair prompt and displayed “When Clicked On” for its second audio object and “In Click Sequence” for the first. A slideshow was opened and the second object clicked, but no audio output was independently captured. An initial single-audio generated file incorrectly included an empty main sequence and PowerPoint offered to repair it. A separate [native single-audio sample](../../tests/fixtures/powerpoint-single-audio-object-click.pptx), with its last-modifier anonymized, contains no main sequence; after the writer was corrected to omit it, PowerPoint opened the [generated single-audio file](../../tests/fixtures/pptkit-single-audio-object-click.pptx) without a visible repair prompt and showed “When Clicked On.” The single sample uses the same generator with `--single`. Automated tests compare both single and mixed structures, multiple objects, interleaved video, unique timing IDs, shared media, no-op import, and Node/Chromium output parity. The observed object-click chain and supported complete audio-only and bounded mixed audio/video main sequences are projected on content import when targets and durations are unambiguous.

These are named single-audio and mixed-slide observations. Actual slideshow timing, audible playback, re-entry, more than two automatic objects, video start settings and other PowerPoint versions remain unverified. Trimming and animation-triggered playback are not covered by these samples. The implemented object-click authoring mode does not grant source-save permission.

PowerPoint for Mac 16.104 changed a [single-object sample](../../tests/fixtures/pptkit-single-audio-object-click.pptx) to automatic and saved the [single automatic sample](../../tests/fixtures/powerpoint-single-audio-auto.pptx). Duplicating that object yielded the [two-automatic sample](../../tests/fixtures/powerpoint-two-audio-auto.pptx); both retained copies anonymize the last-modifier field. The single object's group listens for `onBegin` of the main sequence, with an `afterEffect`. In the two-object sample, the second `afterEffect` shares that group and has a 1000 ms delay, the first object's duration. This is evidence of sequential rather than simultaneous automatic effects.

The [generated single](../../tests/fixtures/pptkit-single-audio-auto.pptx) and [two-object](../../tests/fixtures/pptkit-two-audio-auto.pptx) samples are reproducible with `node scripts/research/generate-audio-auto.mjs <output.pptx>` and the `--single` option. PowerPoint opened the generated two-object sample without a visible repair prompt and showed “Automatically” for both. The [independent verifier](../../scripts/research/verify-audio-auto.py) checks main sequence groups, delays, effect kinds, targets and unique timing IDs in native and generated samples. Tests cover trimmed duration, other media and object clicks, and reject automatic audio following a looping main-sequence audio. This does not establish audible playback, pause/replay semantics, or compatibility with other applications.

Content projection recognizes this exact independent object-click chain for native and generated samples, including shared audio and mapped trims. Tests reject changed events, command targets, duplicate timing IDs, conflicting commands and duration mismatches; unchanged source no-op saves remain byte-identical. A separate all-or-nothing interpretation covers supported complete audio-only main sequences; source-bound timing edits remain unsupported.

The importer recognizes complete audio-only main sequences in the observed shape, including native single/two automatic samples and generated click/automatic groups. It validates source order, projected targets, unique timing IDs, cumulative delays, trimmed durations and known loop states before mapping any main effect. Unknown effects and main sequences containing unprojected videos remain unmapped. Automated negative controls alter triggers, delays, durations, targets and IDs; three fresh export/import rounds preserve the mapped modes.


## PowerPoint video automatic start after an existing sequence

In PowerPoint for Mac 16.104, the first video (shape 2) in the [mixed audio-automatic sample](../../tests/fixtures/powerpoint-audio-start-auto.pptx) was changed from “In Click Sequence” to “Automatically”. The [saved copy](../../tests/fixtures/powerpoint-video-start-auto.pptx) was closed and reopened, and the video Playback menu still showed “Automatically”. Its `lastModifiedBy` value was replaced with `PPTKit fixture` after that observation, so the retained file is not byte-identical to the native save. No slideshow playback or sound was independently measured.

The [independent ZIP/XML check](../../scripts/research/verify-media-start.py) verifies source media hashes, object identities, unique timing IDs, both video pause targets, and every main effect's target, type, delay, duration, group and order. The object order is video 2, video 3, audio 4, audio 5. Before the edit, main play order was 2, 3, 4, 5. After the edit, it was 3, 4, 5, 2: video 2 was appended as an `afterEffect` with a 2000 ms delay in the group containing audio 4 and 5. Thus this one menu choice does not establish immediate slide-entry playback; it also shows that source effect order need not match drawing order. Five altered controls check rejection of a changed effect, delay, pause, ID and video bytes. The Parser currently leaves this reordered sequence unmapped and preserves the source bytes in no-op mode. Fresh export, other videos, edits, applications and actual playback remain unverified.
