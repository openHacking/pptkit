# PowerPoint video trim observation

In PowerPoint for Mac 16.104, the first video in the [two-video automatic sample](../../tests/fixtures/pptkit-video-auto.pptx) was trimmed to 0.150–1.950 seconds, and saved as the [native sample](../../tests/fixtures/powerpoint-video-trim.pptx). The dialog showed a 1.800-second retained duration after saving. Its full MP4 remains shared with the second video; the first video's Office media extension contains `st="150" end="50"`, its command duration is 1800 ms, and the second automatic effect's delay is 1800 ms. PowerPoint replaced the trimmed video's direct relationship with external `NULL` and retained an embedded companion. The retained copy anonymizes the last-modifier field. The dialog was reopened during the same session; closing and reopening the file was not separately observed.

The [generated sample](../../tests/fixtures/pptkit-video-trim.pptx), reproducible with `node scripts/research/generate-video-trim.mjs <output.pptx>`, retains internal video and companion relations. PowerPoint opened it without a visible repair prompt and its trim dialog displayed the same 0.150–1.950 seconds and 1.800-second duration. The [independent verifier](../../scripts/research/verify-video-trim.py) checks source-relative trims and play durations; the sequence verifier also checks following automatic delay. Tests cover valid and invalid boundaries, shared assets, explicit resolver behavior, no-op and three fresh export/import rounds. This is one dialog/structure observation, not proof of actual playback, edit lists, other applications, looping or source-preserving edits.
