# PowerPoint shape and notes character-save control

This named PowerPoint 16.104 control advances IMP-09.2.1.2 for one mixed two-slide source. The original source and V2 candidate were copied only after their hashes matched the [existing headless evidence](text-owner-save-evidence.json). The original files were not modified. The sample contains shape text with an internal slide link, two notes bodies with an external link in the first, a nested shape, table, chart with an embedded workbook, a shared image and injected opaque extensions.

In PowerPoint's UI, text was appended separately to the first slide's shape and first notes paragraph; an actual save and three distinct Save As, close and exact-reopen rounds followed. Source XML checks confirm the two notes remain related to their respective slides, the link relationships remain on the intended runs and point to the expected targets, and the control text, selected-shape geometry, chart cached values, embedded workbook bytes and shared image bytes remain present. Links were inspected, not activated. PowerPoint renamed image/workbook parts and removed the orphan that the PPTKit candidate retained; both injected named extensions remained. This is an application rewrite observation, not a general unknown-content guarantee.

The two interactive and third-reopen slide PDFs have identical pixels, but the first page has unequal raw text and drawing records; corresponding glyph origins differ by up to approximately 0.0062 PDF points. The second page's complete records match. Notes printing yields **three pages both before and after** the UI edits, with the first notes paragraph, its control paragraph and second-slide notes separately visible. On the first notes page, interactive and third-reopen pixels differ and corresponding glyph origins differ by about 0.1234 points; the other two notes pages' complete records match. The PDF displays the decomposed source `é` as `é`, while source XML retains the decomposed text. This observation does not prove an intended one-slide-per-notes-page layout or general notes presentation fidelity.

PPTKit then imported the third native copy with `text-runs-v2` and changed the first run of the existing shape and notes while retaining the UI-added runs. Independent ZIP/XML comparison finds the same part set and exactly the two selected text atoms changed in their slide and notes payloads; every other payload remains byte-identical. PowerPoint opened this new candidate and completed three further distinct Save As, close and exact-reopen rounds. The initial and final candidate PDFs have equal pixels, full text traces, drawings and image records on both slide pages and all three notes print pages. The already removed orphan was not restored.

The [independent oracle](../../scripts/research/oracles/native-v2-interactive.py) checks source/candidate hashes, both text changes, reciprocal notes relationships, selected geometry, links, image/workbook bytes, chart cache, control text, detailed PDF results and twelve corrupted cases. The [producer](../../scripts/prepare-native-v2-post-edit.mjs) reproduces the second PPTKit candidate and report byte-for-byte from the retained native input. Run the oracle against the directory in [the evidence manifest](native-v2-interactive-evidence.json); neither command repeats or simulates the PowerPoint UI actions. [Parser consumer evidence](native-v2-interactive-parser-evidence.json) checks ten source, candidate and native-saved files in Node, browser ESM and global, including thirty exact no-op saves. Broader owner/reference safety, native editing in other environments, notes layout and arbitrary implicit dependencies remain open.
