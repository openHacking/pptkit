# LibreOffice metafile rasterization probe

On macOS 26.5 (25F71), LibreOfficeDev 26.8.0.0.alpha0 (2c87e51eeaa2b413ff4ae097b2705eea1995d8e5) and Pillow 12.1.1, the optional [probe](../../scripts/research/metafile-libreoffice-probe.mjs) generated an asymmetric 160 × 90 SVG containing a red rectangle and a blue circle. LibreOffice converted it separately to EMF and WMF, then converted each metafile to PNG with its default headless Draw filters. PPTKit exported each PNG through the explicit vector rasterization resolver; the probe checked that the PNG media bytes were exact and that the vector-loss warning was present.

Both conversions produced a 794 × 1123 PNG. Thresholded red pixels occupied x=327–374, y=526–554; blue pixels occupied x=420–457, y=561–598. Thus these successful conversions included the surrounding page and did not preserve the source canvas as the output image extent. Placing the result in the source's frame without compensating for the page produces incorrect geometry. This observation concerns these filters and this generated sample; it does not establish a general defect in metafile rendering or evaluate a properly bounded conversion. No PowerPoint rendering, native editability, arbitrary metafile compatibility, color management, fonts, or preservation-aware editing was tested.

The same probe embeds each generated metafile in a synthetic presentation, imports the content projection, checks the unsupported-image finding and retained ordinary shape, and verifies byte-identical no-op output and blocked rebuild. Retained fixture copies allow the [parser regression test](../../packages/pptx-parser/test/content-images.test.mjs) to repeat those checks in both OOXML dialects, including two references to the same source part. Their SHA-256 digests are `9d7939d8772cbc60d56636206b6d43638768a06d84501926d01f0f748b422a90` (EMF) and `4547868938560a75a8c8ae6dea6d9928f8bbc0ccc931502f1cf9ae99a08f239b` (WMF). This establishes exact original-byte no-op preservation only; editing the source picture or rebuilding it remains unsupported.

Run after building Core, the parser and the exporter with `node scripts/research/metafile-libreoffice-probe.mjs`; it requires `soffice` on PATH and Python Pillow, creates isolated temporary files, and removes them on exit. The program reports the actual version and pixel bounds rather than asserting fixed output dimensions across LibreOffice releases.
