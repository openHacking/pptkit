# Explicit placeholder index verification

The [index contract](../architecture/decisions/0059-explicit-placeholder-indices.md) adds authored numeric identities without deriving them from traversal positions. The [named fixture](../../tests/fixtures/placeholder-index.mjs) combines source/target layouts, three body candidates, explicit zero/max/title indices, a colliding implicit subtitle, text/picture bindings, two themes, three pages and an ordinary unbound object.

Seven [Core test groups](../../packages/core/test/placeholder-index.test.mjs) check immutable capture/IR omission, invalid and duplicate indices across roles, exact diagnostic locations, key/index/type precedence, same-index role conflicts, explicit decisions/detach, cancellation, reordering, unchanged IDs/handles, failed definition rollback, stale plans and runtime key/kind admission. Two [Exporter tests](../../packages/pptx-exporter/test/placeholder-index.test.mjs) read generated payloads to check matching prompt/local indices, zero/max, reordered layouts, implicit-number omission from Core, dense reserved/implicit allocation and invalid-definition rejection.

The [public rebind suite](../../scripts/layout-rebind-parity.test.mjs) adds adopt/preserve/reset Node/ESM/global comparisons for complete plans/IR/origins/Layout/SVG/warnings/PPTX and Parser reports. Independent Chromium DOM checks the actual native index map and text/picture bindings; source-only saves stay byte-exact. Installed Node and strict NodeNext consumers exercise the optional numeric field and `method: index`.

Actual PowerPoint 16.104 (25121423) zero/max-index opening, before/after printing and three save/close/exact-reopen/three-page print rounds are independently accepted in [native evidence](placeholder-index-native-evidence.json). The saved files omit the default zero `idx` attribute and retain the maximum index. Source/native prompt maps, local text/picture bindings, collision-free implicit numbering, owning layout/master/theme, EMU frames, strings, image payload/links, notes backlinks and hidden-page flags are checked against manual fixture expectations. Preserve-page used glyph programs/metrics/positions stay exact; only the new master accent changes. The unselected page keeps exact raster/drawings/images, with glyph-subset renumbering checked through actual used glyph programs. Four image-palette pixel probes check physical picture visibility on every page. Every reopened PDF record and package part stays exact after first save except validated clocks/TotalTime. The six-panel native contact sheet was viewed and is separately hash-bound.

Twenty-three actual corrupt ZIPs reject body-to-decoy/picture-to-implicit binding, omitted max index, duplicate/colliding prompts, overflow/negative/fractional indices, changed role, unselected subtitle renumbering, wrong owners/theme/fonts, lost picture/content, notes backlinks, EMU geometry, image bytes, object ID collision, wrong embed, page size and missing target prompt. Four actual corrupt PDFs reject a covered picture, swapped pages, omitted hidden page and same-raster font advance damage. The last keeps all pixels exact while changing an embedded glyph width; used glyph metrics still detect it.

[Actual-file Parser evidence](placeholder-index-native-parser-evidence.json) checks five before/after/reopened files in Node/ESM/global: complete inspections, content projections, reports and fifteen byte-exact source-only no-ops. All twelve local placeholders per input resolve uniquely by index, including default-zero/native explicitness and the retained max. Both source and compiled runtime dependencies are bound, so a changed Parser/Core requires reinspection. The [artifact verifier](../../scripts/verify-placeholder-index-evidence.mjs) regenerates all fifteen prepared PPTX/IR/Layout/origin/plan/warning/SVG artifacts and verifies native/Parser files, negative fixtures, dependencies and proof links.

First-save differences outside this named numeric binding graph are recorded in full; this proof does not declare all arbitrary first-save semantics source-equivalent. General native template import/rebinding, full reset and cross-document identity mapping remain open. Historical unindexed controls retain exact current output through the separately refreshed byte/native compatibility verifiers; they are not substituted for the new indexed control.

This completes the authored matching-policy subtask. AUT-07.2 remains open for the separate full reset/field/general geometry requirements; native source projection is tracked under IMP-05.1.4.

An adversarial review found an existing runtime admission gap: keys/kinds were not checked before role-sensitive matching, and an unsupported kind could reach Exporter's body fallback. The follow-up adds located Core validation for empty/non-string keys and unsupported kinds. Duplicate-key collection admits only valid strings before formatting a duplicate diagnostic, so malformed object keys cannot trigger string conversion. Focused tests reject malformed values, two matching invalid roles and failed replacement, retain `__proto__` as a valid logical string key, and require export to reject an unsupported kind. Valid fixture bytes and native files remain unchanged; only producer/consumer code dependencies are refreshed after verification.
