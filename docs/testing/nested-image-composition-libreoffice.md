# Nested image replacement and ancestor composition in LibreOfficeDev

The [probe](../../scripts/research/nested-image-composition-libreoffice.mjs) ran on macOS 26.5 (25F71), LibreOfficeDev 26.8.0.0.alpha0 (2c87e51eeaa2b413ff4ae097b2705eea1995d8e5), Pillow 12.1.1 and Poppler. It generates two slides with two nested groups, a 180° rotation and horizontal flip. On slide 1, an explicit replacement plan commits an outer group move/resize and replaces the red target with green; its blue sibling stays in the group. Slide 2 remains the red/blue control. The original generated slide 1 group has `rot=10800000`, `flipH=1`, x offset 2,540,000 EMU and width 2,032,000 EMU.

For the generated file and three headless LibreOfficeDev save/reopen cycles, independent ZIP/relationship inspection found green/blue media on slide 1 and red/blue on slide 2; both blue pictures shared one target, and all three image SHA-256 values remained unchanged. Six sampled PDF pixels per cycle showed green, blue and white at the slide 1 control points and red, blue and white at slide 2's points. The parser's no-op output matched each actual PPTX source byte for byte. These checks prove the sampled content and selected relationships for this fixture, not an entire-page pixel match or interactive editing.

LibreOfficeDev rewrote the group representation: the first save had two groups per page but no rotation/flip attributes on the recorded group transforms. On slide 1, the first saved outer y offset was 1,295,640 EMU and width 1,625,040 EMU; the second and third saves changed these to 1,296,000 / 1,624,680 and 1,296,360 / 1,624,320 respectively. The unchanged samples therefore do not prove identical group geometry, authored transform semantics or lossless editing. PowerPoint native interaction and other group transforms remain unverified.

Run `node scripts/research/nested-image-composition-libreoffice.mjs` after building Core, Layout, parser and exporter. It requires `soffice`, `pdftoppm` and Pillow; temporary files are isolated and removed on exit. It asserts the sample's media, pixels, generated source transform and exact no-op output, while reporting application-written geometry for comparison.
