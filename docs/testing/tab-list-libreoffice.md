# List markers and tab stops: LibreOffice controls

The retained [PDF observation](tab-list-libreoffice-evidence.json) covers 36 generated PPTX slides: a `•` bullet, Arabic starts 3 and 333, three indent/hanging pairs, and four tab alignments. In this LibreOfficeDev headless conversion, marker starts followed `text box left + indent − hanging`. The following `P` started at the greater of the paragraph indent and marker end. The tab target used the text-box left edge plus the explicit stop, rather than the left margin used by the separate non-list ODF controls. These are application-specific observations of these controls; they do not establish general list behavior or PowerPoint behavior.

The [browser comparison](tab-list-browser-libreoffice-evidence.json) checks the right edge of the tab-aligned text in all 36 cases against Chromium Layout. The maximum observed difference is 0.139 pt. The PDF text font identifies as Liberation Sans; Chromium used a registered same-PostScript-name Liberation Sans candidate and HarfBuzz advances agree within 0.5 pt. The PDF bullet uses OpenSymbol while browser measurement uses the first run's font, so the right-edge comparison does not prove marker-font or marker-position equality. Separate browser tests exercise marker-width boundaries.

Run `python3 scripts/research/verify-tab-lists.py` to inspect retained PPTX/PDF controls, and `node scripts/research/verify-tab-list-cross-app.mjs` to check the recorded browser comparison, candidate font hash and HarfBuzz arithmetic. Rerunning [the comparison](../../scripts/inspect-tab-list-cross-app.mjs) performs a fresh Chromium measurement. These checks require retained `.tmp/native-tab-list` artifacts and local LibreOffice fonts; they do not verify PowerPoint, actual native edits, automatic wrapping or arbitrary markers.
