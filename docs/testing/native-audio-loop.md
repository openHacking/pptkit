# PowerPoint audio loop and rewind observations

In PowerPoint for Mac 16.104, the third audio object of the [four-object baseline](../../tests/fixtures/pptkit-audio-volume.pptx) was changed and saved as three samples: [loop](../../tests/fixtures/powerpoint-audio-loop.pptx), [rewind](../../tests/fixtures/powerpoint-audio-rewind.pptx), and [both](../../tests/fixtures/powerpoint-audio-loop-rewind.pptx). The retained copies anonymize the last-modifier field. The selected object's media time node changes from `fill="hold"` to `fill="remove"` for rewind, gains `repeatCount="indefinite"` for loop, or has both changes for the combined case. Other audio objects retain their settings.

The [generated sample](../../tests/fixtures/pptkit-audio-loop.pptx), reproducible via `node scripts/research/generate-audio-loop.mjs <output.pptx>`, uses one shared audio asset for four instances: neither option, loop, rewind, and both. It opened in the same PowerPoint version without a visible repair prompt; the corresponding Playback checkboxes showed the expected states for loop, rewind and the combined object. These are editable UI state observations; actual sound, repeated playback, stop, replay and slide re-entry were not captured. A separate [trim authoring slice](native-audio-trim.md) now exists; actual trimmed loop boundaries remain unverified. Other applications and versions are untested.

The [independent XML verifier](../../scripts/research/verify-audio-loop.py) checks the target and time-node attributes for every audio instance in native and generated samples. Export tests also cover shared assets, mixed video, click and object-click start modes, invalid values, and default byte compatibility. Import does not project these settings.
