# Shared-definition edit verification

This AUT-07.1.2 slice adds master declaration creation/replacement and layout replacement through [the public API](../api/multi-master-authoring.md#editing-shared-definitions), under [ADR0057](../architecture/decisions/0057-master-theme-ownership.md#shared-definition-editing-follow-up). Per-property origins, artwork and general template editing remain open.

[Ten Core test groups](../../packages/core/test/definition-edit.test.mjs) cover shared propagation, old immutable snapshots, full-replacement reset semantics, missing bindings repaired by creation, duplicate/unknown/renamed IDs, nested/sibling element ID reuse and external collisions, bound placeholder/connector dependencies, rollback of auto-ID allocation, unrelated versus affected invalid drafts, resource reference ownership, and malformed/accessor/cyclic/sparse/over-depth input. Input getter execution is checked with a mutation counter. Failed candidates are followed by real operations reusing provisional/removed identities, rather than inferred from an unchanged snapshot alone.

[The public edit sequence](../../tests/fixtures/master-definition-edit.mjs) changes shared ownership, adds a master, clears old declarations, preserves false/zero flags and deliberately attempts an invalid replacement. [Cross-package tests](../../scripts/multi-master-parity.test.mjs) compare full normalized documents, Layout, SVG and PPTX bytes across Node, browser ESM and global without network requests. Independent browser DOM follows actual slide→layout→master→theme edges, checks expected theme colors, native shape counts, shared layout identities and background ownership. It does not use Parser projections to establish these facts. The shared layout shape occurs once in its owning layout and is not copied into slides.

[Isolated installed Node](../../tests/consumers/node.mjs) exercises the three methods and native graph output. [Installed strict types](../../tests/consumers/types.ts) check the richer factory return type, readonly registry and base-interface compatibility. The checked TypeScript example uses every new method.

Adversarial review targets five failure modes: silently merging omitted declarations; mutating old snapshots; leaking staged IDs/allocator or resource ownership on failure; breaking shared slide dependencies; and expanding the legacy structural contract. Explicit reset/none/zero cases, reference identity assertions, follow-on identity/asset operations, bound connector/placeholder rejection, and installed types respectively guard them.
