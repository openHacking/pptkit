# Resolved media deduplication: LibreOfficeDev probe

On macOS 26.5 (25F71), LibreOfficeDev 26.8.0.0.alpha0 (2c87e51eeaa2b413ff4ae097b2705eea1995d8e5), Python Pillow 12.1.1 and Poppler, the [optional probe](../../scripts/research/resolved-media-dedup-probe.mjs) creates a two-slide presentation. Two distinct Core assets resolve to the same red PNG from byte and path sources; a third resolves to a different blue PNG. Images appear on slides, a layout and a master. The resolver is invoked for all three assets and the opt-in deduplicator emits a single red media part plus a separate blue part.

Independent ZIP/XML inspection finds that the two red references on slide 1, the red reference on slide 2, and the layout and master references all resolve to the same red media part; slide 2's blue reference resolves to a different part. The red and blue SHA-256 digests were `cbfc5435155863342a420a8084d99082646da5508ee635ed2a1af4b53f0f4132` and `fd298a04c9d501c6bc2f4900c902cbe49f5031717600c7a0de9a6ebe83803ee9` respectively. The resolver's path is illustrative: it explicitly returns the bytes and does not test filesystem loading itself.

After each of three headless LibreOfficeDev PPTX save/reopen cycles, the same image digests and shared-versus-distinct relationships remained, and PPTKit's no-op save reproduced each actual LibreOffice-produced file byte for byte. LibreOffice renamed the media and changed ownership: the original layout and master each held one red reference, while the saved layout held none and the saved master held two. At five sampled positions per page, the first page remained red/red/white/red/red and the second red/white/blue/red/red in the original and all three reopened PDFs. This is evidence for these sampled positions and resources, not a pixel-perfect full-page comparison or proof that owner semantics and editability are preserved.

Run `node scripts/research/resolved-media-dedup-probe.mjs` after building Core, parser and exporter. It requires `soffice`, `pdftoppm` and Pillow, creates an isolated temporary directory, and removes it afterward. The script asserts the named relationship and pixel expectations, so another application version may produce a different result. PowerPoint interaction, other producers, effects, arbitrary images and preservation-aware edits remain unverified.
