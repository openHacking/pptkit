# Column and line chart with a secondary value axis

This research probe assembles a native clustered-column and line chart from separately exported controls. It uses one workbook with a shared Jan/Feb/Mar category column, independent numeric columns, and two reciprocal category/value axis pairs. The secondary category axis is hidden; both value axes are visible. The line and columns use the same category centers. The [OOXML plot-area contract](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.plotarea?view=openxml-3.0.1) allows these chart families to coexist in one plot area.

The [evidence](combination-chart-probe-evidence.json) records stable LibreOffice 26.8.2.2 on macOS arm64. The left axis displays 0–10 and the right axis 0–1,000. Independent PDF measurements verify three columns at 20%, 50%, and 80% of the left scale and a line at 80%, 20%, and 60% of the right scale. Native resave and reopen retain the reciprocal axis graph and both value caches, while changing axis IDs and removing the embedded workbook. The two PDF renders are checked individually; this is not a claim of identical appearance.

After building, run [the generator](../../scripts/prepare-combination-chart-probe.mjs) with a new output directory. Using distinct LibreOffice profiles, export `combination.pptx` to PDF in `pdf/`, resave it via `Impress MS PowerPoint 2007 XML` in `saved/`, and export the resave to PDF in `reopened/`. Retain the three command logs as `open.log`, `save.log` and `reopen.log`, and record `soffice --version` in `version.txt`. Run the [independent verifier](../../scripts/research/verify-combination-chart-probe.py) with the output directory.

The original probe predates the public API. The [public API observation](combination-public-probe-evidence.json) uses the same controls and independently verifies the two axes and native save/reopen; run the generator and verifier with `--public` to repeat it. See [combination authoring](../api/chart-combo.md) for the supported profile. The [saved LibreOffice package](../../tests/fixtures/combination-libreoffice-resave.pptx) is a regression fixture for cache-only import, with its hash checked against the public evidence and three fresh export/import rounds.

PowerPoint 16.104 on macOS opened the public sample and showed Jan/Feb/Mar, the left scale of 0–10, the right scale of 0–1,000 and three line markers at the column centers. No repair dialog was observed on that open. That observation covers first display of the unedited sample.

The [source edit-save observation](combination-source-save-native-evidence.json) changes February columns from 5 to 7 and the line from 200 to 400. The package verifier confirms both changed caches and their workbook cells before opening. LibreOffice 26.8.2.2 renders the February marks at 70% and 40% of their respective scales on first open and after native save/reopen. It removes the workbook when it saves, while retaining both edited caches and axis pairs. To repeat, run the generator with `--edited`, perform the same three headless commands using `combination-edited.pptx`, then pass `--edited` to the verifier.

The [PowerPoint save/reopen observation](combination-powerpoint-resave-evidence.json) starts from the source-edited sample. The slide reopened with the same scales, categories and edited marks. The [saved fixture](../../tests/fixtures/combination-powerpoint-resave.pptx) retains the workbook and moves the hidden secondary category axis from top to bottom. Run the verifier with the saved file path and `--powerpoint-resave` to check the axes, caches and workbook independently. The parser regression also edits the native fixture and checks the recovered worksheet bindings. PowerPoint’s interactive Edit Data command was not tested.
