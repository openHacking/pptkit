# Slide visibility source-preserving save

Factory-owned slides expose `setHidden(boolean)`, with `hidden` remaining read-only to callers. The setter validates the value before changing the slide; custom `PresentationSlide` implementations may omit it. Imported sessions expose this setter as optional through the base interface, so consumers should check it before calling.

`importPptx(bytes, { projection: "content", slideVisibilitySaveProfile: "attribute-v1" })` admits changes to the hidden state of existing source-bound slides. Each slide must be the raw PresentationML `sld` root, with its original `show` attribute or absence consistent with the imported state and source slide identity. Hiding writes `show="0"`; unhiding writes `show="1"`. If the attribute was absent, hiding inserts it. An unchanged visible slide with no declaration remains unchanged, and no-op saves still return original bytes. The profile does not remove a declaration or edit slide order, sections or other settings.

The opt-in report contains `slideVisibilitySources` with a slide identity, source location and bound/unmapped status. This is eligibility evidence only; it does not grant a save plan. Multiple slides can be changed in one plan. Views sharing a source slide must agree, including unchanged views; conflicts block the plan. Source package policy and applicable part guards, relationship closure, change/work/output limits, full candidate comparison and reprojection still apply. Geometry, text or other unadmitted edits block the whole plan. The profile supports combination with compatible text, chart and `firstSlideNumberSaveProfile: "attribute-v2"` edits; description, name and existing decorative value edits can join through `descriptionEditSaveProfile: "mixed-v5"` with `editSaveProfile: "text-runs-v3"`. Picture replacement, artwork, field/text projection and other excluded profiles cannot be combined.

The CLI supports `inspect source.pptx --projection content --visibility-values --json` and a hash-bound `--visibility-edits` manifest; see [CLI save](cli-save.md).

[Parser tests](../../packages/pptx-parser/test/slide-visibility-save.test.mjs) check both dialects, three saves/reimports, exact affected XML, non-target package bytes, mixed edits, limits, stale plans, shared-source conflicts and signature guards. [Node file tests](../../packages/pptx-parser/test/file-save.test.mjs) and [browser/Node parity](../../scripts/decorative-export-parity.test.mjs) cover public entry points. A [LibreOfficeDev headless observation](../testing/slide-visibility-libreoffice.md) checks a three-page source edit, three producer resaves and PDF page extraction. A successful plan has `scoped-preservation` assurance, not a PowerPoint or LibreOffice interactive validation. Native slideshow behavior, other producers, and full slide/document property preservation remain unverified.
