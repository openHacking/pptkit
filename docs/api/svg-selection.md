# SVG preview selection frames

`getSvgSelectionFrames(slide)` accepts one resolved `LayoutSlide` and returns a frozen, detached array of slide-owned element frames in SVG paint order. Each frame carries the stable element ID, outer-to-inner ancestor group IDs, and four slide-space corners in the element's original corner order. Group scaling, flipping and rotation use the same order as SVG rendering, including nested groups. The result is a snapshot: recompute it after resolving a changed slide.

`getSvgSlideSelectionFrames(layout, slideIndex)` also includes visible master and layout artwork in renderer paint order before slide content. Each frame adds an immutable `owner` containing `type` (`master`, `layout` or `slide`) and its ID. The page's `showInheritedShapes` and layout's `showMasterShapes` are honored independently. A shared master or layout owner denotes the definition, not a local object or authorization to edit all pages. `hitTestSvgSelectionFrames` retains this owner type in its TypeScript result. The [typechecked example](../examples/svg-selection.ts) combines owned frames with viewport mapping.

`getSvgSlideSelectionGeometry(layout, slideIndex)` extends that ordered owned snapshot with connector polylines, using resolved start, route and end points after element and nested group transforms. Entries have `kind: "frame"` or `kind: "connector"`; connector points are immutable slide-space coordinates. `hitTestSvgSelectionGeometry(items, point, connectorTolerance)` returns the topmost frame or polyline centerline within the caller's finite nonnegative slide-space tolerance, including endpoint and zero-length segments. It does not infer stroke width, dashes, arrowheads, caps, opacity or exact painted pixels; tolerance is a selection policy chosen by the caller. The per-snapshot limit is one million connector points, in addition to the element and depth limits. Overflowing hit-test arithmetic throws rather than silently selecting a target.

Pass `{ includeConnectorStrokeGeometry: true }` to additionally snapshot local points, width and accumulated transform for positive-width, positive-stroke-opacity connectors. `hitTestSvgConnectorStrokes(items, point)` tests their round-capped and round-joined stroke bodies in local coordinates, including nonuniform group scaling, and returns the topmost matching connector. It ignores frames and cannot determine whether another object visually occludes the connector. Solid, dash, dot and dash-dot stroke patterns follow the SVG renderer, with dash phase continued across segments. Zero-width, zero-stroke-opacity and no-paint connectors have no stroke geometry and are skipped; arrowheads are not tested. Element/group opacity is not considered unless combined with `excludeZeroOpacity`; clipping, CSS, filters, pixels and hit tolerance are not evaluated. Singular or numerically unrepresentable inverse transforms and unrepresentable dash periods throw; finite arithmetic can differ at stroke boundaries. This is an opt-in snapshot; existing geometry and hit-test behavior remain unchanged. Recompute it after layout or style changes.

Pass `{ excludeZeroOpacity: true }` as the optional third argument to omit objects whose resolved element opacity is exactly zero and all descendants of zero-opacity groups, across slide, layout and master layers. The default retains them for authoring selection. Positive opacity, including very small values, is retained; the option does not inspect fill or stroke opacity, shape text, image transparency, clipping, effects, CSS or actual pixels. It is therefore a coarse filter rather than a general painted-visibility test. Recompute the snapshot after opacity changes.

`{ excludeUnpaintedShapes: true }` additionally omits a shape only when it has no text or shadow, its stroke is none, zero-width or zero-opacity, and its fill is none, a zero-opacity solid, a gradient with all stops at zero opacity, or a pattern with both colors at zero opacity. These checks use the resolved style and apply inside groups and shared layers. A shape with text or shadow is retained conservatively, even if those contents would not paint; other element types are unaffected. Nonzero strokes keep the entire frame or interior selectable, not just the actual stroke. CSS overrides, clipping, effects and pixels are not evaluated. Both options may be combined; their default values are false.

`{ excludeUnpaintedConnectors: true }` omits a connector with no stroke paint, or one with zero-width or zero-opacity stroke and no arrowheads. It applies across slide, layout and master layers and nested groups. A connector with arrowheads and non-none paint is retained even when the line has zero width or opacity: the renderer's SVG markers use independent paint, and their visibility cannot be inferred from line opacity. This is a conservative filter, not an exact test of marker, dash, cap or stroke pixels. It may be combined with the other options; its default is false.

Shape entries additionally carry immutable normalized outline data where needed. `hitTestSvgSelectionOutlines` uses the renderer's geometric interiors for rectangle, rounded rectangle, ellipse, triangle, diamond, arrow, chevron and parallelogram, including nested transforms and the explicit parallelogram slant. Other objects still use frames and connectors still use centerline tolerance. The original frame-based hit function keeps its previous behavior. Outline hits describe geometry regardless of fill visibility: `none`, opacity, stroke, effects, shape text, clipping and painted pixels are not tested. An extremely small rounded radius that underflows uses a rectangle. SVG shape geometry is not a guarantee of PowerPoint's native preset appearance.

`hitTestSvgSelectionFrames(frames, point)` returns the last frame containing the finite slide-space point, or `undefined`. Frame edges are included subject to floating-point rounding. Its cross products use scaled vectors to reduce overflow and underflow from multiplying large or small coordinates; unrepresentable coordinate differences throw `RangeError`, and finite floating-point arithmetic still has precision limits. Callers own selection state. The function makes no DOM reads and does not mutate Layout or authoring state.

`createSvgViewportMapping(slideSize, viewport)` returns a frozen snapshot with a uniform `scale`, the centered `contentBox`, and `slideToViewport(point)` / `viewportToSlide(point)` functions. It follows the root SVG's default `xMidYMid meet` behavior and accounts for letterboxing. The viewport box and input/output points use the same caller-selected coordinate system: for browser client coordinates, supply the SVG content viewport's client rectangle in CSS pixels. The mapping permits points outside the slide, including letterbox areas; callers decide whether to reject them. Recompute after resize or movement. The caller must account for borders, padding, CSS transforms, browser zoom and device-pixel conversion when deriving the viewport; an axis-aligned bounding rectangle alone cannot represent rotation, skew or arbitrary transforms. The helper does not read the DOM, inspect CSS, or infer a different `preserveAspectRatio`.

For a transformed 2D preview, `createSvgAffineMapping(matrix)` instead accepts six SVG/DOMMatrix affine coefficients `{ a, b, c, d, e, f }` and provides the same two point-mapping functions. In a browser, the root SVG's non-null `getScreenCTM()` supplies slide-to-client coefficients in CSS pixels, including its viewBox mapping and the browser's 2D transforms. The caller reads that matrix after layout and obtains a new snapshot when it changes. Both directions allow outside points and return frozen coordinates; singular, nonfinite, explicitly 3D or numerically unrepresentable inverses reject. Very ill-conditioned transforms can lose precision even when invertible. The helper does not support perspective projection, DOM observation, clipping, device-pixel conversion or scroll/resize subscriptions.

Frame-based tests use **rectangular authoring frames**; the separate outline function applies shape interiors as described above. Neither tests painted pixels. Transparent fills, text whitespace, image crop/fit, effects and overflow do not alter the frame. Hidden elements and descendants of hidden groups are omitted; zero-opacity objects are omitted only when the geometry option requests it. Groups themselves are omitted; the frame-only functions omit connectors. Zero-area leaf frames and descendants of zero-area groups are omitted. Coordinates outside a group are not clipped. Invalid nonfinite geometry, invalid group coordinate dimensions, more than 100,000 visited elements across the selected layers or more than 64 nested groups throw. Do not use this API as a complete editor hit-test or visual clipping contract.
