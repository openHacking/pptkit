# Video source inventory

Content imports may opt into `videoSourceProfile: "iso-bmff-v1"`. For effective slide-local pictures with a direct DrawingML `videoFile`, Parser inventories each direct reference, each `p14:media` under the specified Office extension and each `a:blip` poster reference. Each record identifies the slide, raw source element and relationship, object identity, declaration and status. It scans pictures in groups even when their geometry cannot be projected. Inactive MCE choices, masters, layouts, non-picture objects, `quickTimeFile`-only and media-extension-only objects are outside this profile.

Internal `video/mp4` targets are inspected with the bounded [ISO BMFF framing inventory](iso-bmff-inspection.md); `iso-bmff-framing` means only that top-level framing and the `ftyp` declaration were read. The record contains the part name, content type, major/minor brand, compatible brands and box count. It does **not** verify tracks, codec, offsets, visual content or playback. Other MIME types, malformed framing, missing relationships, fragments and wrong relation types/modes are reported unsupported. Office companion records identify whether a single unambiguous internal video declaration points to the same part, a different part, or cannot be compared. Conflicting audio or QuickTime declarations block that comparison.

Poster records identify the distinct image relationship and source part or unresolved external target. `internal` describes relationship resolution only; it does not validate the poster's image bytes or imply that an image was projected. If the source has no `a:blip`, no poster record is fabricated. External references record the unresolved relationship target but are **never fetched**. Multiple objects referencing one video retain separate source records and share one inspection, charged once by part identity. Distinct inspected video parts are bounded by `maxImportedAssetBytes`, `maxTotalImportedAssetBytes` and the 64 MiB inspector limit; this inventory's aggregate counter is separate from image projection and audio inventory. Each profile enforces its own `maxReportFindings` cap. Limits fail the import rather than truncating the report.

This is a read-only inventory. It creates no Core video asset, grants no source editing or playback permission, does not extract a poster, and does not alter the default static media-poster fallback. No-op save retains the original source bytes. Default imports omit `videoSources`. The Node file adapter captures the option before I/O; Node and Chromium inventories are compared by a no-network regression test. See the [native H.264 observation](../testing/native-h264-video.md) for the specific source sample, not a general compatibility claim.
