# Source master picture inventory

`inspectPptxMasterPictures(bytes, options?)` in the Parser root, browser and global entries inventories pictures in the **effective** drawing trees of listed slide-master parts. It reports the source master part and numeric identity, listed layout parts, source slide IDs whose layout both appears in that master's list and points back to it, and pictures in drawing order. Slide membership is not a claim that inherited artwork is visible. Unlisted or ambiguous ancestry is not silently added.

`slideUses` identifies each verified slide-to-layout path and retains the slide's and layout's explicit `showMasterSp` attribute as source lexical strings when present. An absent attribute remains absent; the inventory does not apply defaults, validate the boolean, evaluate placeholders or determine whether any particular picture is visible. These records share the inventory's work, record and text budgets.

Each picture records its verified raw XML element index, optional source drawing ID/name and placeholder type/index, containing group raw indices, embedded/link relationship ID and classification, and explicit transform and source-crop lexical attributes when present. Missing crop sides or transform fields remain absent; the API does not synthesize defaults, calculate world geometry or interpret rotations. Non-picture `sp`, `cxnSp` and `graphicFrame` nodes encountered in these trees contribute to `otherDrawingCount`, which is not a complete count of unknown or opaque objects. External image relationships are classified without fetching or returning the remote target; malformed internal targets can cause package inspection to reject before a report is returned.

Only effective MCE branches and recognized `spTree`/`grpSp` containers are traversed. Inactive branches, unknown wrappers, layout pictures, unlisted masters, inherited placeholder semantics, image pixels, ICC/EXIF, unknown effects and indirect binary references are outside the inventory. `coverage: "effective-listed-masters-only"` and `mapping: "not-performed"` are explicit: a source index or relationship does **not** establish Core projection, object editability, complete reference closure or permission to replace or delete a source part. Use the source-preserving session for byte-identical no-op saves. The separate opt-in partial content projection is described in [content import](content-import.md).

`masterPictureLimits` accepts positive safe integer `maxWorkUnits` (default 1,000,000), `maxRecords` (100,000) and `maxTextCharacters` (1,000,000). The budgets bound this inventory's traversal and returned records/string characters; inherited OPC, ZIP, XML and MCE limits separately bound source inspection and may reject first. These are not hard process-memory caps. Limit objects reject unknown keys and accessors. An already aborted signal rejects; traversal checkpoints permit cooperative cancellation. Input bytes are copied before asynchronous archive work; shared-memory input is rejected, and synchronous caller getters can still mutate input before the copy. Results are detached and deeply frozen.

The [focused tests](../../packages/pptx-parser/test/master-picture-inventory.test.mjs) cover Strict/Transitional, nested groups, active MCE selection, source identity, missing/wrong/external relationships, unlisted layout membership, budgets, input snapshots and cancellation. [Browser/Node parity](../../scripts/master-pictures-parity.test.mjs) verifies a shared nested-picture deck with requests blocked. For one PowerPoint 16.104 native-edited file, an [independent raw ZIP/XML oracle](../../scripts/research/oracles/master-pictures-native.py) checks object index, crop, frame, image target and page IDs against the [bound evidence](../testing/master-pictures-native-evidence.json); it does not prove native UI provenance or general import fidelity.
