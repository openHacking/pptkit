# First-slide-number preservation

`importPptx(bytes, { projection: "content", firstSlideNumberSaveProfile: "existing-v1" })` explicitly admits replacement of an existing, nonnegative `firstSlideNum` on the effective presentation root. Set `session.document.setFirstSlideNumber?.(value)`, then prepare and save an `edit` plan. The candidate must be an integer from 0 to 9999. The prepared report identifies the raw source element and the before/after values. Default imports still block this edit.

`existing-v1` permits the number change alone. It cannot be combined with text, chart or picture edit profiles, master artwork, diagram preview or optional text-style projection profiles. `fieldTextProfile` may be used for read-only field projection. In `existing-v1`, adding a missing attribute or clearing an existing one is blocked. Negative source values, new values over 9999, and unrelated document edits are blocked in both profiles. Restore the baseline to prepare an exact no-op save. A plan becomes stale if the document changes after preparation.

The importer resolves the effective presentation root to its raw element identity, including an MCE-selected branch. The writer checks the expected decoded source value and replaces only the existing attribute value. Before a plan becomes ready, the save checks the source dependency closure, replaces the approved part, compares the entire candidate package for out-of-scope changes and reprojects the actual candidate against the full Core snapshot. The Node file adapter captures the option before filesystem work. Tests cover three save/import rounds, both OOXML dialects, selected MCE branches, Node/browser parity, unsupported combinations and stale plans. This is not permission to change other presentation attributes or a guarantee that a native application will preserve the value. PowerPoint editing and reopening the `existing-v1` profile have not been verified.


`firstSlideNumberSaveProfile: "attribute-v2"` additionally admits inserting an absent `firstSlideNum` and clearing an existing nonnegative declaration via `setFirstSlideNumber?.()`. An absent attribute means the default start of 1, but is distinct from an explicit `1`; save reports omit `before` or `after` when the respective declaration is absent. Replacements still accept 0–9999 and the candidate checks above apply. This profile may be combined with `editSaveProfile: "text-runs-v1"`, `"text-runs-v2"` or `"text-runs-v3"`, and/or `chartEditSaveProfile: "existing-values-v1"`, to atomically save admitted bound text and chart-value edits alongside the number change; field caches and identities remain protected. Picture source inventory (`pictureSourceProfile: "embedded-v1"`) can be requested with `attribute-v2`; it remains read-only and does not grant picture-edit authority. With `pictureEditSaveProfile: "replace-v1"`, the same profile can combine one picture replacement with the starting-number change; this combination excludes text, chart and field profiles; number-only saves remain available. Master artwork and diagram preview remain excluded. The existing `textFontProfile`, `notesTextProfile` and `textTargetSaveProfile` options may be combined with `attribute-v2` under their own prerequisites and guards. Field projection may be combined with chart-value editing; fields remain read-only. Text/chart edits that target the same source part are blocked; picture replacement and numbering must target distinct parts. The lexical editor inserts or removes only the selected attribute, preserving the other package contents and inactive MCE branches. Tests cover repeated insertion, replacement and clearing, strict and transitional MCE, UTF-16 in both byte orders, and browser/Node output parity. Combined saves have tests for shared-picture inventory, slide text and notes adjacent to a field, including three rounds in both OOXML dialects and browser/Node parity. Paragraph-target and font projection combinations preserve timing and retain character-range guards in three-round tests in both dialects; notes-style projection is also covered. Combined field projection, chart, text and number edits have three-round tests in both dialects; chart-number saves also have Node, browser ESM and global parity and [three PowerPoint reorder/save/reopen observations](../testing/combined-number-chart-powerpoint.md). One [PowerPoint observation](../testing/first-slide-number-powerpoint-observation.md) covers inserting 17 and a single save/reopen after slide reordering; clearing and broader native coverage remain unverified.
