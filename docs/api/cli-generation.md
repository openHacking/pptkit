# CLI JSON generation

`pptkit generate deck.json output.pptx --json` creates a fresh PPTX from a UTF-8 JSON authoring document. The destination must be new, including no existing symlink; parent directories must exist. The command uses public Core authoring methods and the browser-neutral Exporter, then validates the generated package with Parser and publishes it with Parser's create-only file adapter. It does not overwrite a file or perform native application verification.

```json
{
  "version": "pptkit-authoring-v1",
  "presentation": { "metadata": { "title": "Example" }, "size": { "width": 960, "height": 540 } },
  "slides": [
    { "elements": [ { "type": "text", "box": { "x": 40, "y": 40, "width": 400, "height": 80 }, "content": "Editable text" } ] }
  ]
}
```

`presentation.metadata.customProperties` accepts the [typed custom-property authoring subset](core-metadata-save.md#authored-custom-properties). Unsupported XML characters and overlapping OOXML escape-like sequences reject `generate` and `validate --export` as `authoring-export-invalid` before publication.

The envelope accepts only `version`, optional `presentation`, optional `assets`, optional `layouts`, and required `slides`. `presentation` maps to Core `PresentationInit`; slides, layouts and assets map to their Core input contracts. Top-level fields on those objects are checked against the current documented Core contracts. This is not a complete JSON Schema: nested fields follow Core/Exporter behavior, validation and warnings, and unknown nested properties may be ignored. Use their [authoring and validation documentation](core/presentation.md) when constructing input. Duplicate JSON object keys follow JavaScript JSON parsing (last value wins).

`pptkit validate deck.json --json` reads the same input, constructs the same Core document and returns its complete Core authoring diagnostics without generating or writing a deck. A valid document returns exit 0 and `report.valid: true`; Core error diagnostics return exit 1, `status: "invalid"` and the full located diagnostics on stdout. Malformed or unsupported authoring input returns exit 3 on stderr; resource limits return 4. This check does not decode image pixels, run the Exporter, verify native support or guarantee that generation will succeed without warnings. Validation is synchronous and cancellation is observed around it, not during Core traversal. Both commands reject non-object boxes, more than 100,000 elements, and element nesting deeper than 128 before constructing Core state.

Add `--check-descriptions` to include `report.descriptions`: `status: "checked"`, `scope: "authored-definitions"` and all [missing-description findings](accessibility-descriptions.md), with object and owner identities. Findings alone do not change the exit code. Add `--fail-on-missing-description` to return exit 1 and `report.valid: false` when any are found; the failure policy requires the check and is validate-only. With Core errors the check is `skipped-invalid-core`, rather than presenting an incomplete result. It can be combined with `--export` and its separate warning policy. A clean result only means the selected objects have explicit descriptions or are excluded by the check; it does not assess quality, reading order, contrast or native/assistive-technology behavior. The whole report shares the output budget, and synchronous checking cannot be interrupted until it returns.

Add `--description-occurrences` alongside `--check-descriptions` to select `scope: "modeled-slide-occurrences"` instead of the default definition inventory. Findings identify each affected slide and the source owner; unused definitions and suppressed inherited artwork are excluded. The existing strict flag applies to the selected scope, so a deck with missing descriptions only in unused definitions fails the default check but can pass the occurrence check. Expansion is bounded by the output budget and returns exit 4 without a partial report if it cannot fit. This is modeled visibility, not native or assistive-technology verification.

Use `--check-contrast` to add `report.contrast` with the [conservative text contrast observations](accessibility-contrast.md). `--fail-on-contrast` requires that check and returns exit 1 if any observation is below threshold **or indeterminate**; absent or excluded content is not assessed. Without the failure policy, observations do not change exit status. Invalid Core documents produce `skipped-invalid-core`. Both flags are validate-only and can be combined with description and export checks. A zero-finding or successful strict result is not a conformance claim: chart labels and image text are outside this profile. Visible inherited text has one finding per slide occurrence with its master or layout identity. The output budget bounds both findings and serialized bytes; synchronous checking cannot be interrupted until it returns.

Add `--export` to also run the normal Exporter and parse the resulting PPTX structurally in memory, without publishing a file. On success, `report.scope` is `core-and-export` and `report.export` contains `status: "checked"`, the slide count, generated byte length and all export warnings. Warnings do not change exit 0 or `report.valid`; they may describe omitted content and should be inspected. Core errors still return exit 1 and mark export `skipped-invalid-core`. Export refusal returns exit 3 with the export diagnostics, and package or resource failures retain their normal exit codes. The generated bytes use the same default Parser limits as `generate`; `--max-input-bytes` bounds the JSON input, not generated bytes. The output budget bounds the report, not peak generation memory. This option does not run a native application or prove visual fidelity. `--export` is valid only on `validate`.

For a policy that treats every exporter warning as a failure, use `validate deck.json --export --fail-on-export-warning --json`. A checked export with warnings then returns exit 1 and `report.valid: false`, preserving the full warning list. The same flag on `generate` returns exit 3 with `export-warnings-rejected` and the warnings before any destination is published. If a complete report exceeds `--max-output-bytes`, the command instead returns exit 4 with an output-limit error; increase the budget to inspect the warnings. A warning-free export proceeds normally. This policy includes all warnings, including approximations that a caller might consider acceptable; it is not a complete loss detector or a native fidelity guarantee. It is opt-in and requires `--export` when used with `validate`.

`pptkit preview deck.json --slide 1 --json` returns a JSON envelope containing a selected slide's SVG, dimensions, slide ID, zero-based index, hidden flag and Renderer warnings. `--slide` is a one-based canonical decimal position (including hidden slides), independent of the presentation's displayed starting number. The command does not create a file. Rendering warnings cover the selected slide; unscoped layout diagnostics, if any, remain global. `report.status` is the Renderer status. For example, a directly embedded non-8-bit JPEG may return `jpeg-preview-precision-unverified`: the CLI still returns exit 0 and the original image bytes, so callers must inspect the warnings rather than infer visible pixels from successful publication. A nonexistent slide returns exit 3, and an oversized JSON response returns exit 4 without partial output. The selected SVG is static and follows the [SVG renderer's limitations](svg-renderer.md); it does not prove PowerPoint appearance, rendering of embedded fonts or native animation playback. Treat SVG from untrusted content according to the embedding application's security policy.

Add `--output 'slide preview.svg'` to a single-slide JSON or PPTX preview to create a standalone SVG. The success report includes the relative destination, slide metadata, warnings, optional import report and `publication.status: "committed"` with byte length; the SVG text is in the file rather than the report. The file bytes equal the inline SVG for the same captured input. With `--slide all --output deck.html`, the output is an HTML document with every page in order, including labeled hidden pages; the report instead contains a `slides` metadata array and `publication.format: "html"`. An empty deck produces an HTML document without pages. Each slide's escaped SVG is placed in its own sandboxed `srcdoc` frame, isolating repeated SVG IDs and disabling scripts. Browser rendering and external resource behavior still depend on the browser; do not treat the wrapper as a general sanitization guarantee for untrusted SVG.

The cumulative raw SVG, final SVG or HTML file, and JSON report each obey `--max-output-bytes`; the complete report is checked before publishing. HTML escaping and frame markup add bytes, so a whole-deck file can exceed the budget even when the raw SVGs fit. Intermediate escaping and the current SVG can allocate before their final checks; this is not a peak-memory guarantee. The destination must not already exist, including as a symlink. Parent directories must exist.

Publication writes and syncs a new `0600` temporary file in the destination directory, then hard-links it exclusively to the target. Cancellation before the link leaves no published output; once linked, success is authoritative. A failure removing the temporary name after commit is reported in `publication.temporaryPath` when the complete report fits. If post-commit details do not fit, success instead reports `detailsTruncated: true` and the caller must inspect the directory. Failed pre-commit cleanup returns `file-cleanup-failed` with the temporary path. This CLI adapter does not sync the directory or independently read back the temporary file, and assumes a trusted stable parent directory and a filesystem supporting hard links. It does not provide the stronger [PPTX file adapter](file-save.md) durability or identity guarantees. Browser availability is not required, and the file remains an SVG with the renderer's documented limitations.

Use `--slide all` to render every page in presentation order, including hidden pages. The report has `slides` rather than `slide`; each entry retains its zero-based index and SVG. Empty decks return an empty array. Rendering warnings cover all rendered pages and global layout diagnostics. All SVGs, warnings and any import report share one output budget, so a whole-deck request may exceed the limit even when each single-page request fits.

`pptkit preview deck.pptx --input-format pptx --slide 1 --json` instead imports the captured package using the default experimental [content projection](content-import.md) before rendering. `report.inputFormat` records the selected format, and `report.importReport` contains the full public import report, including source findings and diagnostics; review it alongside the SVG warnings. Unsupported objects and inheritance may be absent or approximated, and this command does not claim source fidelity or native validation. External image relationships are not fetched. The full import report and SVG share the output budget; if they do not fit, the command returns an output-limit error rather than silently omitting findings. `authoring-json` remains the default format and does not add an import report.

The renderer normalizes and resolves the complete document, then renders only the selected slide or all slides when explicitly requested. The CLI passes `--max-output-bytes` as a cumulative raw SVG byte limit, stopping before later slides once it is exceeded; the final JSON is separately checked because escaping, warnings and import reports also consume bytes. Each current slide is constructed before its raw SVG check. These limits do not bound layout work, the current slide's transient allocations or peak memory. Cancellation is checked between slides and elements; synchronous normalization, layout and individual rendering steps are not preemptible. The JSON input and embedded-asset policy applies to authoring-JSON preview, validation and generation. PPTX preview instead uses the Parser content-import limits and policies.

Assets normally use `{ "type": "bytes", "encoding": "base64", "value": "..." }`. To opt into local files, pass `--asset-base DIR` to `generate`, `validate` or authoring-JSON `preview`, and use `{ "type": "path", "value": "photo.png" }`. The base is resolved against the command working directory; asset paths use relative slash-separated components, reject absolute paths, parent components, backslashes, colons and empty components, and resolve against that base rather than the JSON file's directory. URLs are rejected and never fetched. Without the option all path assets remain rejected.

Local assets are read as regular files and captured as bytes before Core construction; each declaration is read separately, even when paths repeat. The command checks file metadata around each read and returns ordered `assetInputs` with the captured path relative to the command working directory, byte length and SHA-256 in successful JSON reports. The JSON source is independently bounded by `--max-input-bytes`; the sum of local asset bytes across declarations has the same limit. Embedded Base64 remains part of the JSON bound. These limits do not bound peak memory, Base64 expansion, or synchronous conversion. Symlinks are followed, and lexical path restrictions do **not** make the base a security sandbox: use trusted local paths and directory contents. No filesystem atomic snapshot across multiple files is promised. The file adapter's per-file change check cannot exclude every concurrent mutation. `--asset-base` is rejected for PPTX preview and other commands.

Explicit hyperlinks remain document content and are not fetched. The Exporter may omit unsupported or invalid images with warnings; check `exportWarnings` rather than assuming every requested object was materialized. Authored event timelines remain subject to the Exporter's refusal policy. Parser's default ZIP and prepared-output limits also apply to the generated package, so a generated PPTX larger than those limits is rejected before publication. These limits are not a hard peak-memory guarantee.

`--image-diagnostics` opts `generate` or `validate --export` into the Exporter's bounded PNG/APNG and GIF structure/playback diagnostics and JPEG EXIF-orientation and ICC diagnostics. Findings appear in the existing export warnings; add `--fail-on-export-warning` to reject generation before publishing or to make export validation fail. The checks preserve original bytes and do not decode pixels, establish native playback, validate complete color fidelity or guarantee that every malformed image is detected. Without the flag the existing signature-only default remains unchanged. See [byte assets](byte-assets.md) for the exact format-specific limits and warning meanings.

Use `--validate-image-data` on `generate` or `validate --export` to check PNG/APNG decoded scanlines, GIF LZW indices, and supported JPEG marker structure. Failed images are omitted with warnings. Combine it with `--fail-on-export-warning` to prevent publication or fail export validation instead. It can also be combined with `--image-diagnostics` to retain the JPEG EXIF and ICC warnings. This flag does not enable URL fetching or change how local paths are captured.

```sh
pptkit generate deck.json deck.pptx --validate-image-data --fail-on-export-warning
```


CLI tests exercise truncated headers and real APNG, animated GIF, PNG/JPEG ICC and JPEG orientation samples. They verify asset-located warnings, one warning per repeated asset, unchanged packaged bytes, rejection before publication in strict mode and acceptance of ordinary PNG/GIF samples. These samples do not expand the underlying inspectors' guarantees.

JSON success uses `pptkit-cli-report-v1`, source path/size/hash, relative destination, `nativeVerification: "not-performed"`, and a committed report with slide count, byte length, export warnings, directory-sync status and file warnings. The command preflights a bounded fallback report before publication. If report details exceed `--max-output-bytes` after commit, success instead contains `detailsTruncated: true`; inspect the generated file and its directory. Cancellation before publication returns 130; after publication the committed result is authoritative. Other exit codes follow [CLI inspection](cli-inspection.md). The [file adapter contract](file-save.md) describes publication and cleanup guarantees.

Tests cover JSON/geometry errors, unsupported asset sources, existing targets, limits and cancellation, as well as a generated text-and-image package reimport. Isolated installed-command tests exercise the executable. The command does not establish cross-application appearance or editability beyond the underlying exporter contracts.

Round custom connector paths are also exercised through JSON validation, preview, generation and content reimport, including rejection before publication when closed endpoints differ. An isolated installed CLI test generates and previews a closed round path and checks its imported closure and opacity. This covers the documented round-path subset, not arbitrary SVG paths or native point editing.
