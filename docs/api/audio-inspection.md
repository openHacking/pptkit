# PCM WAVE inspection

`@pptkit/media-inspection` exports `inspectWavePcm(bytes, options?)`, a synchronous, environment-neutral structural inspection of a deliberately narrow RIFF/WAVE profile. It snapshots the supplied `Uint8Array` view and returns frozen channel count, sample rate, bit depth, frame count, duration and the data chunk offset/length relative to that view. It does not return or retain audio bytes, decode samples, establish audible content, validate an audio device or prove native/browser playback.

The accepted format is little-endian RIFF/WAVE with exactly one 16-byte PCM `fmt ` chunk before exactly one `data` chunk, one or two channels, 8 or 16 bits per sample and positive sample rate. The declared RIFF length must exactly match the input; every chunk and required odd-byte pad must fit, and PCM block alignment, byte rate and sample-frame alignment must agree. Other bounded chunks are skipped without interpreting their contents. This is a supported subset, not a claim that other WAVE variants are invalid. The PCM arithmetic follows [Microsoft's WAVEFORMATEX documentation](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/ns-mmeapi-waveformatex).

`maxBytes` defaults to 64 MiB and may be lowered; `maxChunks` defaults to 4096 and may be lowered. The optional abort signal is checked before copying and while visiting chunks. Invalid options or exceeded budgets throw `RangeError`; malformed or outside-profile input throws `TypeError`. Cancellation propagates the signal reason when present. The function performs no I/O or network access.

Content imports can request `audioSourceProfile: "wave-pcm-v1"`. Direct effective `a:audioFile` and `a:wavAudioFile` declarations on slide-local pictures yield frozen `audioSources` records with the declaration, relationship attribute, slide and exact raw element identity, relationship ID and status. Scanning is independent of picture or ancestor-group geometry. If a picture also has one of those direct audio declarations, each `p14:media` reference under the specified Office extension is inventoried separately, using the [Office media relationship type](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/922b7818-6e5f-4641-a9c5-fab4063ec124). Its `companionStatus` compares the internal target with a single direct audio relationship: `same-part`, `different-part` or `unverified`. It does not imply that media is playable or otherwise semantically consistent. External records expose the unresolved relationship target as `externalTarget`; links remain unverified and are never fetched. The target is source data, not authorization to load it. Internal whole-part audio relationships include their part and content type. `audio/wav` and `audio/x-wav` are inspected against the above subset; successful records contain PCM metadata. Malformed, other-MIME, missing, fragmented, wrong-type and incompatible relationship modes are unsupported. Multiple references to one part share one inspection but retain separate source records. This profile does not inspect inactive MCE choices, master/layout artwork, media extensions without a direct audio declaration, audio attached to non-picture objects or other audio representations.

Distinct internal audio parts inspected by this profile have a separate aggregate scan budget using `maxTotalImportedAssetBytes`, and each part is bounded by `maxImportedAssetBytes` and the 64 MiB inspector ceiling; the counter is separate from image projection accounting. The record count is bounded by `maxReportFindings`. Over-budget imports fail rather than silently truncate the inventory. This opt-in inventory does not create Core media assets, authorize source edits or change playback or save capabilities. An unchanged no-op save preserves the original package bytes. Default imports omit `audioSources`.

With content projection, `audioProjection: "wave-pcm-v1"` also inventories sources and projects an unambiguous embedded PCM WAVE picture into a Core audio object and an immutable byte-backed audio asset. It requires one direct audio declaration, no conflicting audio/video declaration, nonzero mapped geometry, and either no Office media companion or one valid companion pointing at the same part. A mapped poster must use supported stretch placement and full opacity; an absent or unsupported poster becomes an audio object without a poster. Distinct uses of the same part share one Core audio asset, while poster assets remain independent. Audio and projected images share the imported-asset byte budget in this mode. Source findings distinguish fallback projection from unsupported cases. Source timing, playback settings and source editing are not mapped: unchanged no-op save retains original bytes, while edit-save profiles and picture-source inventory cannot be combined with this projection. Fresh export with `audioMode: "wave-pcm-v1"` creates new default playback timing, not the original timing.

## Authoring and static preview

Core can register `kind: "audio"` assets and add `type: "audio"` objects with an `audioAssetId` and optional `posterAssetId`. Audio and poster are separate assets; the poster must be an image, and image objects cannot reference audio assets. Byte inputs are captured by the existing immutable asset registry. Known asset references, cleanup, and cross-document slide copy account for both IDs, including nested and hidden objects. Core stores intent and does not decode, fetch or verify the audio format.

SVG displays the poster, or a neutral speaker placeholder when it is absent, with an `audio-static-preview` warning. It never loads the audio resource or plays it. By default PPTX generation rejects a document containing audio before resolving assets. Unreferenced audio assets are skipped by the PPTX image loader.

PPTX generation explicitly opts into `audioMode: "wave-pcm-v1"`. It accepts up to 4096 visible, top-level audio objects per slide with nonzero geometry, full opacity, no action or placeholder binding, and no authored event timeline on that slide. Objects are emitted in slide order into the native click sequence, with independent targets and a shared media part for each shared asset. Audio on layouts, masters or nested groups is rejected. Its audio asset must declare `audio/wav` or `audio/x-wav`; embedded bytes or bytes returned by the explicit [media resolver](byte-assets.md#external-audio-and-video) must pass `inspectWavePcm`, the per-asset budget and a 1–2147483647 ms rounded duration. Paths and URLs have no built-in audio loader. Validation occurs before calling the image resolver. Multiple slides can reference the same audio asset and share one WAV part.

The writer uses the native sample's paired audio/media relationships, poster image and click-sequence timing with 80% volume. A supplied image poster follows the existing image loading policy; a missing or invalid supplied poster fails the export. Without a poster, a generated neutral speaker image is embedded. The output always reports `audio-playback-unverified`: the package structure and media bytes do not prove audible playback. One generated one-second sample opened in PowerPoint for Mac 16.104, was recognized as audio, and its preview control changed to pause and returned to play with a 1-second duration; this did not independently capture sound or verify slideshow playback. Source-bound audio editing, general codecs, other playback settings and broader native compatibility remain unsupported.

An authored audio object can set `playbackStart: "object-click"` to request an independent click on that object. The default and explicit `"click-sequence"` use the normal slide click sequence and generate identical bytes. Object-click audio gets a distinct native interactive sequence and target; sequence audio and videos keep their own ordered effects. Unknown values fail validation and export. [PowerPoint for Mac 16.104](../testing/native-media-start.md) recognized a generated mixed sample's two audio objects as “When Clicked On” and “In Click Sequence,” respectively. This is one menu observation, not proof of sound output, slideshow timing, repeated clicks or other applications. Static SVG does not play either mode. Import does not map source start settings into this field, and fresh export of imported media therefore uses its default; existing import diagnostics report unmapped playback settings. Automatic starts and arbitrary animation triggers are not supported.

An authored audio object can set `playbackVolume` to `"low"`, `"medium"`, `"high"` or `"mute"`. The default is `"high"` and explicit high retains the previous output bytes. This is per object, even when audio bytes are shared. PowerPoint's muted flag is distinct from its volume attribute; this four-choice contract does not claim a precise acoustic gain or preserve a separately selected pre-mute level. Unsupported values are diagnosed before media resolution. Import does not map source volume; source-bound editing, video volume and arbitrary volume values are not supported. [Native observations](../testing/native-audio-volume.md) verify the menu state, not audible volume or slideshow behavior.

Audio objects may set `loop: true` to request repetition until stopped and `rewindAfterPlayback: true` to request returning to the beginning after playback; both default to false and may be combined. Explicit false values preserve the default export bytes. These settings are per object, independent of the shared asset, start mode and volume. The [native observations](../testing/native-audio-loop.md) establish editable PowerPoint checkbox states, not actual repetition, stop or rewind behavior. Trimming is not authored, so behavior for a trimmed source and its loop boundary is not defined here. Source import does not project these settings; video and source-bound edits are unsupported.

Audio objects may specify integer `trimStartMs` and `trimEndMs`, measured as milliseconds removed from the beginning and end of the source respectively. Both default to zero; explicit zeros retain the default output bytes. The writer retains full source bytes, stores per-object trim metadata, and adjusts the playback command duration. The sum must leave at least one millisecond of the source duration rounded to milliseconds; it is checked for every instance after WAV inspection, including shared and externally resolved assets. Invalid values are rejected before any external resolver is called. The independent [native observation](../testing/native-audio-trim.md) confirms one generated interval in PowerPoint's editable trim dialog, not audible playback or loop boundaries. Source import does not map trim; video trim and source-bound editing are unsupported.
