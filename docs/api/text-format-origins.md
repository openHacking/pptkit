# Text formatting origins and clear barriers

`resolvePresentationInheritance` now also reports normalization sources for text boxes, shape text, layout placeholders, chart text, authored slide notes and table cell formatting. It uses the same frame/paragraph/run selectors as ordinary normalization. No origin fields are added to Canonical IR.

Element targets use `{ kind: "element", id }`, with document-global IDs. Placeholder targets use `{ kind: "placeholder", id: layoutId, key }`, so equal keys in different layouts remain distinct. Authored notes use `{ kind: "notes", id: slideId }`. These form `PresentationInheritanceTextTarget`; the original `PresentationInheritanceTarget` interface remains extendable and unchanged. Origin target/source unions gain the new cases. Sources additionally support `{ kind: "preset", id: presetName, path }`. Preset paths quote arbitrary names, for example `textStylePresets["brand.name"].run.bold`.

Element properties follow normalized paths: `frame.*`, `content.<paragraph>.style.*`, `content.<paragraph>.runs.<run>.style.*`; shape text adds the `text.` prefix. Placeholder properties use `textStyle.frame/paragraph/run.*`. Sources identify actual declarations in the current authoring snapshot, rather than an intermediate owner or another equal value. Shared layout elements are recorded once; group children do not inherit their parent's placeholder text style. Empty strings still produce formatting records.

The cascade is defaults → placeholder preset → placeholder inline style → element/shape-text preset → local frame/paragraph/run style. A preset normalizes against the effective placeholder context; its omitted fields do not overwrite placeholder values with defaults. Scalar margins point all four effective sides to the scalar declaration; partial margins retain independent sources. `false`, zero and explicit default-valued declarations remain local. Effective `colorOpacity: 1` has an origin even though the ordinary normalized style omits that default-valued field.

Auto-fit and bullet objects retain whole-object selection. A new shrink declaration without scale uses `defaults.text.frame.autoFit.fontScale` (1). Enabling a list over a non-list fallback synthesizes indentation/hanging from `defaults.text.paragraph.listIndent` (27 points), unless explicitly overridden. Numbering style/start and bullet character defaults have their own `defaults.text.paragraph.bullet.*` sources. Inapplicable bullet/fit fields have no invented records.

Optional east-Asian/complex-script font overrides and script-font map slots support the existing `null` reset contract. Their rows have `state: "cleared"`; never-declared optional slots have no row. Whole-map null records a clear for each supported script code, all pointing to the whole-map declaration. These barriers survive subsequent fallback normalization. Later specific slots can reopen with their own sources. Clearing an override still permits the normal remaining font-family fallback; it does not mean that text has no font.

Fresh PPTX now retains resolved placeholder paragraph/run defaults and writes explicit `b="0"`, `i="0"`, `u="none"`, `strike="noStrike"` for false values, including empty paragraph insertion styles. The independent XML check found the previous omission; see [verification](../testing/text-format-origins.md). Layout-owned elements that use placeholder geometry/style remain visible ordinary artwork; only the dedicated placeholder stub owns native prompt identity. Fresh slide/run formatting remains materialized resolved state. This change does not yet make every inherited slide property a live native template link; native shared-template editing requires separate admission. The named two-page output now has three native save/close/reopen rounds; general template/font behavior is still open. Source-preserving writes are unchanged.

Generated list markers ignore leading zero-character insertion styles, use the text-bearing font/paint without text underline, and clamp first-line outdent to the frame edge. XHTML reserves hanging width for the marker. This addresses named native controls, not general measured native typography.

This slice excludes text content ownership, broader geometry/structure origins, new authoring of notes-master/theme styles and per-character physical font selection. Their existing normalization/output stays supported, but no new origin coverage is claimed here. Full inheritance/reset/native-template tasks remain open. See the [checked example](../examples/text-format-origins.ts) and [base origin API](inheritance-origins.md).


## Chart text and authored notes

Charts report all five effective fields (`fontFamily`, `fontSize`, `bold`, `italic`, `color`) under `style.textStyle.*`, `titleStyle.*`, `legend.textStyle.*`, and, for bar/line charts, `axes.category.labelStyle.*` / `axes.value.labelStyle.*`. Pie charts have no invented axis records. The common style supplies legend/axis fields; title size 12 and bold true have separate `defaults.chart.titleStyle.*` sources, while remaining fields inherit common text defaults. Other built-ins use `defaults.chart.textStyle.*`. An omitted title or hidden legend still has effective normalized formatting and corresponding records, without claiming it is rendered.

Chart normalization resolves symbolic font/color references against the owning layout/master theme. A formatting origin identifies the declaration that selected the reference, even if the effective value is a concrete font or hex color. Use the existing layout theme origin entries to inspect that theme's selected role. For example, local `{ theme: "body" }` points to the element's `style.textStyle.fontFamily`, not directly to a master declaration; its resolved font can still change on the next master replacement. Explicit default-valued fields and false overrides retain their local sources.

Notes properties are `notes.<paragraph>.style.*` and `notes.<paragraph>.runs.<run>.style.*`, with notes targets scoped by slide ID. Direct sources are `{ kind: "slide", id: slideId, path: "slides.<index>.notes.…" }`; built-ins and font null barriers use the same text selectors as ordinary authoring. Slide text presets, placeholders and chart styles do not become notes fallbacks. Notes use current authored values or `defaults.text.*`; they do not acquire an authoring notes master/theme graph from Parser's separate source-only notes projection.

Missing notes and an empty string normalize to one empty text run with default formatting. Explicit empty paragraph/run arrays retain their existing semantics: an empty content array yields no notes formatting records, while a paragraph with no runs has paragraph records only. Empty insertion runs still retain explicit clear/false/zero/default-valued sources. Origins describe logical declarations, not the concrete physical font selected later in a notes theme or a native app. No source writer, field evaluator or notes-page artwork support is introduced here.

[Chart/notes verification](../testing/chart-notes-origins.md) covers both source paths and independent exported XML, along with browser/installed public consumers.

[Table cell origins](table-format-origins.md) now retain regional/preset/local declarations through the actual raw merge chain, including all supported cell style, paragraph/run leaves and font clears. Shared physical border conflicts remain Layout-owned.
