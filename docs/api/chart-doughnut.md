# Doughnut charts

Core accepts `chartType: "doughnut"` with one or more series sharing a nonempty category array. Each dense series contains nonnegative finite values or explicit `null` blanks, and can declare one opaque `pointColors` entry per category. Each series is a concentric ring; series order runs from the hole outward. Category colors in the legend come from the first series. The optional integer `holeSize` is 1–90 percent of the outer radius (default 50), and `firstSliceAngle` is 0–360 clockwise degrees from the top (default 0). Pie charts retain their single-series contract. Neither family has axes. `blankDisplay` is `gap` or `zero`: a blank remains null and has no visible area, while an authored zero remains numeric data.

Layout exposes `chartLayout.doughnut` with a center, inner/outer radii and per-category angular slices for each ring. It normalizes values before summing, avoiding overflow for large finite values. SVG uses actual annular paths, including a two-arc full circle, and retains transparent chart/plot backgrounds in the hole. Layout and preview remain approximations of native Office placement and font metrics. Fresh PPTX output writes native `doughnutChart`, explicit geometry, per-point colors and a separate embedded workbook and chart caches. The [older Open XML hole-size description](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.holesize?view=openxml-3.0.1) gives a 10–90 range; 1–9 are supported by Office and the Strict schema, and are flagged on Transitional export.

Content import accepts single-family 2D doughnuts with an explicit supported hole size and either an explicit first slice angle or an absent angle or missing angle `val` projected as zero, and compatible series/categories and cache or workbook sources under the existing [chart data rules](chart-import.md). An explicit supported hole size can be an integer or an integer percentage string; source saves preserve the original spelling and fresh export emits an integer. An absent hole-size element, a hole-size element without `val`, or an unsigned-byte hole size outside 1–90 remains source-only rather than rejecting the presentation or assuming an authored default. The zero-angle projection is reported and the original missing element or attribute remains unchanged in no-op and numeric preservation saves. Cache/workbook provenance and no-op preservation remain Parser-owned. The opt-in existing-values numeric preservation profile admits dense doughnut values only when each edited cache atom binds to its matching workbook cell. Sparse blanks, mismatched or unsupported sources, and geometry edits remain blocked; unrelated admitted edits can preserve source payloads. Unsupported labels, inherited formatting, broader source geometry defaults, combinations and native data editing remain outside this contract.

[Cross-package tests](../../scripts/chart-doughnut-parity.test.mjs) check multiple rings, blank and zero data, geometry boundaries, all-null and extreme values, full-circle paths, three fresh export/import rounds, both chart dialects, no-op bytes, Node/browser output and browser pixels. Dense multi-ring preservation edits are checked over three rounds, with independent cache/workbook checks, browser byte parity and a conflicting-cell rejection. [PowerPoint 16.104 evidence](../testing/chart-doughnut-powerpoint-evidence.json) covers three generated samples on first open and one save/close/reopen. Its first-open PDF independently checks ring order, a rotated quarter and blank output, and the three native outer radii and centers agree with the computed Layout values within 0.3 slide points; screenshots and accessibility captures document both states. The evidence does not establish a reopened print, interactive data edits, other producers or general visual equivalence. The sample artifacts remain local under `.tmp` and can be checked by `python3 scripts/research/verify-doughnut-powerpoint.py`.

[PowerPoint 16.104 omitted-geometry evidence](../testing/chart-doughnut-defaults-powerpoint-evidence.json) records controlled first-open captures, one save/close/reopen of a copy, and a later reprint of the original source. Missing first-slice angle produced the same paths as explicit zero; missing hole size produced no hole in two samples and PowerPoint saved `holeSize=0`. Those samples explain the source-only hole behavior and do not establish other producers or empty `val` attributes. [Microsoft documents](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/56d2baaf-961d-4e81-bc6f-09d90ef42a68) an Office hole-size minimum of 1, whereas older Transitional descriptions state 10; fresh exports for 1–9% therefore include the scoped `doughnut-small-hole-office-extension` compatibility warning.

A separate [PowerPoint warning observation](../testing/chart-doughnut-percent-powerpoint-evidence.json) changed one otherwise working Transitional chart from `50` to `050%`. PowerPoint 16.104 requested repair, which was cancelled. Import support for this lexical form therefore does not promise that PowerPoint can open a preserved source without repair; fresh export writes the integer form. Other percent spellings and Strict sources were not tested in PowerPoint.

In a separate [LibreOfficeDev 26.8 headless comparison](../testing/chart-doughnut-percent-libreoffice-evidence.json), the integer and `050%` variants produced equal colored shape bounds, but the first chart’s inner-to-outer ring boundary ratio was approximately 0.667 rather than the PowerPoint print’s 0.75. This observation covers only these files and does not establish general cross-application parity or interactive editing.

[Empty-attribute PowerPoint evidence](../testing/chart-doughnut-empty-geometry-powerpoint-evidence.json) observes one first print and one save/close/reopen: an empty first-angle element rendered like explicit zero, while empty hole-size elements rendered without a hole and were saved as zero. The reopened copy was not reprinted. The [Ecma Strict schema archive](https://ecma-international.org/wp-content/uploads/ECMA-376-1_5th_edition_december_2016.zip) gives an empty hole-size `val` a 10% schema default; because the observed Transitional PowerPoint behavior differs, missing hole values remain source-only for both dialects pending a producer-aware policy.

[Small-hole PowerPoint evidence](../testing/chart-doughnut-small-hole-powerpoint-evidence.json) records 1%, 5%, 9% and 10% charts on first open and one save/close/reopen. The first-print vector paths independently measure each hole ratio, and source and saved packages retain their cache and workbook data. The reopened copy was not reprinted; interactive data editing, other versions and other consumers remain unverified.
