# Experimental native connectors

`generatePptx(document, { connectorMode: "native" })` enables an explicit native connector profile in both exporter entries. The default `"path"` mode retains existing custom-path shape output. Unknown mode values reject before generation. See the [checked example](../examples/native-connectors.ts).

## Supported profile

- Straight connectors with no explicit route points; free endpoints, one attached endpoint or two attached endpoints are supported.
- One non-degenerate horizontal-first elbow is supported when its sole route point is exactly `(end.x, start.y)`. It uses `bentConnector2`, whose preset path goes horizontally from the start and then vertically to the end. All four endpoint directions use flips; free and supported attached endpoints are admitted. Other route shapes fall back.
- A non-degenerate horizontal–vertical–horizontal route with two waypoints at the same interior x-coordinate uses `bentConnector3` and an explicit `adj1` value. The 1/100000 adjustment and independently rounded DrawingML bounding box must represent the waypoint within half an EMU of its rounded authored position; otherwise export falls back and warns. Waypoints outside the endpoint span, endpoints with zero width/height, and other segment arrangements remain on the path fallback.
- Attached targets are text rectangles or `rect`, `roundRect`, `ellipse` shapes with local rotation/flips resolved around their frame center.
- Cardinal `top`, `left`, `bottom`, `right` anchors map to the preset's connection-site indices. Default/explicit `center` does not silently become a side attachment.
- Connector and target share the same immediate group scope and drawing part. Nested groups can carry their own transform when the connected children share that scope.
- Horizontal, vertical, diagonal, reverse-direction and coincident free endpoints use `straightConnector1`, exact resolved bounds and direction flips. Zero width/height is allowed by the DrawingML coordinate schema.
- Stroke, opacity, arrow ends, accessibility/name, action and applicable placeholder metadata use existing serialization behavior.

The output uses `p:cxnSp` with optional `a:stCxn`/`a:endCxn` bindings to actual part-local drawing IDs. IDs are assigned before serialization, so connectors can precede targets and remain correct after copying/reordering. Placeholder-generated IDs and omitted images do not create collisions or dangling supported-target references. IDs remain isolated per drawing part and export invocation.

For slide click actions, the exporter writes same-directory `slideN.xml` relationship targets with `ppaction://hlinksldjump`, which Office-compatible consumers can recognize as slide jumps. Notes and other non-slide parts use their relative `../slides/slideN.xml` target. This is part of slide-action serialization in every connector mode.

The [Microsoft connector definition](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.connectionshape?view=openxml-3.0.1) and [start connection definition](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.startconnection?view=openxml-3.0.1) define the container and attachment ID/index fields. Site ordering and straight geometry were checked against ECMA-376 fifth-edition Part 1 `presetShapeDefinitions.xml`: rect/roundRect use top/left/bottom/right indices 0/1/2/3, while ellipse uses 0/2/4/6 because diagonal sites intervene. `ST_PositiveCoordinate` allows zero. Earlier code comments asserting universal rejection of zero extents/custom connector geometry were removed; the established legacy minimum extent remains a path-mode compatibility choice.

## Explicit fallback

Unsupported native cases retain their existing path-shaped appearance and emit `native-connector-fallback`, with element ID and slide/layout ID plus the reason. These include other explicit polyline routes, center anchors, connector-local transforms, unsupported target types, hidden targets and targets inherited from another part. A partially mappable attachment does not silently become a partly detached native connector: the whole connector falls back. Hidden connectors remain omitted under existing hidden-element behavior. A target outside the connector's immediate coordinate scope instead fails Core validation before export, rather than falling back to a path with an incorrect origin endpoint.

Layout resolves anchors under its established geometry/scope rules; direct normalized inputs with a missing or cross-scope target also reject. Content import maps unadjusted `bentConnector2` and `bentConnector3` with a default or bounded literal adjustment to explicit routes, including source flips/rotation and supported target bindings; [the import contract](content-import.md) describes its limits. Source-preserving edits of connector geometry, other bent and curved routing, advanced preset sites and interactive movement remain open. This profile does not promise arbitrary connector routing or Office parity.

## Layout boundary

`LayoutConnectorElement` still exposes resolved point `start`/`end`, route and bounds, and now optionally carries `connections` with the authored endpoint ID and anchor. Default anchors become explicit `center`; free endpoints have no identity. These detached fields are format-independent identity provenance, not OOXML drawing IDs. Renderer uses the same resolved geometry as before. Exporter translates retained identities into the selected native profile; Core/IR gains no XML fields or dependency.

Consumers comparing complete Layout object shapes must allow the new optional field. Normalized authoring state and source references remain unchanged. The native export option does not change default/path serialization; the later Layout correction for transformed targets changes their resolved endpoints in both default output and SVG, as described below.

## Verification and native evidence

[Exporter conformance tests](../../packages/pptx-exporter/test/native-connectors.test.mjs) cover all supported cardinal site tables, direction flips and zero extents, forward references, nested groups, fallback reasons/locations, layout boundaries, generated placeholders, omitted images, copy/source deletion and concurrent exports. Browser tests compare native output bytes with Node; installed consumers exercise public options/types. Existing cross-package tests continue to validate copied/resolved geometry.

The [native evidence record](../testing/native-connectors-evidence.json) records LibreOfficeDev headless PPTX save/reopen to PDF for ten generated native connectors, five with attachments. Independent Python ZIP/XML inspection found all ten connector objects and all target-name/site-index bindings preserved after save, including reverse directions and a transformed parent group. The application normalized coordinates and zero extents (to small positive values) and changed grouped geometry representation; this is attachment-inventory evidence, not exact geometry/visual fidelity.

Run `node scripts/inspect-native-connectors.mjs [soffice-executable]` after building to repeat the optional experiment. Each run uses a new profile/artifact directory and records hashes, application/OS versions and logs. The runner records a changed inventory as an observed result rather than treating conversion success as universal compatibility. Native tools are not required by portable CI.

A [PowerPoint movement observation](../testing/native-connector-move.md) covers one straight connector attached to two rectangles: dragging one target moved the connector and both attachments survived one save/reopen. A [separate attached-elbow observation](../testing/native-elbow-move.md) shows PowerPoint rerouting one single elbow into a double elbow after a target drag, preserving both bindings through one save/reopen; the actual saved file also has three automated fresh import/export rounds. Broader rotation cases, other geometries and wider application behavior remain unverified. The `bentConnector2` and `bentConnector3` paths are based on the [Apache POI preset geometry definition](https://apache.googlesource.com/poi/+/refs/heads/gsoc2012/src/resources/ooxml/org/apache/poi/xslf/usermodel/presetShapeDefinitions.xml); tests cover four directions, target IDs, fallback and browser export parity. The [cross-package test](../../scripts/native-elbow-parity.test.mjs) checks three fresh import/export rounds with single-elbow free and attached endpoints, plus twelve double-elbow direction/adjustment combinations, an attached double elbow, and byte-exact no-op saves. Moving an attached target in PPTKit changes its resolved endpoint but retains the authored route point; if the route no longer matches the native preset, a fresh native-mode export falls back and warns. A preservation save of that source geometry change remains blocked. A [PowerPoint 16.104 observation](../testing/native-elbow-powerpoint-evidence.json) checks eight free single/double elbows in four directions, their printed PDF outlines on first open and after one save/close/reopen, and saved preset/flip/adjustment XML. This observation uses a 25% double-elbow adjustment; broader attached elbow editing and further native reopen rounds remain unverified. The retained capture hashes do not independently establish provenance. AUT-02.3 stays open until its remaining routing and application gates are satisfied.


## Target transforms

Cardinal anchors identify sites in the target's local geometry. Layout applies horizontal/vertical flips before clockwise rotation about the target frame center, so both preview and export consume the transformed endpoint. Native bindings retain the original local site index: a rotated right site does not become a top-site identity. Ancestor transforms apply once to the common group, not to each already-local endpoint. Free endpoints and explicit route points remain authored coordinates. Center remains geometrically valid but has no native attachment site and falls back. Cross-group/cross-part attachment and connector-local transforms remain outside the native profile.

This corrects previous Layout endpoints for transformed targets, including default path output. Untransformed targets retain their previous values. The [PowerPoint rotation observation](../testing/native-connector-rotation.md) checks one approximately 45.462° rotated rectangle and its attached straight connector through one save/reopen; independent trigonometry and the imported Layout endpoint agree with the saved native endpoint within 2 EMU. Other transforms, targets and applications remain open.
