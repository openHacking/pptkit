# SVG preview invalidation

`captureSvgPreviewSnapshot(layout, { environmentRevision, idNamespace? })` captures immutable string representations of conservative SVG dependencies for a resolved Layout. `planSvgPreviewInvalidation(previous, next)` returns frozen `reusable` and `render` lists in next-slide order, plus removed slide IDs. Each entry has a slide ID and its current index. Only reuse the SVG string previously rendered for the same ID and index under the captured conditions; pass `render.map(item => item.index)` as `slideIndices` for a new render. See the [typechecked example](../examples/svg-invalidation.ts).

Page content and the relevant layout/master are compared per slide. Size, document title, global theme, all assets, namespace and `environmentRevision` are shared dependencies; any shared change invalidates every page. This is deliberately conservative. A move invalidates the moved pages because SVG title and definition IDs contain the page index; unaffected pages at unchanged indices remain reusable. Identical values after an edit and restoration may be reused. Snapshots are detached strings, not hashes, so comparison does not rely on a hash collision assumption. They can contain document contents and asset strings: treat them as document data. Capture uses synchronous JSON serialization and has no separate input-size or memory limit; use trusted, bounded, fully resolved Layout data, and do not accept forged snapshots from untrusted sources. Nonfinite numbers and nonserializable function/symbol/bigint values reject; cyclic values throw.

`environmentRevision` is required. The caller must change it whenever resolver behavior, returned URLs or bytes, external assets, runtime-dependent rendering inputs, or any other dependency outside captured Layout changes. A stale or dishonest revision can produce stale reuse. Pass the same `idNamespace` used for rendering. Changes to render options that affect output and future renderer behavior must be represented in the revision; an abort signal and output budget are execution controls, not cached output. The planner does not call the resolver, render SVG, watch changes, manage cache lifetime, or enforce concurrency. An async caller must discard work based on an older snapshot before publishing results.

The lists cover **SVG strings only**. Warnings, status, analysis diagnostics, output-size limits, DOM loading, font substitution, rasterization and image animation are not cached or validated by this plan. Recompute report state for the current input; do not merge stale warning arrays as if they were current. A browser may repaint or load external resources differently even when an SVG string is unchanged.

## Incremental rendering

`renderIncrementalSvg(layout, { environmentRevision, ...renderOptions }, previousCache?)` applies this plan to all slides and returns `{ result, cache, renderedSlideIds }`. Pass the returned cache on the next call. It reuses unchanged SVG strings and their render warnings, recomputes current Layout-analysis warnings, preserves slide and warning order, and applies `maxSvgBytes` to the complete combined output, including cached pages. Changes to `pngAnimationDiagnostics` and `idNamespace` invalidate reuse. `slideIndices` is not supported by this all-slide operation. Cancellation and rendering failures reject without returning a new cache; the previous cache is untouched.

The renderer clones Layout before awaiting any resolver, so later changes to the caller's Layout cannot enter that operation. The result is for the cloned input: consumers must still compare their own current revision before publishing an asynchronously completed result. Resolvers must not mutate the supplied asset or Layout; detectable mutation of the cloned dependencies causes rejection. The frozen cache and its snapshot contain document content, must be treated as trusted internal data, and have no separate memory limit. Do not forge, persist across incompatible renderer versions, share across trust boundaries, or reuse with an unchanged environment revision after resolver behavior or external assets change. Returned `result` objects are detached from the cache and may be modified without corrupting it. This is not a DOM cache and does not guarantee browser image loads or font rendering.

[Node tests](../../packages/svg-renderer/test/invalidation.test.mjs) compare real rendered outputs for local, inherited, global and reordered changes, and cover snapshot detachment, restored state, deletion and invalid inputs. [Incremental tests](../../packages/svg-renderer/test/incremental.test.mjs) compare complete results and warnings with fresh renders, exercise budget, cancellation, asynchronous mutation and resolver mutation. [Chromium parity](../../scripts/selection-browser.test.mjs) checks planning and incremental rendering through the global bundle. This advances ECO-05; it does not close full preview invalidation or editor state management.
